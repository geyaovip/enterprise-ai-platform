## 内容与入口

| 位置 | 已实现 |
| --- | --- |
| 首屏、导航与页脚 | 首屏交代数字员工协助库存、客户跟进和生产准备；“认识数字员工”进入岗位区；五页导航及页脚增加数字员工入口 |
| 首页与应用方案页 | ERP管家、CRM运营官、MES生产官三张岗位卡片，包含已有头像、工作范围、主要交付和对应产品链接 |
| 三个产品页 | 展开对应角色的职责、交付、人工办理事项；前往协作示例和既有工作台 |
| 三组示例 | 岗位名称与头像关联输入/输出，步骤区分员工核对/整理和人员确认/办理；仍为明确标注的静态示例数据 |
| 响应式与可访问性 | 岗位卡片三/二/一列，手机详情顺序阅读；导航增加后在1000px及以下折叠，脚本与样式断点一致，Esc恢复焦点，保留原tab键盘能力 |

数字员工是既有三个专家职责在官网的统一表达，来源为`integrations/workbuddy/experts/*/agents/`和[D-083](83-三应用Agent与MCP同步升级.md)。不创建新的Agent运行实体或扩展权限。ERP保留审批/收付款/出入库的岗位办理；CRM由负责人沟通及记录反馈；MES由人员核对用量、发布、派工及审核报工。

复用三个原有专家PNG头像，按字节一致复制为公开素材，合计约976KiB，延迟加载并由浏览器复用缓存；主视觉和SVG品牌不改。头像仅辅助识别，岗位名由文本提供，空alt避免重复。没有虚构人员履历或认证。

WorkBuddy市场最新审核状态未在本批查询，不添加安装/雇佣链接；使用入口沿已存在的`/login`工作台，避免让角色介绍变成没有实际承接的动作。公开示例不请求API、不调用模型、不读企业数据、不写业务。
