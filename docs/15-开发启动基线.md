# 开发启动基线

状态：2026-09-29 的**开发入口和目标范围**；文档通过不表示代码、部署或客户试用已完成。每次启动新阶段先读本页，再按 [00 文档索引](00-文档索引与决策记录.md) 进入对应契约。

## 已确定的架构

| 项 | 冻结内容 |
| --- | --- |
| 产品与顺序 | **Platform → 新 ERP → 新 CRM → 新 MES → Architecture Review → 建筑五应用**；ERP 第一套面向真实客户试用。 |
| 运行单元 | 一个 Monorepo、一个 Web/Admin、一个 NestJS 模块化单体 API、一个 PostgreSQL、独立 Worker；业务应用是内部一等代码模块。 |
| 技术栈 | Node.js 24 LTS、TypeScript、React + Vite、NestJS、Prisma、pnpm；主版本和 M1 验证门槛见 [ADR-001](ADR-001-技术栈决策.md)。 |
| Platform Core | Tenant、Identity、**OrgUnit 与成员组织关系**、Permission、代码 App Manifest/TenantApp、App Context、AI Runtime、Audit；只实现首客需要的行为。 |
| 按需平台能力 | 文件、知识检索、集成、通知按真实用例建设；知识权限与 Citation 的最小契约先确定，不预建向量库。 |
| 共享策略 | App Local → 第二个真实消费者 → 语义/生命周期/权限比较 → Architecture Review → 必要时提升 Shared。无空 `shared-business`、`construction/shared`。 |
| ERP 范围 | 按 [D-008](00-文档索引与决策记录.md#已确认的决策) 完整重做旧 ERP 当前已实现功能，增加可执行 AI 聊天；逐项用 [17 追踪矩阵](17-ERP功能追踪矩阵.md) 验收。 |
| 旧项目关系 | 旧三应用只作功能/规则证据；新项目不依赖旧代码、服务或数据库。三套新应用验收前保留旧项目及数据。 |

## 当前开发入口

1. **M0/M1**：按 [ADR-001](ADR-001-技术栈决策.md) 建仓，固定确切依赖版本，验证干净安装、构建、迁移、同库事务与回滚。技术栈不在日常开发中重新选型。
2. **Platform Foundation**：实现租户/身份、稳定 OrgUnit 关系、应用上下文、服务端授权、App Manifest、审计和 AI Tool 执行底座；知识只交付最小检索/Citation 契约，文件与向量检索按用例实施。
3. **ERP 第一条切片**：采购确认 → 分批入库 → 库存与应付同库事务，验证页面与 AI Tool 使用同一业务命令；随后完成 [17 追踪矩阵](17-ERP功能追踪矩阵.md) 的 ERP 全范围，再做真实模型和客户试用验收。切片不是 ERP 全范围。
