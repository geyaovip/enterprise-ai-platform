# 可观测性与运维

> 文档属性：功能契约。规则与验收要求不等于全部能力已实现或已发布，日期证据保留其环境。状态入口：[47](47-项目现状与文档维护.md)；公共UI：[ui/00](ui/00-公共UI规范.md)。

已有自动运行、任务通知和业务回执的日期发布记录见 [43](43-自动运行与工作体验优化.md)；最新本地实现、历史发布及未覆盖边界统一见 [47](47-项目现状与文档维护.md)。

目标：从 ERP 首客试用起就能发现故障、定位租户与业务影响、恢复服务及数据。本文保留运维要求与历史记录；当前运行版本和验证状态以 [41](41-六批优化交付与线上验收.md) 为准。

当前收尾按 D-022：生产定时备份暂缓，采用发布流程中的手动数据库＋知识原件联合备份，保留校验和及独立恢复记录。知识链当前使用内置引擎；RAGFlow Cloud 暂缓。告警和实际发布回退的未验证状态仍如实保留。

## 共享云与专属部署边界

- 业务模块不写 `if (privateDeployment)` 分支。数据库、对象存储、模型、队列、邮件/通知等外部依赖由部署配置与 Provider 接口注入。
- 共享云以租户隔离运行；专属部署可以为单客户配置独立资源，但保留同一租户/权限业务语义，避免两套代码分叉。
- 统一 API 与 Worker 使用各自运行身份；平台及业务模块使用同一个 PostgreSQL 数据库、一套受控迁移和备份流程。三个前端分别构建/发布并记录兼容版本；OpenClaw 按互不信任租户隔离运行，D-020/D-022 指定内置知识库为当前方案，RAGFlow Cloud 保留可选并暂缓。专属部署使用同一产品版本和迁移，按租户配置启用所需模块。
- 所有环境以独立 Secret 管理凭据；本地 `.env.example` 只能含变量名和安全占位值。密钥轮换与加密密钥备份要有恢复步骤。
- 构建产物具有版本号/提交号；部署记录写明目标环境、镜像摘要、迁移版本、操作人、验收结果和回退版本。

## 监控和日志

| 类别 | 最小记录 |
| --- | --- |
| 请求 | 时间、request ID、路由模板、租户 ID、操作者 ID、状态码、耗时；不记请求正文中的敏感数据。 |
| 业务 | 核心写动作、对象 ID、结果与失败码；业务审计由专门 Audit 记录，不用普通日志代替。 |
| AI | conversation/action/task ID、模型逻辑角色、Provider、延迟、token/费用或可用用量、Tool 调用、业务回执与失败类型；不记录完整客户资料。 |
| Worker | 队列积压、重试次数、最终失败、幂等键和租户；失败可在后台定位并人工重试。 |
| 资源 | API/DB/Worker 健康、数据库连接、错误率、延迟、磁盘、内存和备份结果。 |
| OpenClaw/RAGFlow | 租户 Gateway 与会话归属、运行错误/超时、知识处理队列与索引状态、检索失败、资源容量、版本和组件健康；不记录原始客户文档或跨租户内容。 |

指标和日志保留 `api`、`worker` 的服务标识及业务模块标识，并用 request ID 串起统一 API、聊天动作、业务命令、AI Tool 与异步任务；对话中的“操作已完成”必须能追到真实业务写入和审计记录。只记录租户/操作者稳定 ID，不在日志写明文业务资料。统一 API 与 Worker 的就绪检查分别覆盖各自必要依赖。

AI 审计与排障按实际调用链关联会话/动作 ID、Agent/Skill/Tool 定义版本、目标 App 与对象、模型、确认状态、用量、业务回执及有权知识来源/引用 ID。OpenClaw/RAGFlow 的 trace 仅作诊断输入，不能替代平台自己的授权决定、业务提交回执和审计记录。组件不可用时记录影响范围与恢复路径，不把模型建议标为已执行业务结果。

健康接口区分进程存活与依赖就绪；就绪失败不能被静态页面 200 掩盖。客户试用前设定负责人、告警接收方式、支持入口和故障升级路径。具体可用性目标与备份保留期需按首客合同/数据要求确认，不在此凭空给出数字。

## 备份、恢复和发布

- 每个生产租户的平台数据与应用数据均进入受控备份；统一数据库整体备份、加密、限制访问并定期恢复演练，验证身份、业务对象和审计引用仍可用。保留期、删除策略和数据导出要求在首客开通前确认。
- 发布前检查统一迁移链、容量、备份可用性和回退方案；三个前端、API、Worker、OpenClaw 与 RAGFlow 记录兼容版本及配置。OpenClaw 租户实例状态/凭据与知识文档/索引分别备份并演练恢复或重建。使用可向前兼容的迁移顺序，禁止以删除旧表/旧列作为首步。
- 更换 Runtime 或知识引擎时，在隔离环境先验证新适配器和数据映射；以平台原始文档重建索引并校验文档/引用 ID、权限和数量。发布窗口停止接收新任务，排空或显式中断未完成任务，保存平台会话/动作/审计和业务回执，再切换配置并观察错误率；回退时恢复原适配器配置与兼容数据映射。记录不可迁移的组件私有状态和用户可见影响。
- 发布后从公网或客户实际入口验证登录、当前租户、ERP 核心读取与受控写入、AI 启用状态、审计和健康接口。
- 出现数据错乱、跨租户可见或关键财务/库存事务异常时停止扩展流量，保留证据，按已演练方案回滚应用或恢复数据。不能只回滚前端。
- 共享服务器操作必须先识别其他服务、容器、卷和回退镜像；不得使用全局 `docker system prune` 或删除无关项目卷。

## 客户专属部署准备清单

即使首批只交付共享云，也要保证：部署配置与业务代码分离；可按配置启用所需业务模块并使用统一数据库；可替换 PostgreSQL 托管方、存储及模型供应商；不依赖固定公网域名或特定租户 ID；初始化可重复执行；健康、备份、升级和日志收集有同一操作接口。真正的客户专属安装包、离线环境和 SLA 在客户场景明确后单独验收。

## 首阶段当前操作入口

三端与 API/Worker 使用 `infrastructure/compose.production.yaml`；OpenClaw 的开发隔离实例由 `infrastructure/openclaw-member.mjs` 创建/验证/启动，生产需要独立成员容器/主机与受控网络。RAGFlow Cloud 无本地容器，配置通过平台运营端加密入库。组件连通由运营端主动检查，知识瞬时失败退避重试最多三次，删除失败持续退避；Cloud 长请求期间 Worker 就绪允许最多 5 分钟的处理周期，空闲周期 15 秒未更新则不就绪。最终发布仍需告警、容量和真实失败恢复演练。

`infrastructure/phase1-backup.sh` 在 API/Worker 已停止的写冻结窗口联合备份 DB 与知识原件卷，不能只执行旧数据库备份脚本就宣称文档可恢复。平台加密密钥、成员 Gateway 私有目录和 Cloud 索引重建配置需要单独受控备份；2026-10-08 生产知识开通后的联合备份已在独立数据库恢复，元数据、加密绑定、向量与原件核对通过，证据见 [21](21-云端发布记录.md)；实际发布回退尚未演练。完整命令、配置切换和回退见 [25](25-首阶段组件部署与联调.md)。

## 定时一致备份（D-022 暂缓）

`infrastructure/scheduled-backup.sh` 使用 Linux flock 互斥，停止本项目原本运行的 API/Worker 后联合备份 PostgreSQL 与知识原件，验证归档目录、生成校验和并恢复原运行状态；不做自动删除。`infrastructure/systemd/` 中 timer 每日 03:30 触发并允许随机延迟，service 的 checkout 路径须在发布时核实，不能直接假设 `current` 已存在。

现有脚本预留 `.backup-status.json` 与本机 syslog/systemd OnFailure。用户明确当前不需要生产定时备份，未安装 timer；运营页源码改为说明当前手动备份方式，不因定时记录为空显示过期警告。将来启用前需先核对当前 release 和 native 数据库 Compose 覆盖文件、进行隔离验证，再验证执行与外部通知。外部值守通知仍未接通，不能宣称已经有人收到报警。
