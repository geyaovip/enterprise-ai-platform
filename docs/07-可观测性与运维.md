# 可观测性与运维

目标：从 ERP 首客试用起就能发现故障、定位租户与业务影响、恢复服务及数据。此文是实施要求，不表示当前新平台已经部署。

## 共享云与专属部署边界

- 业务模块不写 `if (privateDeployment)` 分支。数据库、对象存储、模型、队列、邮件/通知等外部依赖由部署配置与 Provider 接口注入。
- 共享云以租户隔离运行；专属部署可以为单客户配置独立资源，但保留同一租户/权限业务语义，避免两套代码分叉。
- 统一 API 与 Worker 使用各自运行身份；平台及业务模块使用同一个 PostgreSQL 数据库、一套受控迁移和备份流程。专属部署使用同一镜像和迁移，按租户配置启用所需模块。
- 所有环境以独立 Secret 管理凭据；本地 `.env.example` 只能含变量名和安全占位值。密钥轮换与加密密钥备份要有恢复步骤。
- 构建产物具有版本号/提交号；部署记录写明目标环境、镜像摘要、迁移版本、操作人、验收结果和回退版本。

## 监控和日志

| 类别 | 最小记录 |
| --- | --- |
| 请求 | 时间、request ID、路由模板、租户 ID、操作者 ID、状态码、耗时；不记请求正文中的敏感数据。 |
| 业务 | 核心写动作、对象 ID、结果与失败码；业务审计由专门 Audit 记录，不用普通日志代替。 |
| AI | conversation/action/task ID、模型逻辑角色、Provider、延迟、token/费用或可用用量、Tool 调用、业务回执与失败类型；不记录完整客户资料。 |
| Worker | 队列积压、重试次数、最终失败、幂等键和租户；失败可在后台定位并人工重试。 |
| 资源 | API/DB/Worker 健康、数据库连接、错误率、延迟、磁盘、内存和备份结果。 |

指标和日志保留 `api`、`worker` 的服务标识及业务模块标识，并用 request ID 串起统一 API、聊天动作、业务命令、AI Tool 与异步任务；对话中的“操作已完成”必须能追到真实业务写入和审计记录。只记录租户/操作者稳定 ID，不在日志写明文业务资料。统一 API 与 Worker 的就绪检查分别覆盖各自必要依赖。

健康接口区分进程存活与依赖就绪；就绪失败不能被静态页面 200 掩盖。客户试用前设定负责人、告警接收方式、支持入口和故障升级路径。具体可用性目标与备份保留期需按首客合同/数据要求确认，不在此凭空给出数字。

## 备份、恢复和发布

- 每个生产租户的平台数据与应用数据均进入受控备份；统一数据库整体备份、加密、限制访问并定期恢复演练，验证身份、业务对象和审计引用仍可用。保留期、删除策略和数据导出要求在首客开通前确认。
- 发布前检查统一迁移链、容量、备份可用性和回退方案；Web、API 与 Worker 记录同一兼容代码版本。使用可向前兼容的迁移顺序，禁止以删除旧表/旧列作为首步。
- 发布后从公网或客户实际入口验证登录、当前租户、ERP 核心读取与受控写入、AI 启用状态、审计和健康接口。
- 出现数据错乱、跨租户可见或关键财务/库存事务异常时停止扩展流量，保留证据，按已演练方案回滚应用或恢复数据。不能只回滚前端。
- 共享服务器操作必须先识别其他服务、容器、卷和回退镜像；不得使用全局 `docker system prune` 或删除无关项目卷。

## 客户专属部署准备清单

即使首批只交付共享云，也要保证：部署配置与业务代码分离；可按配置启用所需业务模块并使用统一数据库；可替换 PostgreSQL 托管方、存储及模型供应商；不依赖固定公网域名或特定租户 ID；初始化可重复执行；健康、备份、升级和日志收集有同一操作接口。真正的客户专属安装包、离线环境和 SLA 在客户场景明确后单独验收。
