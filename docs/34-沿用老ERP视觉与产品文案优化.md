# 沿用老 ERP 视觉与产品文案优化

> 文档属性：日期实施/验证记录。保留当时版本、环境与结论；文中“当前/待完成”以该段日期为准。状态入口：[47](47-项目现状与文档维护.md)；公共UI：[ui/00](ui/00-公共UI规范.md)。

日期：2026-10-09。用户要求直接参考老 ERP 的 UI、交互与布局，同时明确新旧功能不同，不复制旧业务；并要求精简正式产品页面中的说明文案。对应 D-024。

## 实施范围

- 以旧 ERP 实际产品目录和新建产品弹窗为参照：236px 白侧栏、浅灰背景、蓝色主按钮、24px 标题、记录行的主次文字、590px 普通弹窗。复杂新平台表单使用 900px 弹窗，保留全部现有字段。
- 共用 `ErpShell` 与 `erp-theme.css`，三个端使用相同品牌区、导航图标、按钮、表单和账号入口。员工导航按工作台、销售管理、采购与库存、财务管理、企业服务五组常显；移除“更多业务”折叠，企业业务设置归入企业服务。导航区独立滚动，品牌和底部账号固定，当前菜单在页面切换、刷新和窗口缩小时保持可见。
- 客户、商品、供应商、采购和销售列表采用旧 ERP 的记录行布局；新平台的批量导入导出、筛选、角色权限、负责人调整、AI 入口和详情路由保留。
- 概览把待处理采购、销售和账款余额作为主要指标，基础资料数量放在摘要条。未完成业务仍使用新平台责任人数据，未复制旧项目近期单据功能。
- 删除 48 处页面副标题、说明段落及空状态介绍，并精简邀请、文件导入、服务未开通和审批提示。保留字段约束、错误反馈、实际不可用状态、资金与数据写入确认、外部服务的数据发送提醒。去掉产品页面的开发/验收叙述。
- 修复底部账号名称被齿轮入口挤压、筛选导出按钮悬空、财务关联链接间距、关闭移动侧栏后仍可聚焦等问题。
- 只修改前端及规范；未引入旧 ERP 的 API、数据库、权限角色或业务规则，未变更生产后端。
