## 4. 交互契约

- 查询条件暂存，查询/Enter应用，重置回默认第一页；保留当前企业、分页与已应用条件，详情返回恢复现场。
- 操作组只突出一个主动作；列表以查询、数据和行操作为主，新建/编辑在明确工作层，成功后以接口结果刷新。
- 简短编辑采用统一Dialog；有变更关闭先保护输入。普通放弃用副按钮；提交失败保留字段，结果未知先核查，不假报成功。
- 账号菜单/通知的真实数据和业务直达继续有效；弹窗标题、关闭、分页、焦点和手机触控统一。
- 密码显隐位于框内，切换不提交、不清空；真实修改密码需用户主动操作。选择器、标签、文本域正确处理中文IME/Enter。
- PC AI为非模态，手机全屏为模态；关闭只关展示，已提交任务沿服务器生命周期，待确认操作仍明确人工确认。
- AI当前会话输入在面板生命周期保留，同企业站内导航保留内存草稿；刷新/离站采用浏览器提示。未发送输入尚无跨登录/企业的服务器持久化，CRM后续按14实施。会话业务写入继续走现有API，未提交内容不得冒充已保存业务记录。
- 颜色同时配文字；无数据、搜索无结果、无权、失败、待核实分开。点击反馈/AI首字仍按D-032，转圈不当实际结果。

### 验收边界

本轮为本地UI实现和工程验证，未部署到生产；未进行真实客户、第三方连接、真实模型质量/速度、原生手机软键盘和实际纸张打印验收。知识/外部通道未配置时继续显示真实不可用状态。ERP保持既有4000字消息上限；CRM规划600字及服务器会话草稿另行实现。响应式截图不代替原生手机验收。

本次截图使用隔离QA库；工程测试桩已停止，普通本地API已恢复并撤掉QA成员的临时Runtime绑定。旧三套应用及原本地/线上数据未由本轮修改。before保留修改前源码/文档；baseline.json/changed-files.json用于区分本轮改动与用户原有未提交内容。最终三端冒烟期间未观察到控制台错误，见final-console.json；工程及环境摘要见verification-summary.json。
