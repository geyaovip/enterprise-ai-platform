## 已修复

| 问题 | 当前实现 |
| --- | --- |
| 平台已加载Skill，指令却要求模型再次加载 | 统一指令；按问题选择Skill；已加载名称从模型可请求列表移除。固定Skill更新为1.0.1 |
| 相同事实重复查询 | 同轮相同工具/规范化参数复用结果；每次查询前重新检查权限、组织/渠道范围、设置、数据修订及计算日期。权限或版本变化后不复用 |
| 普通问题带入无关工具、对象、重复描述 | 按问题与资源选择有权工具/主数据；去除与函数定义重复的工具说明；模型规则定义精简，服务端完整类型与业务校验不变 |
| 问候进入完整业务处理 | 仅对明确问候/能力介绍走轻量路径；不查询业务、Skill或知识。业务问题、对象上下文与含操作要求的文本继续受控处理。默认记忆能力保留 |
| 网关遇到503自动重试最多8次 | 项目自有Agent settings设置`retry.provider.maxRetries=0`；受管策略版本3，在无活动租约时升级。该项不是`openclaw.json`键 |
| 模型返回后取消/权限变化/校验失败丢失用量 | 接收终态时先登记用量，再决定是否交付；失败/取消保留已知用量，缺失值标未知，不视为0 |
| 清理测试租户同时清理计量 | 新增独立`AiModelUsage`，无业务级联外键；记录环境/批次、来源、实际可知型号、虚拟请求型号、输入/输出、缓存/推理分项、终态及错误，不保存提示词/密钥/工具参数 |
| 付费题集整批重复、缺少预算 | 必须显式`PAID_MODEL_TEST=1`；支持案例子集、轮数、调用/Token预算；每次调用追加并同步用量文件；每批独立回执；模型错误或未知用量停止继续请求 |
| 规则格式不合法直接中止问答 | 参数校验移入受控错误反馈流程，返回字段错误供模型修正；仍有每轮5次模型调用、24k估算输入及已知累计60k Token的继续调用门槛，不绕过原校验 |
| 模型自行改写预览状态 | 状态直接引用`usableForTask/invalidReason`，计算时点用`asOf`；操作前服务端仍重新校验，不由外部/网关日期推断状态 |

同轮缓存只用于选定只读查询，不缓存写操作、失败结果或人群预览创建。上面的应用Token门槛是“达到后不再继续调用”，不是供应商账单的绝对上限；缺失用量与最后一次请求的不确定性须单列。

## 独立账本与历史统计边界

迁移：`20261023090000_ai_model_usage`、`20261023091000_ai_usage_context`。隔离QA现为25条迁移；生产仍为23条。本批不补写历史未知Token。

- 该账本覆盖Runtime回复/摘要与ModelGateway直连；知识向量嵌入是另一条调用链，本批不声称覆盖全部火山消耗。
- 以后以`AiModelUsage`作为运行计量的独立来源；不要再把同一请求的`AiExecution`、`AiUsage`、`UsageRecord`相加。
- `model=null`表示网关没有暴露实际型号；`requestedModel=openclaw/...`是虚拟助手，不能冒充火山实际型号。此次真实型号另由隔离计量代理保存的底层请求确认。
- `usageStatus=reported/partial/unknown/pending/not_requested`区分完整、部分、缺失、未终结及未请求模型；未知或未结束记录不按0统计。
- 缓存是输入的子集，推理是输出的子集，均不重复加总。不从Token小计推断账户全部费用。
- 历史已恢复的469,064 Token见`var/operations/20261023-model-usage/review-v2.md`；不覆盖其中162次没有用量的历史HTTP成功响应。本批另计，不能把6.8万当作账户总量。

只读查询入口（在API目录、具备目标库的运维环境执行）：

```sh
node scripts/report-model-usage.cjs --since=2026-10-23T00:00:00Z --environment=production
node scripts/report-model-usage.cjs --since=2026-10-23T00:00:00Z --batch=<BATCH_UUID>
```

隔离替身与付费QA通过环境、批次及真实模型回执区分；不能把所有`NODE_ENV=test`记录一律视为免费，也不能把替身的虚拟Token当成真实消耗。

### 调试中发现与处理

1. 首次400来自测试代理额外填写`max_tokens`，与网关的`max_completion_tokens`冲突。已统一为单一上限参数；该次没有用量明细，单列未知。
2. 初始10万预算为上述未知400保留39,735 Token的保守占位，之后拦截了后续请求。网关将本地503拦截反复重试，均未再次发往火山；据此定位并关闭8次恢复重试。预算拒绝现在返回不可重试的400。
3. 精简规则定义后首次方案题产生不合法条件，暴露了参数校验在错误恢复范围之外的问题。已补字段错误反馈、强化类型提示；只重测失败题，最终2次请求通过。
4. 方案回答曾按网关日期推断固定时钟样本已过期。补充工具状态优先的约束后，单次真实模型状态复核通过。普通生产时钟/历史数据组合未全面验收。

预算调整在续测前向用户说明：底层请求上限从24收紧到12，用量预算从10万调整为13万，继续保留400未知占位。最终已知用量加保守占位为107,761，小于最终预算；占位不是已发生账单。另有一个应用层执行被本地预算挡住，没有相应火山请求，不能把应用/底层未知计数相加。

## ERP专项检查与修复（D-055）

日期：2026-10-23。本节记录新平台ERP本地检查阶段，不涉及`existing-business-apps`。该阶段未发起新的火山请求；后续发布另见58。D-054账本、失败用量和网关重试治理属于共享Runtime，ERP复用这些机制；ERP没有CRM的`load_skill`只读工具循环，不能把CRM的43次重复读取直接归到ERP。

### 发现的问题及处理

| 问题怎样发生 | 后果 | 本批修复 |
| --- | --- | --- |
| 对话默认允许提出操作，ERP未筛选工具，每次预装供应商/商品；具备权限还会加入全量补货建议 | 普通分析和无关操作带入额外输入；与库存上下文重复 | 按本轮问题选择工具；咨询/否定操作意图不提供写工具；参考对象跟随实际可用工具。库存上下文已有资料时不再预装补货清单 |
| 库存、客户商机列表没有模型输入条数范围说明 | 大企业上下文膨胀；截取后容易误当全部 | 模型库存明细最多100项，其他候选/补货/商机最多50项；标记总数（可知时）和是否部分结果；不得补造未给出的对象ID |
| 新建商机工具需要客户ID，但原选项没有客户引用 | 模型可能猜ID或多次询问 | 仅在商机创建时提供有权客户引用，保留销售负责人范围与数量上限 |
| 合同上下文直接查库存，只沿用合同查看权 | 无库存权限的合同查看者可能得到额外库存事实 | 独立检查库存查看权；无权时既不查询也不发送库存/缺货数，不将未知当作0；补货计划工具也需库存权限 |
| ERP派生回答缺少授权范围凭据 | 角色变化后正文可能继续带出先前有权取得的资料 | 新生成对话/分析记录携带授权范围；读取和续聊时复核。角色变化后整条派生回答隐藏，后台消息结果拒绝访问 |
| 通用业务分析没有像风险检查一样复核模型处理期间的数据变化 | 将已过时事实作为当前建议交付 | 返回前重新读取并比较事实；变化时拒绝交付该次分析，已发生模型用量保留 |
| 24k输入检查仅在对话循环，模块分析/风险/提取未共用 | 其他入口可绕过同样的输入准入 | 检查下沉Runtime入口并覆盖直连Gateway；平台组装消息/工具估算超限先拦截，不静默截断事实。不含网关/供应商内部附加开销，不是账单绝对上限 |
| 模块内分析/风险/提取统一记为reply | 难区分哪个功能消耗高 | 用途分为analysis、risk_review、document_extract；保留reply与context_summary；只读报表支持`--app`和`--purpose`并按两者分组 |
| 数据库取消先落地、模型用量随后返回，但本进程尚未收到取消信号 | 账本可能误记失败，执行表却是取消 | 失败处理同时核对数据库终态，保留cancelled状态及已知用量 |

没有移除记忆、写操作确认、对象授权或正式业务校验。按关键词选择工具只是减少候选，不能授予权限；未识别的操作需用户明确对象和动作，模型不能自行扩大工具范围。候选超限时当前不自动分页或额外调用模型；需缩小范围或从业务页选择，不能宣称已分析完整企业。旧记录缺失授权凭据、模型型号或用途时，不补造历史信息。
