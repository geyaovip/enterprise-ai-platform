# 路由与接口契约

此处是新平台的**目标路由**，不是现有线上地址。Web URL 统一表示企业和应用上下文；浏览器只访问同源统一 API。平台与 ERP 路由由同一个后端的不同代码模块处理；后续 CRM、MES 按业务前缀注册模块路由，不要求独立服务。`tenantKey` 为稳定、URL 安全的企业标识，不能作为权限凭据。模块开发规则见 [10 应用模块契约](10-应用接入契约.md)。

## Web 路由

| 路由 | 页面 | 权限/行为 |
| --- | --- | --- |
| `/login` | 登录 | 已登录用户转到最近有权租户或企业选择。 |
| `/tenants` | 企业选择 | 仅显示当前用户所属企业；单企业可跳过。 |
| `/t/:tenantKey` | 应用入口 | 显示已启用且有权限的应用。 |
| `/t/:tenantKey/ai` | AI 聊天与业务操作 | 显示当前企业及可选择的已授权应用上下文；对话可调用受控业务 Tool，操作进度和结果留在会话中。 |
| `/t/:tenantKey/erp` | ERP 经营概览 | 依据角色展示真实指标与入口。 |
| `/t/:tenantKey/erp/customers`、`/customers/:id` | 客户列表/详情 | 销售 owner 范围由服务端执行。 |
| `/t/:tenantKey/erp/opportunities` | ERP 商机 | 首期由 ERP 持久化；访问范围由服务端执行，未来 CRM 关联按 Q-003 确定。 |
| `/t/:tenantKey/erp/products` | 产品目录 | 搜索、分页、停用状态。 |
| `/t/:tenantKey/erp/suppliers` | 供应商 | 采购相关角色。 |
| `/t/:tenantKey/erp/purchases`、`/purchases/:id` | 采购列表/详情 | 草稿、确认、分批入库和 AI 分析在业务详情中。 |
| `/t/:tenantKey/erp/contracts`、`/contracts/:id` | 销售合同列表/详情 | 草稿、确认、分批出库和 AI 分析。 |
| `/t/:tenantKey/erp/inventory` | 库存与流水 | 盘点入口与库存结果。 |
| `/t/:tenantKey/erp/finance` | 应收应付 | 财务角色可进入并登记收付款。 |
| `/t/:tenantKey/admin/members` | 企业成员 | 企业管理员。 |
| `/t/:tenantKey/admin/org` | 组织单元与成员归属 | 企业管理员；仅管理租户内组织，负责人范围由服务端校验。 |
| `/t/:tenantKey/admin/apps` | 应用启用 | 企业管理员。 |
| `/t/:tenantKey/admin/ai` | AI 配置与用量 | 有授权的管理员。 |
| `/t/:tenantKey/admin/audit` | 审计 | 有审计读取权限者。 |

未知地址显示可恢复的 404；无权访问显示 403，不能伪装为空列表。浏览器回退与刷新保持企业/应用上下文；切换企业时关闭旧租户的 AI 面板、清理页面缓存并重新取数。旧项目的路由只是功能参考；如实际客户切换需要保留书签，再设计明确的重定向，不把旧会话自动视为新平台会话。

## API 命名

公共入口为 `/api/v1`。平台级身份接口如 `POST /auth/login`、`POST /auth/logout`、`POST /auth/change-password`、`GET /me`、`GET /tenants`；租户资源统一置于 `/tenants/:tenantKey` 下。ERP 示例：

```text
GET  /api/v1/tenants/:tenantKey/apps
GET  /api/v1/tenants/:tenantKey/members
GET  /api/v1/tenants/:tenantKey/org-units
POST /api/v1/tenants/:tenantKey/org-units
PATCH /api/v1/tenants/:tenantKey/org-units/:id
GET  /api/v1/tenants/:tenantKey/audit-logs
GET  /api/v1/tenants/:tenantKey/ai/conversations
POST /api/v1/tenants/:tenantKey/ai/conversations
DELETE /api/v1/tenants/:tenantKey/ai/conversations/:id
POST /api/v1/tenants/:tenantKey/ai/conversations/:id/messages
GET  /api/v1/tenants/:tenantKey/ai/actions/:id
POST /api/v1/tenants/:tenantKey/ai/actions/:id/confirm
GET  /api/v1/tenants/:tenantKey/ai/risk-reviews/:type/:id
POST /api/v1/tenants/:tenantKey/ai/risk-reviews

GET  /api/v1/tenants/:tenantKey/erp/purchases
POST /api/v1/tenants/:tenantKey/erp/purchases
GET  /api/v1/tenants/:tenantKey/erp/purchases/:id
POST /api/v1/tenants/:tenantKey/erp/purchases/:id/confirm
POST /api/v1/tenants/:tenantKey/erp/purchases/:id/receive

GET  /api/v1/tenants/:tenantKey/erp/contracts
POST /api/v1/tenants/:tenantKey/erp/contracts/:id/ship
GET  /api/v1/tenants/:tenantKey/erp/inventory
POST /api/v1/tenants/:tenantKey/erp/inventory/stocktakes
GET  /api/v1/tenants/:tenantKey/erp/finance/receivables
POST /api/v1/tenants/:tenantKey/erp/finance/receivables/:id/payments

POST /api/v1/tenants/:tenantKey/ai/tasks
GET  /api/v1/tenants/:tenantKey/ai/tasks/:id
```

其余 ERP 资源在同一 API 中按业务前缀开发。实施每个资源时，以新需求和验收契约为准，旧 API 仅供核对业务行为，不照搬参数或数据库结构。聊天消息可产生问答、待确认动作或执行中的动作；动作记录返回状态、目标对象、业务回执和 request ID。确认接口仅确认服务器保存的具体动作内容，执行前重新校验权限与对象版本。采购/合同履约分析分别返回系统核算事实和模型建议，并仅在单据及库存事实未变化时展示已保存结果；单据提取等模块 AI 通过已注册的应用能力和任务接口执行。所有业务上下文由服务端读取、按租户/对象权限裁剪；聊天中的应用上下文不授予额外权限。

统一 API 对每次 ERP 请求核验当前会话、成员状态、应用启用和动作授权，生成服务端可信的 `AppContext`/`RequestContext`；`appId` 是授权上下文的一等字段，不能只从 URL 前缀推断。ERP 模块继续校验对象范围与业务状态；AI Tool 在执行和确认时重新核验 App、成员及对象权限。同进程模块不需要内部签名 HTTP 调用。平台管理路由与 ERP 业务路由分属不同模块，业务写入只能经过数据所有者的应用服务。

## 请求与响应规则

- Cookie 会话只通过 HTTPS 传输，设置安全属性；写请求校验来源并使用 CSRF 防护。服务端从会话、已验证成员关系与 TenantApp 形成 `RequestContext`，不得信任请求体中的 `tenant_id`、`user_id`、`appId` 或角色；客户端选择应用后仍须授权。
- 列表统一 `page`、`page_size`、排序与过滤字段；服务端设页大小上限。返回 `items`、`page`、`page_size`、`total`；无权数据不能算入总数。
- ERP 客户与供应商列表的 `q` 可按名称或编号检索，商品列表可按名称或 SKU 检索，商机列表可按名称检索并用 `customerId` 限定客户；建单选择器分页查询并保留已选项，不以首 100 条作为完整目录。
- 写接口对金额/数量、业务版本和关联对象做服务端校验；可能重复提交的创建/付款/出入库动作使用幂等键或唯一业务约束。版本冲突返回可识别机器码并提示重新载入。
- 错误结构统一为 `{ "error": { "code": "...", "message": "...", "request_id": "..." } }`。至少区分未登录、无权限、对象不存在、输入无效、业务冲突、限流和服务不可用。客户界面显示可行动信息，不回显内部异常或敏感参数。
- 异步 AI/文档任务返回任务 ID 与状态；状态至少有 `queued/running/completed/failed/cancelled`，失败保留可重试和审计信息。业务写入不能因模型超时而误报成功。
- 聊天触发业务写入时，成功响应必须来自应用 Service 已提交的结果；返回 `action_id`、目标对象 ID/链接、实际状态和 request ID。重复提交、模型重试与用户刷新必须按幂等键避免重复写入。
- 请求与响应类型应由契约/同源 schema 生成或共享，不手写两套互相漂移的类型；公开 API 变更需有兼容窗口和迁移说明。
- 统一 API 发布 OpenAPI/schema；每个业务模块维护自己的资源定义，公共契约只规定身份上下文、错误、分页、幂等和审计等通用字段。平台与业务模块按同一代码版本构建和发布。

## 路由验收

登录、企业切换、直接输入详情 URL、刷新、浏览器后退、无权、对象不存在、会话过期、移动端导航都必须验证。API 还要以 Tenant A/B、不同 ERP 角色和 AI Tool 调用分别验证同一路由的授权结果；伪造请求体中的租户、用户或角色必须被拒绝。停用 ERP 或撤销成员权限后，下一次请求应立即按新状态执行。
