## 客户试用补齐（2026-10-07）

- `GET erp/work-items?page=1&page_size=20&kind=all&q=`：返回 `items/total/page/page_size/counts`；支持指派任务、采购入库、销售发货以及现有审核/到期跟进/开票/认领类型，逐类型权限限制。旧 `truncated` 字段暂保留为 false。
- `POST erp/master/:kind/import-preview`，body `{csv}`：`kind` 仅 customers/products/suppliers；返回 `total/valid/errors[{row,message}]/columns/items`，items 为前 10 条。
- `POST erp/master/:kind/import`，body `{csv,requestKey}`：UUID 请求键，整批原子新增，返回 `{kind,count,repeated}`。同键换内容为 409；编号冲突整批回滚；无导入角色为 403。
- `GET erp/master/:kind/export?q=`：按当前权限与关键词返回 `{filename,csv,total}`，最多 10000 条；客户端生成 UTF-8 CSV 下载。
- CSV 限制、业务归属和验收见 [28](28-功能完整性检查与客户试用准备.md)。无数据库结构变更。

此处记录路由契约，不把每条目标路由自动认定为上线能力；当前可用入口和已验证 D-029 增量见 [41](41-六批优化交付与线上验收.md)，本页末尾为已实现的通用接口。D-016 将 Enterprise Workspace、Tenant Admin、Platform Admin 拆为三个独立前端；它们访问同一受控 API，跨域部署时按明确允许的来源、Cookie/CSRF 和登录跳转配置。平台与 ERP 路由由同一个后端的不同代码模块处理；后续 CRM、MES 按业务前缀注册模块路由，不要求独立服务。`tenantKey` 为稳定、URL 安全的企业标识，不能作为权限凭据。模块开发规则见 [10 应用模块契约](10-应用接入契约.md)。

当前 Workspace 的 `/t/:tenantKey/admin/*` 统一重定向到独立 Tenant Admin 的 `/t/:tenantKey`，再按当前身份鉴权。成员、组织、能力及审计由管理首页的左侧设置目录承接；未实现原规格的每个管理子地址。Tenant Admin 另有 `/t/:tenantKey/knowledge` 与 `/channels`。Platform Admin 的 `/`、`#tenants` 承接企业列表；`#tenants/:tenantId` 是独立企业配置页，支持刷新与返回列表；`#usage`、`#audit` 分别承接运行用量和运营审计。成员 AI/知识环境在配置页弹窗编辑。Workspace 当前知识地址为 `/t/:tenantKey/knowledge`，空间和文档在该页选择，引用深链接为 `?citation=:id`；`/knowledge/spaces/:id`、`/knowledge/documents/:id` 尚未作为独立页面实现。

开发端口分别为 4601、4603、4604；生产 Compose 在同一 Origin 下用 `/`、`/tenant-admin/`、`/platform-admin/` 发布三个独立构建。跨 Origin 部署时单独配置明确来源、Cookie 与回跳地址。历史三端路径部署证据见43；D-043/D-044新增改动的生产发布与端到端验证仍待对应发布。

未知地址显示可恢复的 404；无权访问显示 403，不能伪装为空列表。浏览器回退与刷新保持企业/应用上下文；切换企业时关闭旧租户的 AI 面板、清理页面缓存并重新取数。旧项目的路由只是功能参考；如实际客户切换需要保留书签，再设计明确的重定向，不把旧会话自动视为新平台会话。

两个ERP业务入口使用同一 `/ai/conversations` API。`POST` 可选传 `agentId`；服务端按当前成员、TenantApp 和 `defaultAgentId` 解析，目前业务应用只登记 `erp.assistant`；两个只读管理域助手按46单独解析。显式指定无权或未知 Agent 返回 403。既有会话表不变，列表/详情按当前 ERP 授权访问，旧会话无需迁移。页面差异只是标题和资源上下文；会话 ID 可以跨两个入口打开。

D-048：消息`POST conversations/:id/messages`和后台`POST conversations/:id/turns`兼容增加`requireConfirmation:boolean`（缺省false）；公共ERP固定与`allowAction:true`一起发送true，操作只生成pending提案。该字段不能降低Tool原有确认要求，幂等比较包含它；管理域仍拒绝业务操作/知识检索。确认沿用`POST actions/:id/confirm {previewHash?}`，参数在自动展示的工作单核对，一次点击提交；重复确认返回原回执。详情见[51](51-AI对话操作简化.md)。

### D-021 内置知识库增强

沿用 `PUT /operator/tenants/:id/infrastructure/:kind/tenant`，新增 `knowledge-ocr/openai-vision` 与 `knowledge-rerank/api-rerank`（kind/provider）；输入 `{provider,baseUrl,secret?,version,enabled,options:{model}}`。仅运营方可写；加密凭据不返回。停用恢复默认 Tesseract/本地规则。现有 `runtime` 与 `knowledge` 保持原契约。

`GET /tenants/:key/knowledge/engine` 新增 `enhancements`，含 `retrieval=hybrid`、`chunking=structure`、`ocr`、`reranker`、`ocrCloud`、`rerankCloud`；非内置引擎为 null。搜索数组元素可带 `{retrieval:{mode,reranker,degraded}}`，排序信息不参与引用身份哈希。`locator` 可包含 `headings`、`block`、`table/tableHeader`、`ocr/ocrProvider`、`image`，保留行、段落、工作表和页位置。

内置上传新增 PNG/JPG/JPEG，扫描 PDF 自动识别。页数、像素、时间上限和错误码见 [32](32-轻量知识库检索与识别增强.md)。外部重排序失效时界面显示本地规则回退，OCR 无效输出不标为完成。

WHERE ownerMembershipId IS NULL` 原子竞争，失败返回 409，领用成功写 ERP 审计。普通客户列表仍按销售 owner 限定。`followups` 在服务端先重查商机对象范围；写入保留处理人、内容和可选 ISO 下次跟进时间，已经结束的商机不能再安排未来跟进。下一次跟进时间目前是记录字段，不等于提醒任务。打印仅是浏览器基于当前已授权采购详情生成的打印件，不是新公开 API，也不代表签章生效。

管理员可用 `customers/:id/transfer` 携带预期旧负责人、新销售成员或 `null` 公海，以及必填原因。服务端只接受当前租户在职销售作为新负责人；待审销售合同、开票申请或收款认领须先处理。转派同步更新客户、关联商机及合同负责人，合同版本递增以拒绝旧版本操作，历史审计不改写。存在商机、合同或到账记录时不得退回公海，只能转派给销售；空关联客户可退回后重新领用。关联对象若已有不一致的负责人，停止自动转派，交由管理员核对。

采购和销售草稿由其发起人以当前 `version` 提交为 `pending_approval`；仅具 `erp.purchase.approve` / `erp.sales.approve` 的管理员可将其审核为 `ordered` / `confirmed`，或带 `reason` 退回 `draft`。审核人与发起人不能相同；已提交未审核单据不可入库/出库。管理员可以直接确认自己创建的草稿，服务端以 `administratorDirectConfirm=true` 留审计，作为当前单管理员试用环境的特权例外。普通采购/销售账号没有直接确认权限，AI 采购确认 Tool 也只对管理员可用。退回到草稿后，原发起人可携带当前 `version` 修改采购或销售合同的主数据引用、明细与备注；服务端重新核对有效对象、计算价格快照和金额，并在同一事务中替换明细及写审计。已提交或已确认单据不能走草稿编辑。

已确认且尚未全部入库的采购单，由原发起人用 `POST purchases/:id/changes` 提交当前版本、原因及全部现有行的新数量，可改备注；目前不支持增删行、换供应商或改快照单价。新数量不得低于已收数量，无实际变化的申请拒绝。申请后原单版本递增，变更处于 `pending` 时暂停入库；管理员与申请人分离，按变更后的订单版本批准或带原因退回。批准将新数量/总额写回原单，已收数量和已形成应付保持原值；只允许批准一次，退回后可重新申请。变更前后快照、处理人、原因、时间和审计记录可查。当前已有实时待办入口，仍缺持久通知与指派/关闭流程，不能把当前 API 称为完整审批协同。

`erp/work-items` 按当前 ERP 业务状态实时返回当前成员可处理的采购/销售审核、采购变更审核、内部开票登记、收款认领确认和本人到期商机跟进；管理员看不到自己提交单据的审核项。每次请求重新生成可信成员上下文，业务完成或最新跟进记录替代旧记录后待办即消失。最多显示前 100 条并返回实际 `total` 与 `truncated`。它是 ERP 只读待办视图。独立站内任务、公告和持久通知由 ERP Collaboration 拥有，不将关闭任务等同于批准业务单据；处理动作仍在业务详情服务中鉴权和审计。外部可靠投递另行验收。

内部开票申请 `POST erp/invoices` 携带已确认合同 ID、当前合同版本、金额和说明；只允许合同所有者发起，活跃申请与已登记金额总和不能超过合同总额。合同版本在申请事务内递增，避免响应丢失后的同版本重试重复申请。财务成员与申请人分离，可填写租户内唯一的登记编号，或带原因退回。发起人可撤回未登记申请；财务可记录已登记项的作废原因和外部作废凭据编号。登记或作废只是内部状态记录，不代表法定发票开具或税务作废成功，也不自动形成应收；应收仍按实际出库批次生成。申请、登记、退回、撤回和作废均留下 ERP 审计。

`inventory/alerts` 需要 `erp.inventory.read`，采购角色也具有该只读权限；写入仍使用采购或盘点各自的权限。默认 `status=active` 仅返回启用且阈值大于 0、库存不高于阈值的商品；`status=all` 可查看这些商品的当前正常状态。返回状态为 `needs_purchase`、`awaiting_receipt`、`normal`，由实时库存、阈值和已确认采购单的未收数量计算，不是持久化的异常工单。阈值采用 `quantity <= reorderPoint`，因此补货至阈值以上才解除预警；建议新增采购量为 `max(0, reorderPoint + 1 - quantity - confirmedUnreceivedQty)`。采购草稿不计在途；最近入库回执显示入库单号和采购单链接。入库、出库、盘点或阈值变更后再次读取即可看到最新状态。接口按 `page/page_size` 分页，不自动创建、确认采购单或分配负责人。从预警带入采购时，客户端附带 `sourceInventory={productId,balanceVersion,reorderPoint,incomingQty,suggestedOrderQty}`；`POST /erp/purchases` 在同一业务事务内重查库存、阈值及已确认未收量，过期则返回 409，核验后的来源写入创建审计。采购单备注默认显示预警商品与库存版本，用户仍可编辑。

其余 ERP 资源在同一 API 中按业务前缀开发。实施每个资源时，以新需求和验收契约为准，旧 API 仅供核对业务行为，不照搬参数或数据库结构。聊天消息可产生问答、待确认动作或执行中的动作；动作记录返回状态、目标对象及业务回执。结果不明时返回 `result_unknown`，保留操作 ID，禁止盲目重试；用户可刷新操作详情按同事务业务审计恢复回执。会话最后一条用户消息若因进程中断超过两分钟未完成，读取时补入恢复说明；最近操作列表保留定位入口。采购草稿 Tool 先展示供应商、商品、数量与预估金额；确认时携带服务端预览哈希，引用或价格变化则拒绝，待确认操作可取消。确认接口仅确认服务器保存的具体动作内容，执行前重新校验权限与对象版本。AI 入库/出库 Tool 必须明确每行 ID 和数量，避免省略明细触发整单操作。采购/合同履约分析分别返回系统核算事实和模型建议，并仅在单据及库存事实未变化时展示已保存结果；单据提取通过 ERP Skill 调用核对服务。所有业务上下文由服务端读取、按租户/对象权限裁剪；聊天中的应用上下文不授予额外权限。

统一 API 对每次 ERP 请求核验当前会话、成员状态、应用启用和动作授权，生成服务端可信的 `AppContext`/`RequestContext`；`appId` 是授权上下文的一等字段，不能只从 URL 前缀推断。ERP 模块继续校验对象范围与业务状态；AI Tool 在执行和确认时重新核验 App、成员及对象权限。同进程模块不需要内部签名 HTTP 调用。平台管理路由与 ERP 业务路由分属不同模块，业务写入只能经过数据所有者的应用服务。

### 到账流水与认领边界

财务 `POST erp/receipts` 只人工登记已核实的客户到账，租户内银行流水号唯一，不等于银行直连。销售只能查看并认领自己负责客户的到账，`claimable` 返回同客户、本人合同的未结应收；申请须携带流水当前版本和逐笔分摊金额，合计不得超过未分摊到账或应收余额。流水一次仅允许一笔待审认领。财务确认前不冲抵应收；另一名财务成员审核时重新核验申请人仍在职、仍负责客户及合同，确认后同事务生成逐笔收款回执、更新应收余额和流水已分摊金额。财务可带原因退回，申请人可撤回；未分摊且无待审认领的误登记可带原因取消。版本冲突、重复流水及重复确认被拒绝，申请与审核均留审计。财务待审认领进入 `erp/work-items`，完成后消失。已确认分摊的冲销和银行流水自动导入尚未实现，不能宣称完整银行对账闭环。

## 请求与响应规则

- Cookie 会话只通过 HTTPS 传输，设置安全属性；写请求校验来源并使用 CSRF 防护。服务端从会话、已验证成员关系与 TenantApp 形成 `RequestContext`，不得信任请求体中的 `tenant_id`、`user_id`、`appId` 或角色；客户端选择应用后仍须授权。
- 列表统一 `page`、`page_size`、排序与过滤字段；服务端设页大小上限。返回 `items`、`page`、`page_size`、`total`；无权数据不能算入总数。
- ERP 客户与供应商列表的 `q` 可按名称或编号检索，商品列表可按名称或 SKU 检索，商机列表可按名称检索并用 `customerId` 限定客户；建单选择器分页查询并保留已选项，不以首 100 条作为完整目录。
- 写接口对金额/数量、业务版本和关联对象做服务端校验；可能重复提交的创建/付款/出入库动作使用幂等键或唯一业务约束。版本冲突返回可识别机器码并提示重新载入。
- 错误结构统一为 `{ "error": { "code": "...", "message": "...", "request_id": "..." } }`。至少区分未登录、无权限、对象不存在、输入无效、业务冲突、限流和服务不可用。客户界面显示可行动信息，不回显内部异常或敏感参数。
- 异步 AI/文档任务返回任务 ID 与状态；状态至少有 `queued/running/completed/failed/cancelled`，失败保留可重试和审计信息。业务写入不能因模型超时而误报成功。
- 聊天触发业务写入时，成功响应必须来自应用 Service 已提交的结果；返回 `action_id`、目标对象 ID/链接、实际状态和 request ID。重复提交、模型重试与用户刷新必须按幂等键避免重复写入。
- 请求与响应类型应由契约/同源 schema 生成或共享，不手写两套互相漂移的类型；公开 API 变更需有兼容窗口和迁移说明。
- 统一 API 发布 OpenAPI/schema；每个业务模块维护自己的资源定义，公共契约只规定身份上下文、错误、分页、幂等和审计等通用字段。平台与业务模块按同一代码版本构建和发布。

## 路由验收

登录、企业切换、直接输入详情 URL、刷新、浏览器后退、无权、对象不存在、会话过期、移动端导航都必须验证。API 还要以 Tenant A/B、不同 ERP 角色和 AI Tool 调用分别验证同一路由的授权结果；伪造请求体中的租户、用户或角色必须被拒绝。停用 ERP 或撤销成员权限后，下一次请求应立即按新状态执行。

## 客户服务状态（2026-10-07）

`GET /api/v1/tenants/:tenantKey/service-status`：已登录的有效企业成员可读；匿名 401、其他企业 403。返回 `{ai:{enabled,configured},knowledge:{enabled,configured}}`。AI enabled 同时依赖 AI 能力交付/启用与 ERP 授权/启用；configured 只读取当前成员启用的 runtime 绑定。知识 configured 只读取本企业启用的 tenant 知识绑定。响应不包含服务地址、密钥、适配器选项及其他成员信息；不代表连接健康。

## D-020 内置轻量知识库与引擎选择

- `GET /api/v1/tenants/:tenantKey/knowledge/engine`：有效且获知识能力的成员可读，返回 provider/version/formats/embeddingCloud、方案是否已配置/有更新、切换进度及可回退状态；不返回地址、凭据或模型配置。
- `POST .../knowledge/engine/select`：企业知识管理员，`{provider:"native"|"ragflow",version}`。目标已配置且健康后创建候选代次，从平台当前有效原件重建，原引擎继续服务。相同 provider 的已更新模型档案也可选择；相同配置不重复切换。全部成功后经版本校验事务启用，失败保留原引擎；409 表示配置竞争或正在切换。
- `POST .../knowledge/engine/cancel`：知识管理员，`{id}`，停止本企业正在准备的任务并清理候选索引。
- `POST .../knowledge/engine/rollback`：知识管理员，`{version}`，按上次成功切换保存的旧配置重建新代次，成功后启用，不复用已删除的旧外部数据集。
- `PUT /api/v1/operator/tenants/:id/knowledge-profiles/:provider`：运营权限，`{provider,baseUrl,secret?,version,options:{embeddingModel,embeddingFormat?}}`；profile version 独立递增，保存档案不改变启用的配置。配置 GET 仅对运营人员返回非敏感元数据。

`native` 的 baseUrl 为嵌入模型 API 根地址；embeddingFormat 为 `openai` 或 `ark-multimodal`。地址白名单、凭据加密和并发校验沿用基础设施约束。首次启用仍通过运营基础设施配置；直接运营重配会停止候选任务，常规替换应使用档案与企业端切换。

文档列表的版本增加 `processingError` 安全错误码；支持格式随当前引擎展示。内置上传限制普通 PDF、DOCX、XLSX、UTF-8 TXT/MD/CSV；单文件 8 MiB、Office 解压 32 MiB、文字 180000 字、分块 256 个。无文字 PDF 明确失败，嵌入临时故障按 Worker 规则重试；向量维度不一致返回安全的 503 提示。原文定位增加 paragraph/line/sheet/row 与 end，PDF 保留 positions 页码。
