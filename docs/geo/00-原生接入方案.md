# GEO 原生应用接入方案

GEO 自 D-154 起在知行方舟平台运行，复用平台 API、PostgreSQL 和 Worker，按企业授权开通。D-158 加入 GEO 品牌分析官与报告解读入口。接入方案始于 D-151，实施后的页面、权限和状态见[当前契约](01-接口权限与状态.md)。

## 范围与归属

- 原映川 GEO 工作区、数据库、部署、配置保持只读。新平台从新数据开始，不复制旧账号、会话、凭据、额度或报告。
- 注册第五个应用 `geo`，沿现有 API、数据库、业务前端、两管理端和 Worker；不增加后端、队列或登录系统。
- 纵向闭环：品牌项目与别名/确认竞品 → 问题分组与地域/联网条件 → 多模型费用预估及确认 → 异步分析 → 原始回答/引用/评分报告 → 每日/每周监测 → 优化负责人/期限/证据 → 冻结条件复测。
- 首版输入品牌事实由用户核对；旧站自动品牌发现、外部网页抓取、Telegram、原管理员专属后台不搬入。本轮不做内容应用联动、消费端 App 抓取、历史迁移、独立官网或市场上架。
- 复制原项目纯函数评分、回答解析、方舟 API 适配器和时区调度作为模块内部代码，保留来源及版本；应用服务按当前平台契约实现，避免复制旧身份/权限/费用系统。

## 平台接入

| 方面     | 方案                                                                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 身份     | 仅使用平台 User、Tenant、Membership、Session；每请求可信 `AuthService.context`                                                                                             |
| 授权     | `geo.read / geo.project.manage / geo.analysis.run / geo.monitor.manage / geo.optimization.manage / geo.settings.manage / geo.ai.use`；管理员拥有全部，成员按本应用角色授权 |
| 前端     | `/t/:tenantKey/geo`；项目、问题、分析、监测、优化、设置，复用 Shell、切换器、Dialog、分页、主题、AI 对话                                                                   |
| 配置     | 企业内 GEO 多模型设置，服务端加密；沿火山方舟固定官方端点，只使用目标模型原生联网；不变更其他应用的文字/图像配置                                                           |
| 数据     | GEO 专属表均带 tenantId；项目、问题、模型不可变版本、分析与回答、计划、优化任务分开建模；JSON 仅保存不可变输入/结果快照                                                    |
| 任务     | 当前 Worker 增加 GEO 调度与执行通道；数据库持久化、租约、请求幂等、有限重试、未知结果保留，拒绝盲目重发付费请求                                                            |
| 任务中心 | 统一入口贡献 GEO 分析任务及状态；继续使用所属应用接口取消/恢复并重新鉴权                                                                                                   |
| 审计通知 | 写入平台 AuditEvent、PersonalNotification；读取通知与任务需再次检查 GEO 权限                                                                                               |
| 用量     | 每个调用记录型号版本、Token、费用、耗时、供应商回执及结果；费用预估与实际分开，未知费用留空；不消耗普通聊天三次试用                                                        |
| AI       | 接平台 Provider，读取有权项目和结果，生成解释和行动建议；批量付费分析沿页面费用确认，不允许聊天绕过预算                                                                    |

## 不变量与失败恢复

- 所有资源访问同时校验 tenantId 和 appId 权限；任务开始、调用前、写回终态重新检查成员、企业、应用和动作权限。
- 提交幂等键与内容指纹绑定；同键异内容返回冲突。分析冻结品牌、问题/模型版本、地域、联网、解析/评分版本；复测不读取当前问题替代历史条件。
- 单次组合/输入/输出有界，缺失价格、凭据、联网能力或样本时明确阻止或跳过；费用确认不能被任意客户端输入替代。
- 网络超时、进程在提交后退出、5xx 等无法确认是否计费的情况标记结果未知，保留预算占用，不自动重发；明确拒绝的限流可以有限重试。
- 运行租约与版本控制防止并发重复执行；暂停计划不撤销已经提交的分析。撤权则停止新调用，已发生费用和回执仍保留审计。
- 只在同配置、同解析/评分版本和完整有效样本下展示复测分差；分母使用有效回答，排名仅使用明确编号，无样本为 null。

## 开发与验收顺序

1. 数据模型、权限、平台注册及独立迁移验证。
2. 项目/问题/模型、估价与异步执行，接报告及证据。
3. 监测、优化复测、通知/任务中心、AI 与原生前端。
4. 隔离库 HTTP 流程、跨企业/成员越权、配置冲突、幂等、费用与未知结果、租约恢复、计划时区及复测对比。
5. 三前端/API 构建、既有应用回归、真实浏览器桌面与手机/深浅主题；核对原 GEO 源码指纹。
6. 提供本地验收入口、已测/未测边界及测试记录。真实供应商付费调用与客户验收单独记录，不以适配器替身冒充。
