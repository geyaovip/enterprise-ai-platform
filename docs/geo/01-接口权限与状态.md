## 路由与权限

业务 API 统一前缀 `/api/v1/tenants/:tenantKey/apps/geo`；浏览器使用同源 `/api`，身份只来自平台会话。企业管理与平台运营从真实应用目录交付、启停，GEO 不默认给全部企业开通。平台管理员和 GEO 管理员不是同一授权。

## 模型、版本与费用

- 企业最多8个 GEO 模型，首版使用固定火山方舟官方端点；不允许客户端提供任意代理地址。服务端密钥使用平台 `AI_ENCRYPTION_KEY` 加密，与其他应用模型设置相互独立。
- 保存型号、API模式、价格、联网能力时创建新的不可变版本。旧分析和复测引用旧版本；模型整体停用会阻止其后续调用。旧凭据不回显，未从原 GEO 复制任何生产凭据。
- 单价填写人民币/百万Token及人民币/搜索次；数据库用整数微元保存。只按已经返回的实际Token和搜索次数核算；缺失用量进入未知状态，不作免费处理。
- 联网使用 Responses 原生 web_search；每次最多1轮、1个关键词、3条结果；估价包含输出2048Token、输入保守估算及1次搜索。外部供应商的实际计费不构成本系统的硬上限承诺。
- 单次最多32个问题、8个模型、64个实际组合；费用准入最高100元。默认每日预算20元、最多5个待处理分析；每日按UTC结算，尚未结束/未知任务跨日保留占用。
- 预算预留使用企业维度事务锁，所有并发提交共同计算；实际结算与预估分开。跨应用普通聊天额度不用于监测调用；调用另写平台 AiModelUsage 便于运营追踪。
- 任务提交必须携带 `requestKey`、`estimateHash`、选择范围和单次上限。同键同内容重放返回原任务，同键异内容冲突；预估后配置改变须重新确认。

## 状态与恢复

分析：`queued → running → completed / partially_completed / failed / cancelled / needs_review`。Worker 每次只执行一个模型组合，按更新时间轮转；与知识处理、BOM、内容生成等现有执行通道独立。

回答：`queued → running → succeeded / failed / skipped / cancelled / outcome_unknown`。只有供应商明确拒绝的429才自动重试，最多3次、间隔一分钟；超时、5xx、响应/用量缺失、提交后进程中断都保留未知状态，不自动重发。租约180秒，单次网络请求90秒；过期的已提交组合转未知，保留审计和预留。

调用前、终态前检查平台成员/企业/应用与动作权限；撤权停止新调用，已经发生的供应商回执和费用仍可落库。取消不能改写已经结束的任务。未知结果可由有权管理员填写账单/回执依据和实际费用，审计保留人工核对事实，原回答仍缺失。

监测：每日/每周，使用项目时区、执行时最新配置；同一计划+到期时刻唯一。执行状态 `pending / running / submitted / skipped / dead_letter`，租约120秒、最多3次非准入错误重试。长时间停机只补一个到期批次，后续排到未来；暂停不撤回已提交分析。创建幂等键绑定完整配置。

优化任务：`open / in_progress / done`；负责人须为企业活跃成员，基线创建后不允许替换。复测通过分析提交接口携带 `baselineId + optimizationId`，固定原品牌、问题、模型版本、地域、联网、解析/评分和协议版本。只有相同条件且两次完整有效样本才给出分差；完成措施不等于效果已验证。

## 页面与公共能力

- 应用 `/t/:tenantKey/geo`：项目列表；项目内问题/分析报告/数据洞察/自动监测/优化复测，另有企业 GEO 模型和权限设置。
- 当前平台任务中心增加 GEO 任务分区，任务实际操作仍由 GEO 接口鉴权；统一通知使用 PersonalNotification，撤权后不展示原通知，目标页面再次鉴权。
- AI 使用 `geo.assistant` Provider、平台会话与受控 Runtime；仅开放有权项目和报告读取工具，付费批量分析不能从对话绕过页面费用确认。Runtime Manager 新增 `geo-assistant` 工具隔离，profile版本2；生产发布时应同步更新该服务，不能只部署前端。
- D-158 上线 GEO 品牌分析官。具备 GEO AI 权限的岗位可从报告解读入口发起对话，读取现有报告的证据片段及冻结复测条件。详情见[158](../158-GEO品牌分析官.md)。
- 所有列表/表单沿共享组件和语义主题；AI快捷问题、深链资源和通知目标按GEO上下文解析，避免回落ERP。
