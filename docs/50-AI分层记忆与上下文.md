# AI 分层记忆与上下文

日期：2026-10-20。决定 D-047：用户在确认短期/上下文保留平台管理、长期复用 OpenClaw 的分层建议后，授权“整体优化”。这是平台公共能力，当前消费者为 ERP 工作台、企业管理、平台运营三个保留域；CRM 业务未因此启动。

## 功能和边界

| 层次 | 本次实现 | 所有权与限制 |
| --- | --- | --- |
| 短期 | 服务端持久化消息、重新打开历史、每会话最多400条消息（约200轮） | 平台 PostgreSQL；不是 OpenClaw Gateway 的原生长会话 |
| 上下文 | 近期最多24条消息，按估算 token 选择；较早消息经 OpenClaw 只读执行生成摘要；摘要缓存随来源、权限范围改变失效，累计8条新增早期消息后刷新 | 平台选择与鉴权，OpenClaw 生成摘要；历史最终最多32条、估算8000 token；特别长的消息会节选，摘要可能遗漏，不承诺完整无损记忆 |
| 长期 | 个人偏好/约定、管理员维护的企业约定；跨会话检索和少量常驻偏好 | 平台持有原文/范围/版本/审计，独立私有服务运行 OpenClaw 2026.9.7 `memory-core` 官方 CLI；当前是关键词检索与中文二/三字 token 投影（问题词先与当前有权资料词表相交，减少长句噪声），**没有接通语义向量检索或 LanceDB** |

企业知识库、记忆、业务事实分别管理。记忆不能替代库存/金额/状态实时查询，不能改变权限或业务确认。Gateway 继续逐轮 Incognito，会话原文不写入其默认跨会话空间，也不开启自动记忆捕获。

只有用户在“管理记忆”中明确保存的文字成为长期记忆。不从聊天原文自动提炼并存储；不把“我记住了”的模型回答视为保存成功。不自动把旧聊天批量导入长期索引。内容由用户填写，基础校验拒绝常见密码/令牌格式，不等于完整敏感信息识别。

## 公共 UI

三端沿统一顶栏“询问AI”打开原浮窗，输入区增加“管理记忆”，不另建聊天页面。使用公共 Dialog、Field、TabBar、ConfirmDialog 和紫色主题。

- 个人记忆仅当前企业、应用和本人可用；企业约定仅当前企业/应用共享，只有管理员维护。
- 新增、修改、删除、有效期、长期记忆开关；每个个人/企业范围最多50条，标题60字符、内容800字符；修改不能直接改变可见范围。
- 开关控制后续检索与常驻偏好注入，不删除记忆或历史聊天；聊天中已经出现的文字仍属于历史上下文。
- 个人常驻偏好最多4条、企业常驻偏好最多2条（最近更新优先），其他约定按问题检索；最终最多8条、标题及正文合计3500字符。只有常驻偏好且未超限时无需启动索引检索。
- 消息显示本轮引用记忆数、早期摘要消息数及降级提示；数量表示进入提示的资料，不代表模型逐条采用或事实正确。
- 删除/修改/过期使旧版本回答与其派生回答失效，续聊不再使用这些正文；用户原始聊天文字不会因删除记忆而删除。已经在浏览器看到或导出的文字无法追回。
- 修改从后续问题生效；正在生成的任务在增量发布和终态检查记忆版本，变化时拒绝继续交付。刷新/任务结果读取也校验引用。

## API 和模型

HTTP 前缀分别为 `/api/v1/tenants/:tenantKey/ai`、`/api/v1/tenants/:tenantKey/apps/:appId/ai`、`/api/v1/tenants/:tenantKey/management-ai`、`/api/v1/operator/ai`。可信 AppContext 从服务器重建，不接受 body 传入 tenant/user/app。

| 方法/子路径 | 输入/结果 |
| --- | --- |
| GET `memory` | `items`、个人启用状态、`canManageShared`、`indexCleanupPending`、引擎配置/关键词模式 |
| POST `memory` | `{title,content,kind:preference\|convention,visibility:personal\|enterprise,expiresAt?:ISO\|null}` |
| PUT `memory/:id` | 同新增字段，加正整数 `version`；旧版本409，无权/不存在404，企业维护需管理员 |
| DELETE `memory/:id` | 删除平台原文、记录不含正文的审计，事务写索引清理任务 |
| GET/PUT `memory/preferences` | `{enabled:boolean}`，按企业/本人/应用隔离 |
| POST `conversations/:id/messages` 或 `turns` | 兼容增加 `useMemory`（默认true）；仍受个人设置约束，不扩大 `allowAction` 的授权 |

新增 `AiMemoryEntry`、`AiMemorySetting`、`AiMemoryIndexPurge`、`AiContextSummary` 四表，迁移 `20261020150000_ai_memory`。摘要以 conversationId 一对一关联，删会话级联删摘要，不在会话 API 中暴露内部摘要行。摘要与正常回答的执行/计量分别记录，`AiExecution.usage.purpose=context_summary|reply`；摘要也消耗模型与额度。失败的摘要保留正常聊天可用性，提示只使用最近消息。

个人及企业记忆按 tenant/app/owner 筛选后才发送检索；返回 ID 再映射到当前 SQL 版本。模型看到原文，不看到分词投影。回复继承历史中的记忆引用，避免已删除信息通过后续回答或摘要恢复。读取历史采用批量版本核对，避免长会话逐条查询记忆。

## 原生 memory-core 适配与运维

`infrastructure/memory-core-server.mjs` 是平台私有桥接，调用固定版本官方 `memory search` CLI及其原生索引初始化，不依赖其内部数据库 API。独立容器复用与 Gateway 相同的已固定 OpenClaw 镜像，未升级 Gateway 或安装 LanceDB。

- 只允许私网 HTTP，独立随机 `MEMORY_CORE_TOKEN`（至少24字符）；不暴露宿主机端口，不挂 Docker Socket，不给模型密钥。API/Worker 使用 `MEMORY_CORE_URL=http://memory-core:18790`。
- 单一串行操作队列，最多8个排队操作，CLI调用25秒上限，平台请求35秒超时；故障时降级，仅注入已确认常驻偏好，并给出提示，不影响业务权限或伪装检索成功。
- 容器512MiB/1CPU限制，进程只读文件系统，`/tmp`独立tmpfs，原文投影及可重建索引保存在专属volume。按 tenant/app/user 哈希隔离目录，企业约定按用户当前范围派生到该索引；不能拿这个目录隔离代替平台鉴权。
- 仅内容/投影版本哈希改变时重置派生索引，由原生search首次同步；问题缓存128项。删除/修改先在 SQL 生效，索引失效任务同事务落库；失效水位持久化，早于该水位的在途旧快照不能重建已删索引；即时尝试清理，失败由Worker每10秒调度重试，指数退避最长5分钟。清理待完成时 UI 明示，旧记录仍不会从 SQL 进入新的回答。
- 有效期立即影响授权检索；过期投影在该范围下次同步或清理时删除。索引清理不是所有备份永久擦除，受限备份仍按运维留存。用户/企业停用不自动销毁历史归档。
- 不对公网开放记忆引擎，不向默认 Gateway 工作区、未知插件或外部向量服务同步。

部署须追加 `compose.memory-core.yaml`，生产操作沿 infrastructure/README。SQL为权威源；索引可从当前授权记录重建，不能从旧索引反向恢复已删除条目。回退前先备份、停API/Worker并等待活动执行归零。旧API不识别memoryRefs，须使用`apps/api/scripts/ai-memory-rollback.cjs`先dry-run，再在维护态清理已失效引用的消息/任务结果及相关摘要，之后才启动旧API；不能直接让旧版读取未清理的历史。保留新增表、仍有效记忆、用户原文和已提交回执，不删数据库/持久卷。
