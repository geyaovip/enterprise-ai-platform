# AI 对话操作简化

更新：2026-10-20。D-048来源为用户指出默认记忆仍展示勾选、对话内容多次折叠/确认，授权统一减少无必要操作。公共规范入口为[ui/04](ui/04-AI对话与工作单.md)，分层记忆机制仍沿[50](50-AI分层记忆与上下文.md)。

## 改动

| 原操作 | 当前交互 |
| --- | --- |
| 记忆勾选框 | 默认启用，显示自动使用；管理页主动暂停/恢复。保留已有暂停偏好，不改成强制记忆 |
| 每条勾选企业知识 | ERP已开通且有权时自动检索；管理域仍不检索。主动快速回答不检索 |
| 展开“回答选项”再选模式 | 紧凑工具栏直接选择自动/快速/深入 |
| 勾选允许操作→打开详情→重复弹确认 | 默认提出有权操作，自动打开待确认工作单；全部参数直接可见，一次“确认执行”才写入 |
| 展开处理记录、参数和回执 | 生成时显示最近三阶段，完成后显示处理概况；工具参数、用户可读回执直接展示，移除原始JSON |
| 低库存建议折叠 | 空会话直接显示前五项及库存页入口，不将整个库存列表塞入聊天 |
| 管理记忆时再次选相同范围 | 由个人/企业Tab确定范围，表单只说明保存位置 |
| 手动刷新会话 | 由已有SSE/轮询自动同步；不再提供重复刷新入口 |
| 每条无引用提示 | 只显示实际记忆/摘要引用或异常提示 |

后续CRM沿公共UI，不启动CRM业务开发；旧三应用未修改。记忆依旧手动保存，不自动采集整段聊天，不共享其他企业/应用/用户记忆。

## 服务端保护

新请求字段`requireConfirmation`缺省false；公共ERP发送`allowAction:true,requireConfirmation:true`。写入前强制保存待确认AiAction，不能因工具本来是低影响动作而自动执行。字段持久化在既有Task JSON，幂等检查包含该值，重试不能切换确认要求。确认复用现有权限/业务预检、previewHash、事务回执及重放保护。两个管理域不接受业务Tool，删除会话/记忆仍需确认。

保留旧API客户端的显式单次allowAction语义。发布顺序必须后端先于新前端：旧后端严格校验未知字段，会拒绝新版请求；若回退须先回退三端再回退后端。不能只切旧API留下新版前端。
