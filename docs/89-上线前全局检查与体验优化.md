# 上线前全局检查与体验优化

2026-10-27，D-089。按用户“逻辑准确、UI规范、使用顺手”的要求检查三应用及公共交互，修复已复现的问题并发布 API/Worker 与三个前端。此记录区分实际验证与尚未覆盖范围，不把视觉规范目标或一次回归当作所有场景无缺陷的证明。

## 检查结论与修复

| 优先级 | 发现的问题及影响 | 已实现的行为 |
| --- | --- | --- |
| 高 | CRM工作台先取最近20条风险再筛选未关闭；当21条新关闭记录排在前面，旧的未关闭风险会漏掉 | 服务端先按open筛选再分页；新增回归先在旧实现复现失败，再在修复后通过 |
| 高 | 范围或币种切换时旧数据可短暂留在新查询下；迟到请求可能带来误读 | 公共读取钩子立即清空不同路径的数据，并保留请求版本保护；20秒读取超时结束等待并可重试 |
| 中 | CRM首页叠加经营机会、工作台和完整报表，7张大卡将经营指标推到首屏以下；两处币种选择独立 | 独立总览：四项指标→待处理与四类运营方案→活跃分布与跟进；一个URL币种驱动指标、人群及下钻 |
| 中 | 读取失败后仍渲染空列表，用户无法区分“没数据”和“加载失败” | 公共DataResult区分首次加载、失败、重试、成功空态；CRM/MES统一接入，ERP未完成业务独立失败提示 |
| 中 | 仅依赖React busy状态，极短时间的重复操作可能进入两次执行 | ERP公共业务动作增加同步ref锁；CRM方案预览同时防重复与过期范围结果 |
| 中 | CRM只读资料借用表单布局，字段留白过大，常用动作被挤下方；长草稿表单按钮不易找到 | 公共DetailFacts语义键值布局；客户详情紧凑展示；草稿/记录等保存动作进入DialogAction固定区，可选观察设置默认折叠 |
| 中 | MES数量输入清空后立即变0，且未明确扣除待审核报工，用户可能提交超过剩余额度的数量 | 保留输入字符串；显示剩余和待审核量；校验非负整数、合计正数及剩余上限；报满后显示“等待报工审核” |
| 低 | D-087导入的12家公司演示客户沿默认电商类型显示个人 | 仅对目标企业、指定演示渠道与DEMO-20261027外部编号的12条记录经profile Service改为organization；保留版本、审计和全部其他字段 |

服务端权限、对象版本、确认、事务及幂等校验继续作为业务写入边界。运营方案只预览和创建草稿，后续提交、确认和人工执行沿原流程；没有自动向客户发消息。
