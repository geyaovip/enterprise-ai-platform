# 工作通道接入与验收

> 文档属性：功能契约。规则与验收要求不等于全部能力已实现或已发布，日期证据保留其环境。状态入口：[47](47-项目现状与文档维护.md)；公共UI：[ui/00](ui/00-公共UI规范.md)。

状态：2026-09-30 本地实现与隔离库验证。飞书真实企业授权、消息收发和机器人权限尚未实测；企业微信、钉钉尚未接通。此处状态不等于客户验收。

## 产品边界

- 平台里的审批、AI 会话、业务状态和审计是事实来源。外部通道只接收、投递、展示和提交已授权命令。
- 首批需要同时覆盖业务通知和 AI 对话/执行。飞书先实现这两类能力的端到端代码路径；企微与钉钉只在界面显示“待接入”，不出现无效扫码按钮。
- 飞书企业管理员在“工作通道”中扫码创建自建机器人。使用飞书官方 Node SDK `registerApp`，仅申请机器人发送消息和接收消息事件。管理员在飞书授权页核对权限。平台保存加密应用凭据，Worker 以官方 SDK 的 WebSocket 长连接收消息；客户无需填写回调 URL。
- 每名员工在平台生成一次性 16 位绑定码，10 分钟内私聊机器人发送“绑定 绑定码”。身份映射绑定到当前租户的成员，不依据昵称/手机号猜测。解除绑定后立即停止新消息映射。
- 飞书私聊默认是查询；只有消息以“执行：”开头才允许 AI 发起当前角色可用的业务工具。高影响业务工具返回直达该会话和待确认动作的 Web 链接，仍需登录后重新鉴权、核对确认。群聊、非文本消息当前不处理。
- 采购单提交、审核通过、退回会在同一数据库事务中登记飞书投递任务。Worker 异步投递给已绑定目标成员；未绑定者保留待投递状态。平台记录发送回执和失败状态，不把排队当作送达。管理员可给自己发送测试消息并查看回执。

## 安全与运维

- `CHANNEL_ENCRYPTION_KEY` 是单独的 32 字节 Base64 AES-GCM 密钥，仅在 API/Worker 环境保存。不要写入代码或提交真实密钥。轮换需先设计凭据重加密流程。
- 扫码申请、通道状态、身份绑定、测试投递按租户和角色校验。外部消息先按官方应用连接归属租户，再通过外部用户 ID 找已绑定成员；每条 AI 消息重新检查成员、应用和工具权限。
- 同一飞书应用只连接一个平台租户。Worker 使用单实例运行这套长连接；多副本需独立的连接所有权协调。当前重试语义是至少一次，极端的发送后宕机可能重复投递，后续接客户前需进行故障注入验证。
- 飞书 `registerApp` 成功仅代表取得应用凭据；长连接建立、成员绑定、测试消息回执、真实私聊查询与操作回执需要分别验收。官方机器人能力和企业审批/发布权限以实际租户返回为准。
- 企微和钉钉需确认企业应用授权、机器人双向消息、稳定的成员 ID、撤权事件与扫码安装路径，再分别实现。Octop 只作为交互参考，不复制其渠道凭据或未经核实的接口。

## 验收清单

1. 隔离数据库执行迁移与 schema diff，备份和恢复可用；平台现有权限与 ERP 事务回归通过。
2. 管理员扫码授权：取消、过期、权限拒绝、重复创建和换租户均有明确状态；应用凭据不出现在 API 响应和日志中。
3. Worker 长连接建立后仍需收一条真实私聊；未绑定者只能绑定，绑定码不能跨租户/重复使用/复用他人身份。
4. 已绑定成员查询 ERP 数据、发送“执行：”低影响工具、高影响工具转 Web 确认，停用成员/ERP 后立即拒绝。
5. 采购审核通知真实投递到目标人，未绑定、网络断开和重试均留下可核对状态；测试消息收到飞书消息 ID 回执。
6. 企微、钉钉在完成上述同等级验证前持续标“待接入”，不参与已交付能力统计。
