# AI原生工作流

## 业务结果

| 场景 | 事实→分析→受控行动→跟踪 |
| --- | --- |
| BOM核查 | 查询真实BOM/稳定行ID与当前版本→核查用量/单位/损耗和缺失依据→一次确认保存结构化问题→BOM详情逐项核实并留依据→发布前强制核验 |
| 生产准备 | 查询真实产品/已发布BOM→服务端展开多级需求→分析所用版本、需求和未知项→一次确认创建计划草稿→计划详情人工发布和派工 |
| 生产协作 | 查询当前授权概览/计划/工单→解释逾期、待审核、不良和进度→指向对应业务对象→受派人报工、主管审核→已审核数反馈概览 |

不是自动排产或质量判断。缺少产能、库存、设备和工艺数据时不能输出“最优排程”“实际缺料”或承诺交期。

## Provider与运行边界

`MesAiProvider` 注册appId=mes、agentId=mes.assistant、permission=mes.ai.use。工具按当前问题选择；同时包含“计划”和“BOM”时优先生产计划工具，避免漏掉需求预览与计划草稿：

- 读：`mes.production_overview`、`mes.list_records`、`mes.inspect`、`mes.preview_plan`。
- 待确认写：`mes.create_bom_draft`、`mes.create_plan_draft`、`mes.save_bom_review`。
- 不暴露发布、派工、开工、报工数量填写、审核通过、删除和跨应用写工具。

查询再核对对象种类权限；操作员不能借list_records读取物料/BOM或整张计划。AI只获得已保存事实，不读取背景未保存表单。inspect返回来源ID，回答额外带岗位授权凭据；撤权后历史/异步结果隐藏。写操作参数经Zod/当前业务预览校验，确认前再核对版本和previewHash，MES写入事务取得业务锁后再次复核预览哈希，防止确认与实际写入之间子BOM变化。写入走与页面相同的Service和事务。

平台原CRM专用的读工具循环改为Provider能力 `nativeReadTools`，CRM/MES均可使用；仍最多5次模型调用、单轮最多5个查询，输入估算上限24000 Token，已知累计60000 Token时停止下一次调用。没有额外自动重试。超过次数失败，不把已付费请求删掉或记为零。

当前授权对象已有完整事实和稳定行ID时直接复用，不重复查询；模型获得当前岗位范围，操作员不能扩大范围。列表只提供摘要和分页，详细BOM按对象读取，避免批量树重复进入上下文。需要多个对象时先缩小范围；服务端展开、聚合和计算数值，不让模型心算。

OpenClaw适配选择 `mes-assistant`；Runtime Manager策略4从原企业模型配置派生独立MES工具白名单；可用MES_MODEL_ID=doubao-seed-evolving独立指定经验收的Ark MES模型，保留其他应用模型，ERP/CRM各自白名单不扩大。MES业务指令随Provider受控构建，无需重复加载CRM Skill；共享会话、记忆、知识、计量、取消与权限生命周期继续适用。

## 计量和发布

所有调用进入独立AiModelUsage，appId=mes，失败/取消/未知用量不丢失。缓存输入与推理输出按供应方口径归类，不重复相加。D-057的本地替身计量为模拟回执；D-058另行执行真实Evolving题集和逐次对账，实际结果见[06](06-真实模型验收与线上发布.md)。

`MES_AI_RELEASE_ENABLED=true` 才贡献AI权限；默认关闭（包括未配置变量时），另需企业AI能力、成员岗位、可用Runtime与额度。生产例子保持false；不能仅因页面和替身测试通过就开放。上线前使用预算代理执行真实模型题集，验证中文意图、函数参数、事实准确性、BOM误报、撤权、取消和逐请求计量。

未发送问题在当前面板内存保留；刷新不承诺服务器草稿。正式会话、待确认工作单和业务草稿独立持久化，关闭面板不重跑或自动创建计划。
