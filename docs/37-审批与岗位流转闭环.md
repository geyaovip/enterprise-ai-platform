# 审批与岗位流转闭环

> 文档属性：日期实施/验证记录。保留当时版本、环境与结论；文中“当前/待完成”以该段日期为准。状态入口：[47](47-项目现状与文档维护.md)；公共UI：[ui/00](ui/00-公共UI规范.md)。

## 已确认范围

用户在 2026-10-10 确认统一优化新 ERP 审批、岗位流转与提醒，并授权本地和正式环境添加假数据。新 ERP 保持业务与账务状态的唯一写入入口。飞书/钉钉实际连接、身份配对与真实消息送达须另有租户授权及供应商回执，不能以站内通知替代验收。

## 流程与不变量

- 七种模板：采购、销售、采购变更、采购退货、销售退货、开票、收款认领。销售数量变更重新走销售审批，退回恢复原数量与履约状态。
- 审批步骤支持任一人、全部成员和按名单顺序；金额阈值使用独立高金额步骤。提交前校验全部节点接收人，排除自审；缺必需审批人时使用备用审批人，仍不可用则原子拒绝提交。
- 无新模板时兼容已配置审批名单、有效代理和其他管理员；没有其他有效审批人时拒绝提交。新模板启用后，普通页面必须先提交，不提供管理员直接确认草稿入口。旧 API 无新模板时的管理员直接确认保留专项审计并创建仓库办理节点。
- 每次提交保存模板版本、规则、人员与步骤快照。配置修改不改变在途实例；退回重提保留上一轮步骤与事件。
- 仓库及财务办理人必须有相应角色权限。仓库领取后仅该成员能办理；实际入库/出库业务事务完成节点，部分履约保留节点，不提供脱离库存账款的“完成”按钮。
- 审批/退货/库存/应收应付的修改、流转状态及通知仍在同一业务事务中。实例和单据版本均校验；并发失败不会遗留库存、账款或虚假通知。
- 超时前提醒、超时间隔提醒与升级通知使用事件键去重。Worker 扫描每批 100 个实例、按游标轮转；停用企业/应用不处理。失效审批人可转备用；无法接续则进入异常，由管理员转交。
- 临时代理到期恢复原审批人；转交记录原因及新旧接收人。提交人/管理员催办限一小时一次。
- 待办按当前实例接收人生成，已处理者不再收到相同节点待办。全部/异常仅管理员可看，其他人仅可查看自己参与、发起、抄送或升级收到的实例。源单据仍校验自身租户和业务权限。

## 页面与接口

业务设置 → 业务流程 → 分组配置弹窗（审批步骤 / 办理与通知 / 时效与异常）。工作台新增业务流转，含待我处理、我发起的、我已处理、全部与异常；详情在弹窗显示当前节点、接收人、截止时间、步骤及历次记录。

- `GET/POST /api/v1/tenants/:tenantKey/erp/workflow-config`：管理员配置与乐观锁版本。
- `GET .../workflow-preview?kind=&amount=`：发起前解析有效接收人，供提交确认显示。
- `GET .../workflows?view=todo|sent|handled|all|exception&page=&page_size=&q=`：列表。
- `GET .../workflows/by-source/:kind/:id`、`GET .../workflows/:id`：源单与实例详情，重新鉴权。
- `POST .../workflows/:id/review`：版本、同意/退回、原因、内部开票编号；调用原业务 Service。
- `POST .../workflows/:id/control`：版本、领取/催办/转交；转交需有效接收人和原因。
- 站内通知链接实例详情，并显示实时流程状态；已接入飞书的企业进入原渠道投递队列。推进、领取、转交或终止取消过时队列，发送前再次校验周期、节点和接收人。真实外部投递未在本轮开通。
