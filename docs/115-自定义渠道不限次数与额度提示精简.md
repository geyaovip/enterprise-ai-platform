# 自定义渠道不限次数与额度提示精简

2026-10-29发布更新：本页功能已随[D-120联合发布](120-本地待发布功能联合上线.md)上线；下文保留当时实施/验证记录，当前发布状态及回滚以120为准。

2026-10-29，D-115。用户明确要求企业自定义大模型渠道不限制对话次数，随后要求所有渠道都不默认展示剩余次数；默认渠道无法继续对话时，在发送后给出提示。

## 当前契约

- 以服务端当前企业是否存在显式 `AiProviderSettings` 判断自定义渠道。不能由客户端传递渠道类型或跳过额度标记。
- 企业自定义渠道不受账号累计三次试用限制，不创建或扣减 `AiChatTurn`；同一账号即使已用完平台试用，也可以在配置了自定义渠道的企业继续对话。
- 自定义渠道不因套餐月度 `ai_run` 次数用完而被拦截，执行与模型用量继续计量。订阅有效性、应用权益、岗位权限及普通后台任务额度仍按原规则执行。
- 未配置自定义渠道的企业仍使用原有默认渠道试用规则，累计三次在账号下跨企业/应用共享；失败、取消、重复发送及恢复结算逻辑保留。移除自定义配置不会清空或重置原有默认渠道次数。
- `GET .../chat-quota` 默认渠道仍返回 `{limit:3,used,remaining,period:"lifetime"}`；自定义渠道返回 `{limit:null,used:0,remaining:null,period:"unlimited"}`。不返回模型密钥。
- 三端共享对话框移除剩余次数提示、额度预查询及轮询，也不因本地额度状态提前禁用发送。默认渠道达到限制时，发送请求由服务端返回原有 `409 / AI_CHAT_LIMIT_REACHED`，对话框展示错误并恢复输入，不调用模型来生成额度提示。
- 同步消息、异步任务入队和 Worker 执行/恢复共用带可信企业上下文的额度判断。自定义渠道重复请求仍由会话版本、requestKey 和任务回执保证幂等。
- 本次覆盖 D-114 中保留自定义渠道三次限制的范围，以及 D-090 中默认展示剩余次数和本地禁发的交互。原单条字数、单会话容量及执行资源保护不属于试用次数，本次不变；不增加测试按钮或配置模式。
