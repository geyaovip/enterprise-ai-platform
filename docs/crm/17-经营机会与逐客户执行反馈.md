# 经营机会与逐客户执行反馈

2026-10-27，D-081。参考有赞的场景入口、经营数据查询及执行反馈，增强当前CRM。使用已有CRM数据与授权，不连接有赞账户，不复制优惠券、积分、余额或自动营销平台。

## 经营机会

客户总览新增经营机会。按当前岗位的组织、渠道与客户归属权限计算：高价值沉睡、首购未复购、近期活跃、新客未购买；销售显示下一行动已到期的未结束商机；客服显示未来30天内到期的有效服务计划及未关闭风险。无对应读取权限的卡片不展示。

购买场景沿用T-01～T-04分群规则、有效订单和退款净额口径。高价值门槛为所选币种1000，默认CNY，可切换USD/EUR/HKD；不换算汇率，不跨币种相加。卡片人数按当前时点计算，点击后重新预览，保存15分钟有效的不可变快照；零人数不能使用方案，指标未就绪不能进入可执行确认。

每个购买场景提供可编辑目标、沟通参考、执行清单，进入运营草稿后由用户选择负责人、修改期限和方案。场景建议期限为3天后。草稿沿用提交、负责人确认、冻结目标、开始人工运营流程。读经营机会不会创建人群预览或业务任务。

## 逐客户反馈

新增任务表字段trackCustomers，数据库默认false以兼容已有任务；新建页面及场景方案默认选中“完成前逐客户记录处理结果”，草稿阶段可修改。

目标名单来自任务确认时冻结的CrmSegmentEvaluation。查看名单返回当前客户权限交集、分页及待处理/已记录/待跟进人数；受限任务不暴露方案和不可见客户。记录结果需要crm.task.execute、任务进行中、负责人或经理资格、全名单可执行范围，且客户确属冻结名单。

结果类型：已联系、未联系上、有意向、暂不需要、待跟进、跳过。每次须填写摘要，待跟进须设置未来的下次时间；其他结果不能保留跟进时间。下一时间为本任务客户反馈中的安排，不自动创建销售跟进待办或对外通知。

每个客户结果采用递增outcomeVersion；写入使用任务锁、请求幂等和租户内客户复合外键。并发旧版本拒绝；网络重试复用原requestKey与参数。更新追加更正日志并关联原记录，保留原文。通用日志更正不能覆盖逐客户状态，须从客户行更新。

启用trackCustomers的任务，全部目标客户至少有一次有效处理结果后才能完成；跳过需要摘要，待跟进表示本轮已处理但还有后续安排。旧任务完成规则保持兼容。完成/取消后逐客户结果只读，仍可追加通用备注。客户详情不会混入其他客户的专属日志。

人工结果与订单观察分别展示；“有意向”不表示成交，“已联系”不提供外部消息送达证据，购买变化不作因果归因。

## 接口

- GET /growth?currency=CNY：规则机会和角色信号，不保存人群。
- GET /tasks/:id/customers?page=1&page_size=20&status=pending：冻结目标当前可见交集与最新处理结果。
- POST /tasks/:id/customers/:customerId/outcomes：version、outcome、summary、occurredAt、nextAt、requestKey。
- GET /opportunities?overdue=true：行动已到期的未结束商机。
- GET /service-plans?endingWithinDays=30：未来指定天数内结束的有效计划。
- GET /service-risks?status=open：未关闭风险。
