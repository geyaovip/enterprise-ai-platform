## 产品目标

帮助电商品牌的客户运营人员基于可核验的购买记录识别目标客户、制定运营任务、跟踪执行并复盘结果。首版闭环为：导入 → 核对客户和订单 → 计算指标 → 预览并保存分群 → 制定任务 → 人工确认 → 执行记录 → 观察购买变化。

新 CRM 可在没有 ERP 的租户中运行。消费者和渠道身份归 CRM；分析用交易投影保留来源，不承担库存、付款或履约主记录。第一批数据来源与订单口径在 Q-CRM-01/02 关闭后定稿。

## 岗位与日常操作

企业管理员管理应用、成员授权和数据政策；CRM 负责人制定/确认任务；客户运营筛选客户、起草任务并执行记录；数据分析人员管理导入、口径及分析；只读人员查看授权的结果和审计。具体权限以 [06](06-权限与数据安全.md) 为准，不借用 ERP 销售、采购等角色含义。

## 三条主要流程

1. 数据人员先完成客户批次，再在同一交易批次上传订单和完整明细（或对应 XLSX 两个工作表）；系统校验关联并按整单预览；用户确认后后台提交完整组，展示已提交/失败数量及指标重算状态。单独上传明细仅为暂存，不能先行写入业务表。
2. 运营人员建立“历史净消费达到阈值且距最近有效购买超过 90 天”的规则，预览有权人数和样本；保存分群，生成运营任务草稿，核对规则、数据版本、人群和负责人后确认；执行人员登记实际操作与结果。
3. 运营人员从客户详情或分群进入 AI；CRM Service 返回有权指标，AI 解释并提出方案；用户核对后确认持久化任务；回执可打开任务详情。无模型、无知识或 AI 失败时，上述手动流程仍可完成。

## 业务状态

| 对象 | 状态与允许操作 |
| --- | --- |
| 客户 | `active/archived`；归档保留订单和历史引用，默认列表不含归档客户 |
| 分群 | `active/archived`；规则编辑增加版本，已有计算结果及任务引用保留；归档不取消已确认任务 |
| 运营任务 | `draft → pending_confirmation → ready → in_progress → completed`；草稿撤回可编辑，确认前拒绝回 draft 并留原因；draft/pending_confirmation/ready/in_progress 可按权限取消 |
| 已确认任务 | 人群、规则和指标依据冻结；新增客户或修改分群不自动加入；扩展人群须另建任务或重新确认新版本 |
| 完成/取消任务 | 终态不随意回退；记录可追加纠正说明，保留原记录；取消不删除已发生操作 |

任务 draft 可保存未填写完整的负责人、期限和方案；提交确认时必须齐备。pending_confirmation 的业务内容只读，修改须撤回 draft；确认绑定当前方案版本。ready/in_progress 的负责人或期限变更需 manager 复核、校验新负责人全部目标权限并留审计；方案、目标和观察口径保持冻结，要调整则取消剩余执行并另建关联任务。逾期按截止时间计算。完成任务需填写执行摘要，不能把任务完成写成客户复购成功。字段约束见 07，冻结依据见 04。

## 产品限制与成功判定

首版的执行记录由员工填报，不证明外部消息已送达。效果展示为目标人群在明确窗口内的观察结果，未做实验时不声称因果增量或“AI 提升了复购”。报表和 AI 的数字必须回溯到授权的订单和计算参数。

工程成功为：CRM-only 成员可完成整条流程、跨租户/数据范围不泄露、重复导入与重试不重复写入、失败可恢复、数据和状态持久化。业务效果和客户接受度以真实试点另验收，见 [10](10-验收与上线.md)。
