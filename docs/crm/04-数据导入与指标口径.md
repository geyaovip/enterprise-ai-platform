# 电商 CRM 数据导入与指标口径

> 文档属性：CRM V1契约；2026-10-22已实施，工程/发布及未验收项见[15](15-V1实施与验收记录.md)。公共UI见[ui/00](../ui/00-公共UI规范.md)，应用界面差异见[05](05-UI与交互规范.md)，当前状态见[平台47](../47-项目现状与文档维护.md)。

更新：2026-10-20。以下为建议口径 P-004/P-008；Q-CRM-01/02 关闭后才能作为真实客户验收基线。固定计算例子见 [11](11-样例数据与期望结果.md)。

## 首版模板

CSV 使用 UTF-8，可有 BOM；XLSX 使用有表头的普通工作表，不执行公式/宏，不接受加密工作簿。数字/日期解析在服务端完成；超限文件先拒绝再解析。文件大小、行数和同时批次上限通过真实样本定量确认，不沿用 ERP 的 500 行限制作为电商容量承诺。

| 模板 | 必填 | 可选/条件必填 |
| --- | --- | --- |
| 客户 | external_customer_id、display_name | source_created_at、source_updated_at、source_revision；电话/邮箱按用途授权；org_unit 使用已授权稳定映射 |
| 订单 | external_order_id、external_customer_id、status、currency、paid_amount、refund_amount、source_updated_at、expected_item_count | paid/completed/refunded 须 paid_at；source_revision；订单与明细金额不等时声明 unallocated_paid_amount/unallocated_refund_amount 及原因 |
| 订单明细 | external_order_id、external_sku_id、quantity、paid_amount、refund_amount | 稳定external_line_id在来源有此字段时必填；name；无行ID须声明整单替换 |

channelId 在创建批次时选择，不由每行任意指定 tenantId。外部 ID 一律按字符串保留前导零；不得根据显示名推导 ID。金额为十进制字符串、统一币种小数精度；paid_amount≥0、0≤refund_amount≤paid_amount，quantity>0。来源时间带时区，纯日期/无时区格式须使用映射里明确的来源时区。

电话/邮箱不是必填客户识别键。来源客户创建时间未知时保留 null；导入时间不冒充客户注册/首购时间，新客指标单独报告时间未知数量。

### 跨文件批次与完整性

首版只有 `customer` 和 `trade` 两种可提交批次。customer 使用客户文件；trade 同时关联订单文件与明细文件，或同一 XLSX 的 orders/items 工作表。界面分别下载三份模板；“上传明细”属于交易批次的一步，不生成可独立提交的明细批次。

1. 先导客户并确认已提交；trade 预览只引用已存在且有权的渠道客户身份。客户批次未完成时显示依赖和返回入口，不能靠上传文件名猜关联。
2. 按 `(channelId, externalOrderId)` 组装订单行及明细；所有明细必须关联本批次订单行。退款重导也携带订单当前完整明细，首版不接受仅金额增量或仅一条变化明细。
3. `expected_item_count` 为来源声明的完整行数且至少为 1；有稳定行 ID 时不得重复/缺失，计数相等才可确认。无稳定行 ID 的来源必须明确整单替换并声明完整行数，内部lineKey使用新UUID，整组替换不做跨版本行匹配；原始行号只定位错误，不作为长期来源键。
4. 按币种最小单位精确对账：订单支付/退款 = 明细对应合计 + 显式未分摊支付/退款。未分摊部分用于来源的运费/税费/订单级调整，须有字段映射和原因；未声明时两者默认为零并要求合计相等。允许的符号/精度由 Q-CRM-02 来源映射定稿，禁止静默容差或自动填差额。
5. 文件或工作表替换会增加 batch.version、重算 fileSetHash、作废旧 previewHash。订单头及完整明细同一事务更新；来源版本相同但组内容不同仍属冲突，缺失内容不能借“补明细”绕过版本规则。

明细不完整的输入保留在暂存并定位错误，不写不完整交易；订单金额始终是购买指标权威值。只有订单汇总的来源须先补充可核对的明细/映射或另行评审汇总导入模式，首版不自动生成虚构商品行。

### 数量与批次结果

`rowCounts` 按文件角色分别显示解析总行、有效/错误行、已提交/未提交行；`objectCounts` 按客户或订单组显示 created/updated/unchanged/stale/conflict/failed/cancelled/pending。每个有效业务组最终只有一个结果，重试累计显示同组最终状态及尝试次数，不把同组重复计数。已提交订单数不等于明细行数。

预览与实际结果并列；实际 `组总数 = created + updated + unchanged + stale + conflict + failed + cancelled + pending`。导入结束与指标 `queued/running/ready/failed` 分开；重算失败可单独重试，禁止重复应用已提交交易。校验错误阻止整个批次确认；应用期并发冲突可形成部分提交。

## 预览、更新与失败恢复

状态为 `draft → uploaded → validating → awaiting_confirmation → queued → applying → completed`；创建空批次为draft，所需文件到齐才为uploaded；校验有错误进入 `validation_failed`，须修正后重新预览；应用阶段可 `partially_applied/failed`；尚未提交部分允许取消，已提交组不随取消消失。替换文件/映射退回draft或uploaded并作废校验结果，按所需文件是否齐备判断。

预览必须返回新建、更新、无变化、版本冲突和错误数量，以及前若干条脱敏样本。提交使用 batchId、batch.version、previewHash、requestKey；文件或映射变化须生成新预览。错误行阻止确认；不得绕过预览直接入库。

- 客户唯一键：tenant+channel+externalCustomerId。订单唯一键：tenant+channel+externalOrderId。同一来源可用不同店铺作为不同 channel，不只用“淘宝”等平台名做唯一键。
- 来源 source_updated_at/revision 较新才允许更新；较旧记录标为 stale，不覆盖；同版本不同内容标冲突。没有可靠更新时间/版本的来源只允许首次导入或人工确认修正，不根据上传顺序自动覆盖。
- refund_amount 是截至来源版本的累计退款快照，重导替换该版本的累计值，不再次累加；paid_amount 同样为订单支付快照。
- 订单明细只能用稳定行 ID 更新；如果来源没有行 ID，预览时声明“完整整单明细”，在整单事务内替换明细集合。不能使用文件行号作为长期 ID，不能把部分明细当整单替换。
- 缺关联客户时返回错误并提供先导客户路径，不根据姓名自动造客户。关联查询不返回其他租户存在与否。
- 后台恢复重查成员、CRM 启用、导入权限和渠道范围。撤权后停止未提交组；已提交组保留结果与计数，恢复须由有权人员发起。
- 部分应用清楚列出已提交/未提交/失败组。重试沿原 requestKey 与内容哈希，补偿按 03 的版本保护进行；既有引用冲突交人工处理。

原件、暂存和错误报告均绑定租户与批次权限，下载重新鉴权。导出文本防公式注入；日志不保存完整行、联系方式或文件原文。

## 时间、有效订单和金额

建议默认租户时区 Asia/Shanghai；模型保留来源事件时间，计算使用 tenant timezone。范围采用 `[windowStart, windowEnd)`，计算时点为 asOf；所有结果记录 policyVersion、dataRevision、时区和币种。

V1 的 ad hoc 查询由服务器确定当前 asOf；过去的观察时点只读已保存 snapshot，不声称可从最新累计退款快照重建任意历史时点。重算历史购买窗口采用当前已知数据并生成新 asOf；精确历史退款时点还原需真实退款事件或完整来源修订历史，后置单独设计。

有效购买订单：来源规范化状态为 paid 或 completed，paidAt<asOf，且截至 asOf 的 `netAmount = paidAmount - refundAmount > 0`。cancelled/unpaid 不计购买；全额退款 net=0 的订单不计 F、M、最近有效购买或首购。部分退款保留一次购买，M 使用净额。未付款订单不能只因金额大于零进入购买指标。

规范化状态白名单为 unpaid/paid/completed/cancelled/refunded；来源“部分退款”保留其已支付/已完成基础状态并带累计退款额，全部退款映射 refunded。其他来源状态必须在映射中定含义，不能未知状态自动计购买。

建议 paidAmount 为支付实付总额（已扣优惠、包含来源计入的运费/税费），退款按同口径累计；来源不一致时不能静默混算。订单与明细按上节的显式差额规则对账，缺明细先修复暂存。不同币种分别统计，不做未经确认的汇率换算。

指标是“该购买窗口、截至 asOf 的净购买观察”，退款重导可能修正历史窗口。它不等于退款实际发生期的财务现金流；若需后者须引入真实退款事件时间并另定口径。界面显示数据截至时间和后续修正状态。

## 指标定义

| 指标 | 确定性定义 |
| --- | --- |
| R：距最近有效购买天数 | 从全部历史有效购买中取最近 paidAt，按租户本地自然日与 asOf 日的日期差；无有效购买为 null，不能显示 0 天 |
| F：窗口订单数 | paidAt 落在窗口且截至 asOf 有效的订单数；按订单 ID 计，明细数不作订单数 |
| M：窗口净消费 | 上述订单净额之和，按币种计算 |
| 历史累计净消费/订单数 | 全部历史截至 asOf 的有效订单合计/数量；不受当前报表窗口限制 |
| 首购/最近购买 | 截至 asOf 的最早/最晚有效订单 paidAt；全额退款可能使结果回退或为空 |
| 窗口购买客户 | 窗口 F≥1 的不同客户 |
| 窗口复购客户 | 窗口 F≥2 的不同客户；同时展示人数和比例 |
| 窗口复购率 | 窗口复购客户数 / 窗口购买客户数；分母为 0 显示“无购买样本” |
| 历史二次购买客户 | 历史有效订单数≥2；与窗口复购明确分开 |
| 新客 | sourceCreatedAt 在窗口的客户；来源时间未知单列，不能以 importedAt 代替 |
| RFM 分布 | V1 展示 R/F/M 原值及固定可解释区间；区间参数留版本，不默认声称完成预测评分 |

模型和前端不自行算权威金额。批次完成后重算指标；最新成功快照可以展示但标 asOf/revision，“待更新”不能隐去。客户列表、看板、分群、AI 必须使用一致策略和可见范围。

## 分群规则

V1 为扁平 `all/any` 条件组，最多 20 条、无任意嵌套、无脚本/SQL。完整字段/操作符和空值语义按 07 的白名单；新增 `lifetimeOrderCount` 与 `customerAgeDays` 支持首购和新客模板，不能把窗口 F=1 当作历史仅买一次。R/F/天数为非负整数，金额为十进制字符串。

预览返回有权 memberCount、脱敏样本、规范化 rule/hash、policyVersion、dataRevision、scopeFingerprint 与 asOf；数据范围不允许直接传任意用户/租户。保存保留规则版本，重新计算产生新 evaluation；保存规则不等于人群固定。

确认运营任务时冻结 evaluation 和成员集合。相关数据、规则或权限改变时按下节失效规则重新预览。撤权后历史冻结结果按当前权限读取；不能泄露全量 memberCount。

### 四类常用模板（U-01）

模板为代码随版本发布的规则配方；采用后保存展开的完整规则及 templateId/version，不引入可执行脚本或新的模板引擎。以下默认阈值为可编辑设计值，金额示例使用 CNY；其他币种必须手工设阈值。模板人数只有实际预览后才展示。

| ID/版本 | 名称 | match=all 的默认条件（另带 status=active） | 边界 |
| --- | --- | --- | --- |
| T-01/v1 | 高价值沉睡 | lifetimeNetAmount≥1000.00；recencyDays>90 | 高价值是规则阈值；R=null 不匹配 |
| T-02/v1 | 首购未复购 | lifetimeOrderCount=1；recencyDays≥7；recencyDays≤30 | 全退款为 0 单；历史两单但窗口一单不匹配 |
| T-03/v1 | 近期活跃 | recencyDays≤30 | 指购买活跃，不暗指访问/互动活跃 |
| T-04/v1 | 新客未购买 | customerAgeDays≤30；lifetimeOrderCount=0 | customerAgeDays 为来源创建日至 asOf 本地日差；时间未知为 null，不匹配 |

历史订单数和金额按当前有权渠道及币种计算；客户创建日按有权身份的来源资料，不以本次导入日替代。所有模板可在权限内编辑并重新预览；未提供创建时间的来源明确解释 T-04 的未知样本，不显示虚假人数。

客户列表经营条件转换为同一 ruleJson；保存使用已应用条件和成功预览。q 名称搜索仅用于查找，不能保存为分群条件；有 q 时提示先清除搜索再预览，避免保存后人数扩大。排序/页码不进规则；模板与手工规则共用校验、计算和授权。

### 预览有效期与并发确认

预览默认有效 15 分钟（设计值），绑定 normalizedRule、窗口/币种、策略版本、当前授权指纹和 `dependencyVersions`。依赖向量包含规则实际可见的渠道 sourceRevision/customerRuleRevision 及已激活指标 generation；租户全局 dataRevision 只用于追溯，不单独作废无关渠道的预览。跨本地日期变化也必须重预览，避免 R/客龄变化。

受影响渠道正在应用交易或指标未追上其 sourceRevision 时，允许查看带截至时间的旧结果，但新预览标为不可用于任务确认。相关批次完成/部分提交结束后合并重算并原子激活；界面可订阅状态，用户无需反复点击刷新。不能用静默移除新增匹配客户维持旧人数。

| 变化 | 处理 |
| --- | --- |
| 超时、跨日、规则/窗口/币种/策略改变 | 旧预览失效，明确原因并重新预览 |
| 本次范围内的订单/退款、客户归属/状态/标签改变 | source/customerRule 版本变化，等待重算后重新预览 |
| 无关且不可见渠道发生导入 | 保留预览；仍重新检查成员及对象权限 |
| 岗位/范围/负责人权限变化 | 禁止沿用旧确认；重新鉴权与计算，不静默缩减目标 |
| 任务已经确认，新数据到达 | 原目标不变；观察指标显示新计算时点和策略 |

任务确认事务与导入组提交对相关 CrmScopeRevision 行采用同一锁/版本协议（稳定渠道顺序），再比较依赖、权限、方案版本并冻结引用；竞争失败返回可恢复的 409。评价创建读取一致数据库快照；不能分开读人数与成员列表造成漂移。15 分钟有效期不豁免提交时检查。

## 效果观察

任务确认保存目标客户集合、基准窗口、观察窗口、指标策略/版本和人数。任务实际执行时间取执行记录，过早/缺失记录标明未观察。默认展示目标人群的购买客户数、有效订单/净额与复购变化；客户重叠可存在，不把各任务收入直接相加。

建议以起草任务时有效evaluation.asOf为初始窗口锚点：基准 `[asOf-30d, asOf)`，观察 `[asOf, asOf+30d)`，按租户日历日生成并保存明确ISO时间；确认前可编辑，必须起止有序、不重叠且明确币种/时区。确认冻结这些具体时间，不自动改为新的confirmedAt或挪动窗口；重新预览人群也不覆盖已编辑窗口，必要时由用户复核调整。观察未结束显示“观察中/已观察至”，没有执行记录显示“尚无执行记录”，不归为0效果。实际执行晚于窗口起点仍展示既定窗口和执行时间。基准与观察均对冻结目标计算；退款修正沿用本页。

人工填报触达数、回复数、送达等字段标“人工记录”，订单回流指标标数据来源。没有可靠触达回执或实验组时，只称“观察结果/执行后变化”，不输出因果提升、实际送达率或渠道归因收入。
