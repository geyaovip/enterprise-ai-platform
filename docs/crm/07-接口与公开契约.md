# 电商 CRM 接口与公开契约

> 文档属性：CRM V1契约；2026-10-22已实施，工程/发布及未验收项见[15](15-V1实施与验收记录.md)。公共UI见[ui/00](../ui/00-公共UI规范.md)，应用界面差异见[05](05-UI与交互规范.md)，当前状态见[平台47](../47-项目现状与文档维护.md)。

更新：2026-10-22。接口已按V1实现核对；沿用 [平台接口规范](../05-路由与接口契约.md)。

## 共同规则

业务前缀为 `/api/v1/tenants/:tenantKey/crm`，Controller 经 AuthService.context(req, tenantKey, 'crm') 构造可信上下文。普通业务body不接受tenantId、操作者userId/role或任意查询授权范围；授权管理接口只接受06定义的目标member、岗位、scopeBindings和额外权限字段，经settings.manage独立校验，不改变操作者上下文。Service再检查动作、对象、状态与当前版本。

列表 `{items,total,page,page_size}`，建议 page_size 默认 20/最大 100，排序字段白名单并带稳定 ID；total 为有权范围内计数。金额用十进制字符串，时间用带时区 ISO 8601。日期范围、币种、metricPolicyVersion/dataRevision/asOf 在指标输出中明确。

可编辑对象命令传 version；写入传 requestKey（UUID），同租户/命令/操作者和相同指纹重复返回原回执，不同参数复用同键返回 409。来源版本规则另按 04 校验。失败采用现有 `{error:{code,message,request_id}}`，不回显原始异常。

## 关键输入输出示意

分群规则草稿（示意，schema 由 CRM 定义并校验）：

```json
{
  "match": "all",
  "conditions": [
    {"field": "recencyDays", "op": "gt", "value": 90},
    {"field": "lifetimeNetAmount", "op": "gte", "value": "1000.00"}
  ],
  "currency": "CNY"
}
```

预览返回 `memberCount/sample/normalizedRule/ruleHash/previewHash/evaluationId/asOf/expiresAt/policyVersion/dataRevision/dependencyVersions/metricGenerationId/scopeFingerprint/usableForTask/invalidReason`。ruleHash 只覆盖规范化规则，previewHash 绑定规则、参数、评价结果、依赖和权限版本。用户保存/建任务时携带 evaluationId/previewHash，服务端按 04 重新核对；客户端 hash 不替代授权。pending 计算返回 evaluationId/status，不能填 memberCount=0 伪装完成。

### 规则 schema 与列表转换

请求中的 rule 只接受一个 match=all/any 组、1～20 条条件，以及 currency/windowStart/windowEnd；拒绝额外键。默认 status=active 也作为显式条件保存。asOf 由服务器生成，不由模型任意回填。条件按下表严格校验，不进行字符串到数字的宽松转换：

| 字段 | 类型 | 操作符 | 空值/范围 |
| --- | --- | --- | --- |
| channelId | 有权渠道 UUID | eq/in | in 为非空去重集合；每个值须有权 |
| tag | 本租户标签 UUID | eq/in | eq 为有该标签，in 为至少有一个；对象须可见 |
| status | active/archived | eq/in | 显式值，不默认为全部 |
| recencyDays、customerAgeDays | 非负整数或 null | eq/gt/gte/lt/lte/between/is_null | null 不命中数值比较；is_null 的 value 为 boolean |
| frequency、lifetimeOrderCount | 非负整数 | eq/gt/gte/lt/lte/between | 无有效订单为 0 |
| monetary、lifetimeNetAmount | 非负十进制字符串 | eq/gt/gte/lt/lte/between | 必须指定币种；精度按该币种策略 |
| lastPurchaseAt、sourceCreatedAt | 带时区 ISO 时间或 null | gt/gte/lt/lte/between/is_null | between 为 [start,end)，其余比较取精确时点 |

数值 between 使用有序 `[min,max]` 且包含两端；时间 between 使用 `[start,end)`。不允许空条件组、未知字段、脚本/嵌套逻辑/SQL。recencyDays 从有权历史有效购买计算，customerAgeDays 从来源创建日本地日差计算；未来创建时间为来源错误。GET /customers 的编码格式为 URL 编码 JSON rule，受请求长度上限限制；前端/服务端共用 schema，不能另开未校验的查询表达式。q 为普通名称/外部 ID 查找，不能保存为规则；敏感信息不放 URL。

列表过滤、预览、模板展开、AI 规则校验调用同一规则服务。保存筛选仍使用 POST /segments，不新增“保存筛选”实体。保存返回完整 rule、ruleHash、templateId/version 与可打开的分群 ID；页码和排序不进入 rule。

### 任务草稿与方案字段

POST/PATCH /tasks 接受 title（1～100 字）、goal（至多 1000 字）、planText（至多 10000 字）、checklist（至多 30 项，每项含唯一stableId和text≤500 字）、hypotheses（至多10项、每项≤500字）、ownerMembershipId、dueAt、evaluationId/previewHash、baselineStart/End、observationStart/End、currency、version/requestKey。草稿至少 title 非空，其余可空；提交确认须目标及方案非空、至少一项执行清单、负责人有效、期限在未来，两个窗口均合法且不重叠。AI 与人工使用同一约束，期限为确认前的未来时间。

origin、aiInvocationId、skillVersion、factReferences 由受控服务从调用事实生成；普通客户端不能伪造 AI 审计来源。AI 建议被人工修改后创建新方案版本，保留原始来源及人工编辑人；输出 currentPlanVersion/confirmedPlanVersion、方案全文/清单和可见依据。保存不变内容不生成新版本。

submit 绑定当前方案版本，confirm 输入 version/planVersion/evaluationId/previewHash 并重新验证；目标人数为0允许保存草稿/规则，禁止提交可执行任务。待确认超过预览有效期时，复核人在任务内通过target-preview对已保存ruleHash/窗口/币种重新预览；新结果可在确认事务绑定，界面必须展示新人数/样本/截至时间和变化摘要供其明确确认，不静默使用旧人群或修改方案。若要改规则或方案则撤回draft。ready/in_progress 的assign/reschedule仅manager执行（crm.task.confirm），校验新负责人完整目标权限；confirmed方案/目标/窗口不能普通PATCH，调整按01另建关联任务。withdraw仅创建者或manager在pending_confirmation执行，返回draft并留原因。

任务日志 type 采用 execution/note/correction，correctsLogId 只能关联同任务可读日志；所有客户端记录都标人工输入。results 返回冻结目标的有权统计、baseline/observation、observedThrough、executionRecorded、currency/policy/asOf，不接受客户端伪造净消费结果。

| action | 允许状态 | 所需资格/结果 |
| --- | --- | --- |
| submit | draft | task.write；创建者或manager，字段齐备/人群非零；进入pending_confirmation |
| withdraw | pending_confirmation | task.write；创建者或manager，原因必填；回draft |
| confirm/reject | pending_confirmation | task.confirm；manager复核方案/目标/负责人；进入ready或带原因回draft |
| start/complete | ready/in_progress | task.execute；当前负责人或manager；start进入in_progress，complete仅从in_progress且需摘要 |
| assign/reschedule | ready/in_progress | task.confirm；manager；分别传新ownerMembershipId/dueAt及reason，期限须未来；不改目标/方案/状态 |
| cancel | draft/pending_confirmation/ready/in_progress | draft/pending由创建者且task.write或manager；ready/in_progress需manager且task.confirm；原因必填，取消不撤销已记执行 |

日志 execution/correction 需 task.execute 且为负责人或manager，允许in_progress追加执行、completed/cancelled追加有原因的纠正，不能改写终态；note仅在有同样对象范围且具task.write/execute的非只读成员追加。所有动作仍需全目标权限；列表看见部分可见摘要不等于获得执行资格。

写入回执包含 `id/status/version/repeated/request_id` 和实际已提交结果；异步入队返回 `jobId/batchId/status=queued`，不返回“已导入”。指标更新有独立状态。结果不明返回可查询的 requestKey，不鼓励用户换键重复写入。

## 公开命令和对象 Reader

为真实的后台执行/AI/协作注册最小命令，不把每个 CRUD 都塞入通用命令目录。建议 `crm.import.apply_batch`、`crm.metrics.recalculate`、`crm.segment.evaluate`、`crm.task.create_draft`、`crm.task.confirm` 和 `crm.import.compensate`；各命令声明 schema、所需权限、确认要求、preview 和事务内 execute。

公开 execute(tx,ctx,input) 接受已有事务，内部共享 CRM 规则，不能再开独立提交导致业务与平台回执不同步。批量操作以短事务组/步骤推进，不把完整大文件塞入单个命令 input 或长事务。

Reader 支持 customer、segment、operation_task、import_batch，读取当前租户和数据范围，返回最小可见摘要。平台对象链接和通知通过 Reader 二次核对权限。CRM 第一版没有真实 ERP 消费者时不预建双向同步接口。

通用 AI API 复用 `/api/v1/tenants/:tenantKey/apps/crm/ai`；企业入口和 CRM 页面都调用它，不能继续默认 `/ai` 路径而落到 ERP。会话、SSE、确认、恢复和回执沿现有契约，不增加 CRM 专属 AI Gateway。

## 错误与并发

401 登录失效；403 应用/动作/范围拒绝；404 资源不可见；400 字段/规则/来源错误；409 版本变化、预览过期、幂等参数冲突或状态不允许；429 配额/限流；503 运行或数据服务不可用。409 细分 PREVIEW_EXPIRED/DEPENDENCY_CHANGED/METRICS_PENDING/PLAN_VERSION_CONFLICT/SOURCE_VERSION_CONFLICT/IDEMPOTENCY_CONFLICT，输入错误含 fieldErrors 的 path/code/message，仍使用平台错误 envelope；客户端不能解析中文文案判断状态。错误文案指出重新预览、修正字段、查结果或联系管理员的具体路径。

必测：双击确认、相同 requestKey 参数变化、并发退款更新、确认前权限变化、整单明细事务失败、业务已提交后连接中断和再次查询回执，见 [10](10-验收与上线.md)。

## V1补充接口与版本说明

- `GET /metadata`：当前CRM权限、字段目录、成员/组织、策略及AI可用提示；客户端不自行扩大权限。
- `GET /imports/:id/files/:fileId`：返回认证下载的base64原件；所有原件都需独立contact.read及批次配对范围，过期拒绝，并记审计。
- `GET/PUT /ai/draft`：`{version,content,conversationId,requestKey}`，600字符、加密、30天、用户/企业/应用隔离；冲突409，恢复重新鉴权。
- AI会话、任务、SSE、操作详情/确认/取消与记忆沿平台现有`/apps/crm/ai`路由，不另造执行协议。
- 所有当前HTTP路由以`apps/api/src/modules/crm/crm.controller.ts`和平台AI控制器为完整清单；POST默认201，PUT/PATCH/GET为200。
- 未显式提交status条件时只匹配正常客户；日期区间为左闭右开；前台金额为十进制字符串；更新不修改未提交字段。
- 预览依赖覆盖操作者所有可见渠道，隐藏渠道变化不作废；可见但不相关渠道变化可能保守作废。不要宣称已实现更细的最小依赖优化。
