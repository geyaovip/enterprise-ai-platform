## 接入标识与代码位置

建议 `appId: crm`、`displayName: 电商 CRM`、`routePrefix: /crm`、`defaultAgentId: crm.assistant`。现有 appId 正则不支持点号，不能照用原 PRD 的 `industry.ecommerce.crm` 示例。行业含义保留在文档和产品名称。

建议沿当前目录组织：

```text
apps/api/src/modules/crm/
  crm.controller.ts          # HTTP 入口与可信上下文
  crm-permissions.ts         # 应用内角色、动作贡献
  customer.service.ts        # 客户、身份、标签、对象授权
  import.service.ts          # 暂存、预览、确认、幂等、恢复
  metrics.service.ts         # 指标、数据版本、重算
  segment.service.ts         # 类型化规则与结果快照
  operation-task.service.ts  # CRM 业务任务状态与执行记录
  public-contract.ts         # 命令和对象 Reader
  crm-ai.provider.ts         # 应用事实/Tool 适配
apps/web/src/pages/crm/      # 路由页与 CRM 专用组件
apps/api/prisma/             # 同一 schema 和迁移目录
docs/crm/                    # 本组规格和证据入口
```

以上是实现建议，不要求为每个实体生成多层类，也不增加第四套前端、独立账号、独立数据库或行业插件运行时。三个现有前端分别承载业务使用、企业授权和运营交付。

## 数据和责任归属

平台拥有身份、组织、租户、应用交付、技术任务/回执、AI 会话/动作/用量、知识、套餐和审计基础。CRM 拥有消费者身份、交易分析投影、导入与指标事实、分群、目标人群及运营任务。

CRM `OperationTask` 是“召回哪些客户、谁负责、实际做了什么”的业务记录；平台 `BusinessTask` 是执行命令、等待、重试和恢复的技术过程。前者不能被后者的 completed 自动替代。手动执行不需要为了显示状态另造 AI 技术任务。

客户订单文件不默认进知识库；其原件作为受限导入资料保存。模型读取经 CRM 有权统计接口；品牌 SOP 才经知识 ACL 检索。知识不可用不阻止计算和手动经营。

## 与 ERP 的协作边界

V1 默认从授权文件导入，不依赖 ERP 启用。ERP Customer/销售合同与 CRM 消费者/电商订单保留独立 ID；不自动迁移旧 B2B CRM 数据，不把 ERP 合同直接当电商订单。

真正需要 ERP 联动时，先关闭 Q-CRM-06 和相关 Q-003：定义稳定映射、字段 Owner、订单/退款含义、授权、更新版本和失效行为。经 ERP 公开 Reader/命令/事件合作，不能读 ERP 私有表。现有 ERP 公开契约没有完整电商订单投影接口，需按实际消费者扩展并重新验收。

## 最小平台改动

优先复用应用目录返回的权限和启停状态；前端注册契约如需标题/导航/上下文，由 CRM 真实页面驱动小范围扩展。AI 公共聊天支持 appId 与资源描述，CRM/ERP 会话、缓存和回执链接分别验证。新增 Worker 处理器、通知贡献和受管 Agent 配置均沿现有组合根，不另建调度体系。

平台文档中的旧 B2B CRM 例子及“CRM 暂不引入”是历史阶段口径；本次 D-039 进入电商 CRM 文档准备，C-010已授权并接入CRM，正式目录包括ERP与CRM，实际发布和AI闸门见15。
