## 执行与入口

企业AI选择CRM与应用内`/crm/ai`使用同一`crm.assistant`，由可信AppContext选择CrmAiProvider；对话框UI/交互完整参考Demo，见 [14](14-AI对话框与工作单.md)。常驻入口打开默认新对话，历史经标题菜单显式恢复；客户/分群/任务的明确对象分析入口带可见可移除的已保存ID/版本，普通打开不自动引用背景。会话历史按企业/成员/应用隔离，切应用清除旧显示，不把ERP内容当CRM事实。

聊天输入草稿和可恢复工作单使用既有平台会话持久化；关闭/新建先保留，保留失败不声称成功。工作单草稿不等于CrmOperationTask记录，不能因自动保存会话触发业务写工具。UI复用不重建Runtime或另存一套浏览器会话数据库；所需工作单状态在现有会话/动作契约内最小扩展并校验权限。

OpenClaw 负责既有 Agent 执行及原生 Skill 加载；平台继续负责成员环境、会话、权限、确认、审计、配额和业务回执。当前成员 Gateway 的受管/手动配置、快速/只读 Agent 和实际工具映射都必须验证 CRM 路径；公共助手 ID 与 Gateway alias 可以有受控映射，不能仅更改页面文字。

## 首批用例

| Skill 建议名 | 人工步骤与价值 | 事实与输出 | 人工失败路径 |
| --- | --- | --- | --- |
| customer-insight | 汇总客户或分群购买变化、找出需关注的规则特征 | 有权指标/购买记录→带窗口、策略、来源的说明；无数据明确说明 | 客户详情和分析页直接查看 |
| segment-advisor | 把“高价值且 90 天未购买”整理成条件并核对人数 | 类型化规则草稿→服务校验和预览；不执行模型 SQL | 规则表单编辑、手动预览 |
| retention-plan | 把目标人群及品牌 SOP 整理为可执行运营计划 | 分群/指标及可选知识→目标、假设、执行清单、负责人/期限草稿 | 手动填写任务表单 |

原生 SKILL.md 至少定义适用场景、需要的字段、允许工具、缺数据处理、数据口径及输出约束。随可信应用构建维护版本；在已固定 OpenClaw 版本上验证加载、启用/停用和升级，不创建私有 Skill DSL，也不以已有提示词常量宣称原生 Skill 已运行。

本轮按问题与对象上下文选择并预加载所需Skill，已加载名称不再提供给模型重复加载。工具定义按有权场景收窄；模型侧规则schema提供精简类型提示，执行仍使用完整类型与业务校验，参数错误返回字段信息供有限轮次修正。同轮相同事实复用必须检查权限/组织/渠道/版本/日期；预览创建与业务写入不纳入复用。预览状态引用工具`usableForTask/invalidReason`，以`asOf`为计算时点，操作前仍由服务端重新核对。

## 最小 Tool 清单

工具输入 schema 由 CRM 提供；tenant/member/scope 由服务端注入，模型不得传入或覆盖。查询输出最小化，不把全量客户名单和联系方式一次送模型。

| Tool | 输入重点 | 权限与输出 | 确认 |
| --- | --- | --- | --- |
| crm.customer.read | customerId、允许的摘要字段 | customer.read；脱敏画像、数据版本及来源 | 只读 |
| crm.metrics.read | 有权 customer/segment、窗口、币种 | analytics.read；确定性值、分子分母、policy/asOf/dataRevision | 只读 |
| crm.segment.read | segmentId/version | segment.read；规则与当前有权结果 | 只读 |
| crm.segment.validate | 规则 JSON | segment.read；规范化条件与错误；不执行 SQL | 只读 |
| crm.segment.preview | 已校验规则、窗口/币种 | segment.read；人数、脱敏样本、预览 hash/版本 | 只读，不保存业务分群 |
| crm.task.create_draft | title/goal、evaluationId/previewHash、负责人/期限、planText/checklist、基准/观察窗口 | task.write + segment.read；同一任务 Service 保存，回 task ID/status/version/planVersion | 必须确认写入 |

首版不向模型开放导出、导入确认/补偿、授权变更、批量个人字段修改、删除或外发客户消息。任务启用/执行仍由普通业务页面按权限处理。

现有快速纯问答路径不能冒充有依据经营分析。涉及指标、业务对象或工具读取时走完整受控链；核对 Runtime 对只读 Tool 的真实调用/回传，不能要求用户先授写入权才能读取有权指标。需要调整既有分流/工具适配时做最小扩展并覆盖 ERP 回归。

## 建议、确认和回执

AI 文本中的方案是未保存建议。只有用户核对具体目标、负责人、期限与依据并确认后，Tool 才调用 CRM Service 保存任务草稿；Tool execute 前重查权限、评价结果、版本与人群可见性。

保存任务草稿的确认和业务任务目标启用分别对应不同结果：前者返回 draft，后者在普通业务页提交复核后由 crm.task.confirm 将人群与执行责任置为 ready。方案字段和版本沿 03/07 保存；人工修改产生新的方案版本，旧 AiAction 不得覆盖。产品使用清楚按钮和结果文案，不能把“保存草稿”说成已经触达或执行。

复用平台 AiAction/持久回执、幂等与待核实恢复；业务保存和审计保持事务一致。工具超时先查真实结果，不能模型说“完成”就标成功。actionPresentation 提供中文参数、脱敏人数/依据、真实任务链接与回执；不展示内部错误、密钥、原始模型推理或明文个人字段。

## 事实、知识与隐私

客户人数、R/F/M、退款、币种和分群结果从 CRM Service 获取；数字与截至时间一起输出。引用至少提供 appId、对象/计算 ID、版本、窗口和来源；没有权限则返回拒绝，不根据旧会话记忆拼答案。

品牌运营 SOP 和会员政策按平台 Knowledge ACL 检索，默认当前内置引擎，可选 RAGFlow；订单和客户指标不走文档检索。知识未启用或失效时说明缺少资料，仍可基于结构化事实和手工任务完成闭环。

默认不送联系方式/地址、导入文件原文、订单私密备注和完整客户列表；按 06 最小化。模型输出的字段、负责人 ID 和日期继续校验，不以“AI 推荐”免除参数规则。

## 质量与速度验收

固定题集见 [13](13-AI验收题集.md)，事实来自 11、阈值来自 04、权限来自 06。每次版本变更记录实际模型/Provider、OpenClaw 与 Skill 版本、参数、服务端数据时点和工具回执；题集未执行前不写 AI 已验收。

真实模型用固定样例验证：数值/窗口/币种正确；不能从“无有效购买”推断 0 天；规则建议可通过 schema；复用旧版本/无权人群被拒；知识引用能重新打开；写入只有一次且有任务链接。提示注入、缺失退款信息、无模型、运行超时、取消和撤权分别执行。

保留用户点击发送到浏览器可见首字、完整解释/预览、确认后业务回执耗时；进度不计首字。质量测试和工程替身测试分开记录，少量样本不承诺 P95。只有实际省步骤且事实可核验的用例向客户宣称可用。

## 业务输出与采用约束

以下为 CRM 页面展示与保存的业务结构，复用现有 Provider/Tool/操作卡适配，不增加 Agent/Skill 执行 DSL：

| 输出 | 必须字段 | 核对方式 |
| --- | --- | --- |
| 客户/分群洞察 | summary、facts、limitations、references | facts 含 metricKey/value/unit/currency/window/asOf/referenceId；Service 原始结果为卡片权威值，文字不能改写数字 |
| 人群建议 | draftRule、assumptions、missingInputs、evaluationId/previewHash（成功预览后） | 规则经同一 schema→校验→实际预览；未调用工具不展示确认人数 |
| 运营方案 | title/goal/planText/checklist、负责人/期限待选值、基准/观察窗口、hypotheses、factReferences | 每条事实指向有权对象/评价；收益假设显式标注，不编造优惠政策或送达结果 |
| 草稿写入结果 | taskId/status/version/planVersion、requestId、对象链接 | 来自真实业务回执，status=draft；不从模型字符串推断成功 |

缺负责人/期限可以保留待选字段并保存有权草稿，提交启用前必须补齐。未说明金额阈值/来源/窗口时先展示可编辑假设或补问，不静默当成客户已确认政策。没有知识来源的优惠、券、权益只能写待核对建议，不能写已发放。

引用随服务端响应生成，打开重新鉴权；历史会话引用不可读时说明权限/版本变化，不复述旧个人资料。所有 CRM 对象字段、客户名称、来源文件、SOP 内容均视为业务数据，里面的“忽略权限/执行导出”文字不能改变工具授权。工具返回拒绝/失败/无数据时不得用语言补造可用事实。已编辑表单采用 AI 建议前显示差异并确认；旧会话异步响应不能覆盖新企业或新版本。

## 本轮只读意图保护

当轮问题未明确要求创建/保存任务，或包含不要创建等限制时，不向模型暴露草稿写工具；模型仍请求该工具时由服务端拒绝。普通方案建议可以直接阅读，不能自动转成待确认业务草稿。此修正通过替身边界检查，真实模型复测待额度恢复。
