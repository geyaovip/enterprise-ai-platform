# 官网多页面与功能界面渲染优化

日期：2026-10-28；决定：D-108。用户要求分页面、修复数字员工等入口与落地内容不一致、重排联系区，并最终明确需要产品功能界面的渲染图。已发布至https://zhixingark.cn。

## 最终页面与访问路径

官网从五页长页面改为22个规范公开页：主页；数字员工目录及ERP/CRM/MES三个岗位详情；工作目录及九个独立方案；业务应用目录及三应用介绍；协作示例、企业知识、联系与落地。

1. 主页 → 员工目录 → 岗位详情：H1始终是所选员工，展示职责、三项工作、交付与人员分工。
2. 员工/工作目录 → 单项方案 → 对应示例或工作台：具体问题、输入、步骤、结果和确认点各有清晰结构。
3. 应用目录 → 应用功能与业务流程 → 关联员工或工作台：员工、工作和应用分别保有页面身份，通过明确链接关联。
4. 联系页：标题、三项准备资料、邮箱与邮件操作整合在一个模块；手机顺序阅读，删除三列散落和重复联系横幅。

导航进入独立页面，面包屑返回所属目录。分类`?group=`支持刷新与分享，示例`?example=`直达对应面板。旧首页/员工/工作/示例片段保留对应跳转及来源参数。公开路径、静态生成、开发/预览、Worker及sitemap共用`cloudflare/public-routes.mjs`；未知页面返回真实404。

## 产品功能界面渲染

最终采用原生HTML/CSS制作的三张1200×800功能示意，经浏览器渲染后转WebP；文字与数字未交给图像模型改写。采用正式品牌、既有虚拟员工头像及示例数据，源HTML与PNG见[ui-renders](../output/site-multipage-20261028/ui-renders)，尺寸、体积和摘要见[素材清单](../output/site-multipage-20261028/image-manifest.json)。

| 素材 | 功能依据及示例 | WebP |
| --- | --- | --- |
| ERP | 现存/阈值、确认待入库、新增采购建议；24−8−4=12台、48−20−0=28件 | 34,994字节 |
| CRM | 有效订单1笔、7～30天、客户A/C及待确认的回访方案 | 38,114字节 |
| MES | 来源行、物料、用量、匹配及待核对项；缺失数量不默认1 | 32,804字节 |

合计105,912字节。用于应用卡片/介绍、员工协作示例及三个对应重点方案；完整输入/输出及人员确认仍有HTML，不依赖图片小字。图片标注界面示意和示例数据，支持键盘/点击放大、原生dialog、Esc关闭及焦点返回。不是线上真实截图，不表示新增功能或真实AI执行回执。

此前内置image_gen生成的三张通用业务插画，已按用户澄清撤出公开资产；第二批人物工作图任务已停止，未纳入官网。其[提示词](../output/site-multipage-20261028/image-prompts.json)仅为过程记录。最终未使用这些插画。
