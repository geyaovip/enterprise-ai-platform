# 品牌标识与正式域名

更新：2026-10-23，D-059。适用于新平台、ERP、CRM、MES及后续新应用，旧三应用不追溯改造。

## 一套品牌，独立应用身份

| 标识 | 图形含义 | 使用位置 |
| --- | --- | --- |
| 知行方舟 | 船帆与船体，承载行动 | 总官网、页脚、登录、三端品牌区、管理端标签页 |
| ERP | 立体货箱，货物与业务流转 | ERP产品页、应用切换、ERP标签页 |
| CRM | 三个连接的客户节点 | CRM产品页、应用切换、CRM标签页 |
| MES | 生产齿轮与执行方向 | MES产品页、应用切换、MES标签页 |

图形源唯一维护于 `packages/frontend/src/brand-marks.ts`，React使用 `BrandLogo`，三个前端通过 `brandingPlugin`生成同一组SVG。彩色主色#6554D9、辅助色#a294ed；彩色、单色、反白版本均由同一份路径生成，不复制到各应用维护。业务图标继续使用公共图标库，应用Logo不再用业务通用图标代替。

标准画布48×48，保持比例与留白；导航通常28～36px，应用切换最近使用32px，产品卡片36px。图形旁有品牌/应用名称时作为装饰隐藏于辅助技术；独立图片应有名称。反白标识用于紫色等深色背景。新应用需登记独立标识并继承这套规则，不另建主题。

品牌下载页 `/brand/identity.html` 提供四组SVG与单色/反白下载，不进入搜索引擎索引；正式原始图形在仓库中，不把生成图片或下载包作为运行依赖。

## 正式域名

唯一主来源为 `https://zhixingark.cn`；`www.zhixingark.cn` 308跳转主域，保留路径和查询参数。各业务应用与三端共用来源、身份和会话：

| 地址 | 职责 |
| --- | --- |
| `/`、`/products` | 总官网与产品目录 |
| `/products/erp`、`/products/crm`、`/products/mes` | 三个可独立分享、匿名读取的应用官网 |
| `/login`、`/register`、`/join` | 统一账号与加入企业 |
| `/t/:tenantKey/erp`、`/t/:tenantKey/crm`、`/t/:tenantKey/mes` | 企业业务应用 |
| `/tenant-admin/`、`/platform-admin/` | 两个独立管理前端 |
| `/api/` | 同来源API，由入口Worker转发至已有后端 |

各应用独立产品页不等于独立数据库、后端或账号。后续新应用增加产品页、应用标识、注册契约和路由即可沿用正式域名，不强制新建子域名。

公开页canonical、og:url、分享图片和sitemap统一正式来源。公开产品页有各自favicon，业务应用切换时更新对应favicon，两个管理端使用主品牌。私有业务/账号/管理页面继续noindex。

D-060起旧workers.dev的公开官网及抓取入口308至正式域名；登录/企业/API入口继续兼容，旧来源保留在API允许列表。不跨域搬运用户Cookie。现有账号可以在正式域名登录，首次访问正式域名会建立该来源的新会话。

## 运行配置

- 根Worker的Custom Domains绑定主域和www，继续使用WORKSPACE、TENANT_ADMIN、PLATFORM_ADMIN三个Service Binding。子Worker不单独开放workers.dev。
- Workspace构建与Worker的PUBLIC_SITE_ORIGIN均指向正式域名。
- API/Worker的WEB_ORIGIN与PUBLIC_WEB_ORIGIN使用正式域名，WEB_ORIGINS保留旧正式入口兼容。邀请链接由新来源生成；内部API隧道地址和模型/知识/数据配置不因浏览器域名更改而替换。
- TLS、DNS绑定、部署、HTTP、登录与业务访问分别验收，不以Cloudflare配置存在推断可用。实际版本、证据与回退见[59](../59-品牌官网与正式域名发布.md)。
