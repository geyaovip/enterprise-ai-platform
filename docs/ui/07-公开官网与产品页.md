## 信息架构与入口

**官网最多两级，首页计为一级，栏目页计为二级。** 不能继续串联“栏目目录 → 岗位详情 → 工作方案 → 示例页面”，也不能只把URL改短而保留同样的连续跳转。首页可一步直达具体工作或应用在栏目内的位置。

| 规范路径 | 本页包含的内容 |
| --- | --- |
| `/` | 平台主视觉、三组业务能力、补货协作示例、常见问题、联系咨询 |
| `/employees` | ERP、CRM、MES、品牌内容和 GEO 员工原地切换；各自职责、相关工作的完整流程、交付、人员确认和协作示例 |
| `/solutions` | 十一项工作原地切换；输入、处理步骤、结果、确认及适用示例 |
| `/products` | ERP、CRM、MES、品牌内容、GEO 原地切换；功能、流程、产品渲染图及协作示例 |
| `/knowledge` | 资料查询、原文引用、访问权限和核对 |
| `/contact` | 联系模块及直接使用、扩展和专属构建 |

共6条规范公开路径，由`cloudflare/public-routes.mjs`提供给静态生成、开发中间件和Worker。岗位、应用和工作仍是不同对象，但在所属栏目内完整查看，不另建下一级详情。若需比较其他栏目，可使用统一主导航；内容说明不要求继续进入其他页面。

## 导航与页内交互

- 主导航为工作场景、数字员工、业务应用、企业知识、联系与落地、工作台；协作示例嵌入相关栏目，不作为必须再访问的独立页。
- 每个栏目只有“首页 / 当前栏目”两项面包屑，始终能直接回首页，不依赖访问历史。
- 岗位、应用、工作选择使用原生button和tab/tabpanel语义，支持方向键、Home/End和单一Tab入口。切换只更新当前栏目片段，不加载新的详情页。
- 静态阅读面板保留tabpanel语义、可访问名称和键盘阅读入口，但不为整个大容器画焦点框；页内片段直接定位也不能出现整页描边。样式仅限定静态面板，不全局移除outline，按钮、链接及可滚动表格仍保留清晰的键盘焦点。
- 员工工作的完整输入、步骤、交付及确认直接展示，使用标题、间距和分隔线分组；首页常见问题可使用原生 details/summary，岗位工作流程直接展示。人员确认不因结构精简丢失。示例输入与结果就在本页，可从场景开头直接定位。场景末尾指向对应业务应用。
- 页内片段可直接打开、刷新、分享，并恢复正确面板；示例或工作片段要选中所属岗位，并直接定位对应工作。页内定位不应让标题被固定页头遮挡。
- 官网菜单在1000px及以下收起，支持选后关闭、点击外部关闭、Esc及焦点恢复；控件触控区至少44px。
- 旧16个岗位/工作/产品详情及示例路径，包括尾斜杠和index.html形式，308至对应栏目及片段；旧示例参数选择对应岗位，保留来源查询参数。旧首页/产品片段继续由公开脚本兼容，不形成第三层规范页面。
- 旧工作分类参数可恢复相应默认工作；未知参数不新增页面，未知旧路径仍返回真实404。

## 页面布局

- 内容区最多1320px，沿现有品牌间距；不为每个产品另造主题。
- 首页保留概览，不承载所有方案全文、所有示例与重复联系区块。栏目内完成选择、理解流程和查看示例，避免反复切换页面。
- 员工栏目使用岗位切换，同一面板内显示岗位标题、职责、工作及示例。栏目H1保持数字员工，岗位使用H2，展开内容保留正确标题层级。
- 工作栏目采用十一项切换；桌面保持主要流程与结果面板，手机按资料、步骤、结果顺序阅读。员工栏目用完整的岗位工作区块承接相同内容。必要信息仍有HTML文字，不能只放进图片。
- 联系模块的标题、三项准备资料、可选取的邮箱和单一邮件操作必须形成一个完整区块。桌面主内容与邮箱相邻，手机自然向下排列；不把标题、清单、按钮分散到三列，不重复叠加联系横幅。
- 表格只在局部滚动，不允许页面整体横向溢出。长中文、SKU与窄屏布局均需核对。

## 图像与功能示意

首页业务卡片使用概念渲染图、标题和单一场景入口。工作场景的协作示例直接展示示例输入、处理步骤、输出和人工确认项。品牌内容场景可以展示生成与参考改图的产物。

- 主视觉与五个应用采用同一紫白材质。渲染图展示工作内容，实际业务步骤和结果用 HTML 表达。
- 图片标明宽高并提供描述性替代文本。主视觉优先加载，应用图延迟加载。放大视图显示完整画面。
- 栏目示意图使用带可访问标题的原生 dialog，支持关闭按钮、Esc 与焦点恢复。首页能力入口为普通链接。
- 渲染图的主题取自已实现功能。具体数据、来源、限制与人员确认在文字中展示。

## 能力与文案边界

三位既有员工对应九类工作：ERP管家的库存补货、采购跟单、账款核对；CRM运营官的客户运营、销售跟进、客户服务；MES生产官的BOM核查、计划准备、进度追踪。工作分类不等于新增Agent或市场资产。

采购、库存、财务、客户联系、服务审核、BOM发布和报工审核由有权岗位办理。计划准备仅展开理论物料需求，齐套、产能和承诺交期另行核实；待审数量不计入完成。未实现的CAD/CAE/DRC、工艺成本报价、自动齐套和APS等不包装成可用岗位。

文案沿[UI02](02-组件与交互.md#界面文案与信息密度2026-10-28d-093)：删除重复口号、标签与帮助段落，保留能帮助选择和理解结果的内容。输入、必填、表头、可访问名称、来源、待核对与不可逆后果不因清爽而删减。用户授权的邮箱为geyaovip@163.com，使用mailto；不造空咨询表单、无承接试用或未经核实的安装/雇佣入口。

## 渲染、索引与验收

- 6个公开页输出完整匿名HTML，不加载业务React入口。业务、账号、管理端独立应用壳及noindex保持。
- 每页唯一title、description、H1、canonical、分享信息及与可见内容一致的结构化数据。栏目ItemList、两项面包屑及业务应用页中的五个SoftwareApplication与本页实际内容一致，不添加虚假价格、评分或客户评价。
- sitemap只含规范公开路径，不用构建时间伪造lastmod；正式来源为https://zhixingark.cn。尾斜杠、index.html及旧公开域名沿308规范化，保留来源参数；账户、企业和API不因SEO规则跳域。
- 构建后检查全部公开页面、站内链接与锚点、重复ID、资源、旧链接目标、SEO/404、私有壳隔离及静态示例不调用业务API。
- 浏览器检查首页一步进入内容、页内切换/展开/示例、返回与刷新、旧链接及键盘操作、图片放大、菜单、桌面/平板/手机和控制台。截图与DOM检查不代表完整读屏、原生设备或客户验收。
