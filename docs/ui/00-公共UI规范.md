## 对话通道扫码接入

- 四种通道共用“选择通道 → 扫码 → 官方授权 → 连接状态”的布局，默认不展示 App ID、密钥或回调地址表单。授权状态与个人绑定状态分开呈现。
- 二维码必须有可访问名称、过期状态和重新获取操作；刷新页面可恢复仍有效的接入。安全信息不写入浏览器存储。
- 无法可靠识别扫码者时采用一次性成员绑定，不以昵称自动映射权限。绑定指令可一键复制，并明确发送对象和有效期。
- 默认助手有表单标签，低频对话指令放在 info tooltip。断开企业连接与解除个人绑定分别说明后果。
- 上游接收回执只能表述“通道已接收”，不能显示为手机已读。浅深模式和手机端都保留清晰的扫码、绑定和测试入口。


## 列表查找与异步恢复

- 名称和状态筛选在服务端分页之前完成，改变条件返回第一页。将“加载失败”“没有符合条件的结果”“暂无数据”明确区分，不能把读取失败或加载过程呈现成成功空态。
- 任务详情的进度追踪不能依赖任务是否仍在当前列表中。重试、停止、取消均保留忙碌状态、同步提交保护、错误恢复和必要后果说明。
- 多应用通知共用筛选和批量已读入口；操作结果以服务端计数回查，不把晚到通知一起清空。通知弹窗中的选择框在手机和桌面都要保留能读出所选项的宽度。
