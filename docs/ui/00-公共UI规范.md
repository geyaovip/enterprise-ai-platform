所有新应用使用同一套视觉、组件和基础交互。公共规则在本目录维护一次；应用文档只记录业务字段、状态、权限、页面职责及必要差异。历史 [04](../04-UI与交互规范.md) 保留为导航入口，[45](../45-三端UI统一规范与验收.md) 保留为 ERP 三端改造证据。

D-048补充：已启用且有权的默认能力直接可用，不设计额外的“先勾选才生效”；阅读和核对所需的关键信息直接展示，长技术轨迹用摘要控制密度。同一内容核对后提交只确认一次，保留真实业务写入、删除及权限变更所必需的确认。ERP三端与后续CRM等应用共同遵守；AI具体交互及证据见[51](../51-AI对话操作简化.md)。

## 来源与优先级

1. 当前用户明确决定及 [平台决策记录](../00-文档索引与决策记录.md)。D-045 将 D-043/D-044 的公共 UI 口径集中维护；D-024 的旧 ERP 蓝色视觉仅为历史。
2. 本目录公共规则；应用业务行为同时遵守自身领域、权限、数据与验收契约。
3. 经确认且登记的应用差异。共享组件缺项进入公共改进，不靠应用 CSS 覆盖解决。
4. 历史截图、旧实现、外部参考只用于追溯，不能覆盖以上规则。

参照来自自动化运营 2026-10-19 版的[界面与交互](../../../../weibot/自动化运营/文档/设计/界面与交互.md)、[复用指南](../../../../weibot/自动化运营/文档/设计/UI复用指南.md)和[Demo 源码](../../../../weibot/自动化运营/视频运营.html)。这些是设计来源；本目录已写明独立实施所需的规则，其他开发机器无需具备外部项目目录。

## 公共实现与状态

- 统一样式入口：`@suite/frontend/styles.css`，由 [共享包](../../packages/frontend/package.json) 导出；颜色和布局由 [theme.css](../../packages/frontend/src/theme.css) 维护，AI 专用布局由 [ai-dialog.css](../../packages/frontend/src/ai-dialog.css) 维护。
- 统一组件入口：`@suite/frontend/components`；账号页面使用 `@suite/frontend/auth-screen`、`@suite/frontend/session`。文件名 `ErpShell`、`erp-theme.css` 是兼容命名，承载当前公共 Shell/主题，不要求新应用复制一套。
- 已有 ERP 三端本地实现与浏览器证据见 45/46；CRM V1实施/发布见CRM15，应用切换优化见52。设计规则、代码存在、本地验证、生产发布、真实模型和客户验收分别记录，当前状态见 [47](../47-项目现状与文档维护.md)。
- D-045最初公共化为文档整理；后续公共实现与发布沿各日期证据读取。

## 统一范围

公共：品牌与主题、导航骨架、标题与操作层级、基础组件、查询/返回、错误/空态、对话外壳、账号与通知、触控/键盘/焦点规则。

应用自有：菜单分组、业务名词、数据和指标、专用表单、状态机、对象权限、AI 事实/工具、确认后果与结果链接。应用可以独立启用，CRM-only 企业不能出现 ERP 默认错误页或 ERP 业务文案。

官网和产品介绍页共用品牌及语义颜色，采用公开营销页面布局；后台 Shell、租户数据和管理控件不进入公开页。原有旧 CRM/MES/ERP 工作区继续保留。
