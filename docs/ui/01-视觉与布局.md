# 公共视觉与布局

更新：2026-11-03。适用范围与优先级见 [00](00-公共UI规范.md)。应用引用同一公共主题；品牌内容保留创作专用配色。双模式实现见[140](../140-应用浅色深色外观.md)，真实浏览器验收与联合发布见[143](../143-公共UI联合验收与发布.md)。

## 颜色与语义

| 用途 | Token | 浅色基线 |
| --- | --- | --- |
| 品牌/主动作 | `--brand` | `#6554D9` |
| 主动作悬停 | `--brand-hover` | `#5543C4` |
| 选中浅底 | `--brand-soft` | `#F0EDFF` |
| 画布/表面 | `--canvas` / `--surface` | `#F6F7FB` / `#FFFFFF` |
| 正文/次级/辅助 | `--text` / `--muted` / `--hint` | `#202535` / `#596174` / `#606A7B` |
| 分隔边框 | `--border` | `#E3E6EE` |
| 成功/警告/危险 | `--success` / `--warning` / `--danger` | `#187B4D` / `#956000` / `#BF3434` |

输入边界、聚焦和禁用有专用组件规则：普通输入边界使用`--input-border`（浅色`#858D9C`、深色`#6D7482`），保持细边界和足够的表面对比，不把输入边界淡化成装饰分隔色。应用使用语义变量，不按 ERP/CRM 分配不同主色。图表可使用可区分的系列色，同时提供名称、单位、窗口及文本数据，不能仅靠颜色解释结果。

普通文字对比目标至少 4.5:1，必要控件边界和大字至少 3:1；目标须在实际背景、状态和字号下测量，不因列出色值就宣称达标。

2026-11-03补充：透明工具按钮、图标与原生选择器使用所在表面的正文/次级色；实心主按钮的前景色只用于其对应填充底色。不得把`--on-primary`或`--studio-submit-text`套到透明工具栏，避免浅色白字或深色黑字消失。悬停使用主操作悬停色，不借用禁用底色。实际创作工具栏及手机截图必须纳入验收，单独计算Token色对不能替代控件检查。

### 浅色、深色与跟随系统

- ERP、CRM、MES、品牌内容及两管理端共用“账号菜单 → 外观”入口，提供浅色、深色、跟随系统，默认跟随系统；不要在每个页面重复放切换开关。保留头像/昵称整块触发，不恢复下拉箭头。
- 主题是当前浏览器的界面偏好，以`zhixingark:appearance`保存；正式同源的工作区和两管理端共同读取。同源标签页同步，系统外观变化只影响“跟随系统”；显式选择不被系统覆盖。开发端口是不同源，不承诺其localStorage跨端口同步。
- 首次绘制前读取偏好，避免已选深色却先显示浅色外壳。存储被禁用或损坏时仍能切换，当前会话可用；不增加网络请求、企业模型配置或账号写入。
- 通过语义变量区分页面/表面/浮层、正文/次级/辅助、边框/输入边界、主操作及状态；禁止整体滤镜反色。深色公共页面使用`#15171D`背景、`#20232C`表面及`#B8AAFF`主色，内容工作台使用中性`#111111`背景、`#191919`表面及`#C9C2FF`主色；浅色内容工作台使用`#FAFAFA`背景及白色表面。
- 列表文字操作、禁用、错误、危险确认、表单、选择器、提示、账号/通知、AI浮窗均须适配。颜色不替代状态文字、焦点、选中/展开的可访问状态；原生控件通过`color-scheme`沿实际主题。
- 图片、商品和品牌素材、图层颜色、画布备注内容、透明背景及下载/导出文件保持原样；媒体上白字/遮罩、纸质文档和图纸底色按其用途保留。打印使用浅色纸张样式。

## 字体、密度与间距

| 内容 | 基线 |
| --- | --- |
| 字体 | 系统中文字体栈：`-apple-system/BlinkMacSystemFont/PingFang SC/Microsoft YaHei/sans-serif`，无额外网络字体依赖 |
| 页面主标题 | 内容区24px / 32px / 600；滚动进入顶栏后使用共享顶栏的紧凑字号 |
| 区块/弹窗标题 | 16px / 24px / 600 |
| 正文/PC输入 | 14px，正文约 1.7 行高 |
| 表格正文/字段标签 | 13px；标签字重 500 |
| 辅助说明/表头 | 12px；不将错误或必读内容压成难读小字 |
| 手机主要文本输入 | 16px，验证聚焦、输入法及可见区域 |
| 间距 | 优先 4/8/12/16/20/24/32px，使用组件现有间距 |
| 圆角 | 控件 6px、普通卡片 10px、弹窗/AI浮窗 12px；AI输入与工作单按 04 |

同一页面层级、按钮密度和表格留白一致。长名称、连续英文、金额和状态不能挤掉主要动作。金额和数量比较列右对齐、采用等宽数字，币种/单位来自业务契约；缺失值、真实零值和未加载分开。

## Shell 与页面骨架

- 桌面侧栏 224px、顶栏 56px，颜色沿主题表面；品牌、企业/应用范围和底部账号可达，导航独立滚动。内容最大宽 1600px，常规桌面内边距沿共享样式的 32px。
- 左下角账号入口不显示上下拉箭头；头像与昵称使用同一个完整按钮，点击任一区域均打开账号菜单。保留具体账号可访问名称、展开状态、键盘焦点及Enter/Space操作，Esc关闭后恢复入口焦点。
- 侧栏呈现分组和当前页面，不增加每个应用独立的顶栏/账号/通知。当前页面只出现一个主标题。桌面`PageTitle`默认在内容区展示，标题行滚出顶栏下缘后进入固定顶栏，回到顶部恢复；保持原位置高度，避免跳动或重复H1。手机（≤767px）一级和二级页面标题默认固定在顶栏，内容区不重复标题或留下标题占位。页面操作留在内容区。
- 二级页面（新建、编辑、详情、聚焦记录、打印预览）的返回箭头位于标题左边。手机一级页保留左上角导航，二级页使用返回、不叠加抽屉；桌面返回随标题滚动。图标使用具体可访问名称，例如“返回计划”，不可只依赖图形。长标题最多两行，完整标题保留在H1文本和title中，不挤占返回或右侧按钮；触控区域至少44px。
- 顶栏右侧统一“询问AI”，PC 图标加文字，手机图标。当前入口常驻，权限/服务状态决定内容和可执行性，见 04。
- 手机顶栏的导航/返回按钮、标题和AI按钮按内容区的同一水平中心线居中；菜单显式使用 `align-self:center`，不能继承旧版靠上对齐。图标尺寸可不同，触控区域仍为44px；安全区另计入顶栏内边距。
- 设置使用左目录、右默认内容；选中项与内容一致。手机使用同一设置分组的自适应菜单，不复制第二套业务状态。
- 菜单、弹窗、历史选择层与通知按共享层级处理。原生 dialog 的 top layer 以浏览器行为为准，不能只提高 z-index。

## 断点与触控

| 视口 | 统一行为 |
| --- | --- |
| ≥960px | 桌面侧栏常显；960–1199px使用共享紧凑留白 |
| 768–959px | 侧栏抽屉；业务内容按宽度换行；AI仍为PC浮窗 |
| ≤767px | 手机顶栏/控件规则，AI全屏；普通业务弹窗受视口限制，不自动全屏 |
| ≤359px | 增加窄屏标题、长内容与操作可达性检查 |

PC主要控件 40px，手机主要输入/按钮/关闭/导航点击区至少44px；图形大小与点击区分开。表格行内低频按钮可采用共享紧凑规则，手机提供足够触控范围。

Grid 使用 `minmax(0,1fr)`，Flex 子项可收缩；确需二维比较的表格在自身容器横滚。主要动作、正文和错误不产生整页横向溢出。固定底栏预留真实高度及 `safe-area`，使用动态可见视口处理输入法。

图标沿已有 Lucide/品牌资产，普通图形约16–20px；图标按钮有可访问名称，装饰图标隐藏于辅助技术。hover、长按和拖拽均提供触控/键盘替代入口。


D-144焦点视觉：普通输入框使用1px边框和相邻的1px焦点色，形成一层圆角边界；组合搜索、可搜索下拉及创作输入区由可见外层承担焦点，内部字段不再叠框。按钮、链接和原生开关保留2px键盘轮廓。控件保持可读的禁用文字和填充，不再重复降低透明度；系统高对比使用Highlight轮廓。公共实现集中在`theme.css`及`focus.css`，原D-071的3px输入光晕不再采用。见[144](../144-公共控件视觉统一与发布.md)。

D-095：标题初始位置、滚动入顶栏、二级页返回和手机导航由共享PageTitle维护；本次实现与验证见[95](../95-标题返回间距与列表分页.md)。登录、公开官网和弹窗沿各自模板。
