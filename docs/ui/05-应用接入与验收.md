# 公共 UI 接入与验收

更新：2026-10-23。适用于新增应用、公共组件变更和既有页面优化。

## 组件与代码入口

| 能力 | 现有入口 | 应用责任 |
| --- | --- | --- |
| 样式/主题 | `@suite/frontend/styles.css`；theme.css、ai-dialog.css | 使用语义变量，应用样式仅覆盖自己的业务结构 |
| Shell/标题 | `ShellBrand`、`ShellToolbar`、`NavIcon`、`PageTitle` | 接入可信应用目录、菜单/权限和页面主操作 |
| 应用身份/切换 | `ApplicationSwitcher`、`ApplicationChoice`、application-switcher.css；见06 | 可信目录、图标/简称/用途、有权路由与会话恢复 |
| 表单/弹窗 | `Field`、`PasswordInput`、`Dialog`、`ConfirmDialog`、`DialogAction`、`ActionPanel` | schema、业务保存、版本/幂等、失败恢复 |
| 设置/列表反馈 | `SectionTabs`、`TabBar`、`Pager`、`Status`、`Notice`、`Empty`、`Loading` | 真实查询、范围、分页和领域状态；标签编辑等缺项先评估归属 |
| 账号/通知 | `UserMenu`、`NotificationCenter`、`auth-screen`、`session` | 复用同一账号，通知由拥有者贡献，目标资源重新鉴权 |
| AI展示 | `AiDialog`、`AiProcessView`、ai-dialog.css | 应用Provider、事实、工具、工作单及回执适配 |
| AI交互链 | `AiConversation`、`services`、api/hooks | 核对现有scope和固定ERP逻辑，完成新应用适配再接入 |

确切导出见 [package.json](../../packages/frontend/package.json)，实现见 [components.tsx](../../packages/frontend/src/components.tsx)。复用现有契约，避免复制完整样式或从应用私有页面跨目录导入。

应用入口统一导入：

```tsx
import '@suite/frontend/styles.css';
import { PageTitle, Field, Notice, Dialog } from '@suite/frontend/components';
```

上述是实际导出示例；应用路由、权限、数据和保存逻辑按 [接入契约](../10-应用接入契约.md) 实现。`erp-theme.css`为兼容入口，新增应用使用公共styles入口。

## 新应用接入顺序

1. 读取00及本目录01～04，核对现有共享实现和最新项目状态。
2. 编写应用UI适配：使用者、菜单/页面、主要动作、领域状态、权限/范围、异步和字数/批次限制、工作单及回执。
3. 把已有组件、公共缺项和应用专用组件分清。公共缺项更新本规范及共享实现，业务特殊组件由应用维护。
4. 接入可信应用注册、通用身份和导航；验证无ERP的独立应用企业，不复制登录/组织/通知后台。
5. 分别验证功能、权限、浏览器交互、响应式和真实模型/业务效果，记录环境和证据。
6. 申请发布前列出迁移、兼容、共享组件影响、回退与验收范围，保留旧应用。

## 公共变更与例外

基础颜色、字号、断点、Shell、账号/通知和AI外壳统一维护。业务差异优先通过组件参数与应用内容适配；确需改变公共行为时先记录场景、影响和决定，并同步所有消费者。

已有主题/组件不能只为CRM做无条件全局覆盖。改公共组件时覆盖工作台、企业管理、平台运营及已接入业务应用；应用专用表单不因同名自动提升公共模块。版本变化记录于00并同步适配文档，历史验收留存原日期与环境。

## 验收矩阵

| 维度 | 必须覆盖 |
| --- | --- |
| 视觉/布局 | 颜色和字级一致，标题单一，操作层级明确，真实长内容不丢操作 |
| 视口 | 1440/1280/1024/900/768/390/320px；959/960及767/768边界，必要时1199/1200留白边界 |
| 输入/表单 | 清空再输入、字段错、提交锁、保存失败、版本冲突、未保存离开、IME |
| 查询/集合 | 查询/重置/排序/分页、返回现场、跨页勾选、取消不采用、0/null/未加载 |
| 弹窗/浮层 | 居中标题、内容滚动、主要动作可达、Tab/Esc/焦点恢复、背景交互与最上层优先 |
| 范围/权限 | CRM-only企业、切企业/应用/成员、资源删除、撤权、过期异步响应 |
| AI | 新对话、历史、快捷问题、工作单保留、后台恢复、取消、确认/真实回执、服务不可用 |
| 手机/可访问性 | 原生键盘、旋转、safe-area、触控、缩放、对比度、辅助技术和减少动态效果 |
| 公共回归 | 所有现有消费者的代表页面与关键交互；不能只在新增应用验证 |

一份有效证据包含：日期、代码版本/环境、角色与企业/应用、视口、操作、预期与实际、截图/接口回执、失败/未覆盖项。截图不证明写入，构建不证明交互，替身不证明真实模型，旧生产样本不证明新版本已发布。

## 响应速度与实际操作效率（D-032）

以下是工程优化目标，尚非已达成指标或对外SLA：

| 场景 | 目标 | 测量口径 |
| --- | --- | --- |
| 点击/提交反馈 | 200ms内 | 动作到真实忙碌反馈；提交成功按服务器持久化另计 |
| AI处理进度 | 就绪无拥塞时1秒内 | 与界面反馈和首字分开；本地占位不冒充模型收到请求 |
| 常用列表/详情/筛选 | P95两秒内 | 动作到可读数据，骨架/假零不算完成 |
| 普通AI首字 | P95五秒内 | 点击发送到浏览器绘出首个非空白回答字符，含准备、排队、检索、网络和渲染 |
| 简单AI完整回答/单步辅助 | P95十五秒内 | 完整回答或有效操作预览；写入按独立回执 |
| 文件/批量/多步骤 | 持久任务和真实阶段 | 按数据量/步骤记录完整耗时，不统一承诺十五秒 |

分别记录首次、空闲恢复、连续、成员切换、多人、知识与业务写入场景，报告样本数、P50/P95、最大值和失败率；小样本只报告观察值。用户明确不展示“正在提交消息”作为处理进度。AI首字、首段、完整结束及业务回执分别计时；性能历史样本见 [43](../43-自动运行与工作体验优化.md)，不代替新应用实测。

## 现有复用缺项

| 事项 | 当前事实 | 后续接入要求 |
| --- | --- | --- |
| CRM对话适配 | 共用AiDialog/AiConversation已增加CRM独立scope | CRM事实、快捷操作、工作单链接及权限独立；发布/模型边界见CRM15 |
| 会话输入持久化 | CRM未发送问题采用加密服务器草稿、串行自动保存和版本冲突提示；其他域仍为内存 | CRM编辑页使用路由离开保护，共享弹窗保留关闭保护；原生关闭时异步保存不保证完成，以已保存状态为准 |
| 字数限制 | ERP/管理端4000，CRM前后端600 | 不更改ERP现有约束，明确应用参数、前后端校验与错误 |
| 手机与可访问性 | 有桌面/窄屏浏览器证据 | 原生键盘、辅助技术和全面对比度仍按实际设备/版本验证 |

完成情况统一汇入 [项目现状](../47-项目现状与文档维护.md)，不在每份规范重复声明“全部已验收”。
