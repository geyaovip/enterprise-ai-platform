# 首阶段实施计划

本计划把“先平台、再新建 ERP 首客试用”拆成可验收工作包。旧 ERP 只作为功能和规则参考；M5 不是旧 API/数据库迁入。任何阶段都不能以内部演示代替真实客户试用准入。

## 决策门

每阶段先读[15 开发启动基线](15-开发启动基线.md)，再按[总体架构](03-架构与数据安全.md)、[共享准入规则](14-共享能力准入与模块公开契约.md)、[领域边界](12-领域边界与协作契约.md)、[应用模块契约](10-应用接入契约.md)及[旧应用能力盘点](13-三应用业务能力清单与领域归属.md)建设统一公共模块。首客是否要从现有系统导入数据的 [Q-002](00-文档索引与决策记录.md#待确认的决策) 不阻挡平台和 ERP 新建，但阻挡客户专属导入脚本及切换计划。[16 ERP/CRM 模型评审](16-ERP与CRM客户商机模型评审.md)已确定 ERP 首期自有客户和商机；Q-003/Q-004 在 CRM/MES 跨应用关联或提升共享前关闭，不阻挡 ERP 全范围开发。上线前还须确认客户数据处理、模型供应商和支持联系人。

## 工作包

| 顺序 | 工作包与目标 | 主要产物 | 通过条件 |
| --- | --- | --- | --- |
| M0 | 统一架构与领域边界定稿 | 依据 [ADR-001](ADR-001-技术栈决策.md)、[16 模型评审](16-ERP与CRM客户商机模型评审.md)、[17 功能矩阵](17-ERP功能追踪矩阵.md)和共享准入规则确定模块图、所有者、不变量、公开契约、权限/AI/审计及完整功能基线 | 采购到入库切片的同库事务和 AI Tool 边界可复核；ERP 客户/商机有稳定 ID，不预建 Party |
| M1 | 仓库和部署基础 | 按 ADR-001 建 Monorepo、统一 Web/API、Worker、单数据库迁移链、lint/typecheck/test/CI、健康接口，固定确切依赖版本 | 干净安装、构建、迁移、同库事务/回滚和 NestJS/Prisma 兼容性验证通过；无密钥入库 |
| M2 | 平台技术公共模块 | User/Tenant/Membership、稳定 OrgUnit 与成员组织关系、会话、代码 App Manifest/TenantApp、角色/授权、服务端 AppContext/RequestContext、审计底座；确定 KnowledgeProvider/RetrievalContext/Citation 契约 | `AC-01`～`AC-05`，双租户/双角色、组织范围、跨应用及应用禁用测试；权限变更立即生效；无空业务/向量库模块 |
| M3 | 统一 Web 与企业管理 | 企业/应用选择、成员与应用管理、账号安全、UI token 与组件 | 刷新、深链接、手机导航、403/404/空状态验收；操作均对应真实 API |
| M4 | AI 与后台任务基础 | ModelGateway、模型设置、带 AIExecutionContext 的聊天、读写 Tool、确认和回执、用量、任务状态和审计；检索使用 M2 契约，真实用例出现时才实现 Provider | `AC-06`、`AC-07` 的平台能力验证；应用切换、撤权、确认与失败状态可复现 |
| M5 | 从零开发完整 ERP 模块 | ERP 自有客户、商机、商品、供应商及采购、销售、库存、财务的领域模型、表、命令、API、UI、AI Tool；为页面、AI 及真实跨模块消费者提供所需公开契约，不预建未来接口。先以采购确认→分批入库→库存/应付验证技术链路 | [17 功能矩阵](17-ERP功能追踪矩阵.md)逐行有 API/UI/权限/AI/测试和迁移证据；`ERP-01`～`ERP-07`、`AC-10`～`AC-13`、`AC-15` 通过 |
| M6 | ERP AI 真实验收 | 聊天创建真实采购草稿；采购、销售、库存等模块的履约分析、文字提取、缺料解释等有效用例 | `AC-14`、`AC-16`、`AC-17`；真实模型、回执、来源、误报、人工节省及失败处理有记录 |
| M7 | 客户试用上线 | 空库开通或经授权的数据导入、备份恢复、监控告警、发布与回退演练 | M5/M6 全范围及 `AC-10`～`AC-17` 有实际证据，[08 数据导入与上线验收](08-迁移与上线验收.md) 通过；客户可用 |

M2 完成后平台可以继续建设，但只有 M7 通过才称 ERP 可供首客试用。M3/M4 可在 M2 稳定后交错开发；M5 的新模型和功能实现不依赖客户是否导入旧数据。任何客户可见变更上线前先有数据回滚和权限回归证据。

## 每个工作包的实施记录格式

在实施记录中写：`目标/功能 ID → 受影响模块与数据库迁移 → 风险/回退 → 构建与测试命令 → 真实浏览器/部署证据 → 已完成、部分完成、未验证`。不要只用“完成百分比”掩盖未通过的租户隔离、真实模型或恢复演练。

## 后续阶段入口

ERP 首客试用稳定后，继续在同一 Web、API 和数据库中开发 CRM、MES 模块，各自建立业务验收集。CRM 与 ERP 客户/商机发生跨应用关联前关闭 Q-003；MES 与 ERP 商品/物料发生跨应用关联前关闭 Q-004，决定保留各自模型、显式映射或经评审提升共享。三套新应用稳定后，先复盘平台公共模块、领域边界与部署经验，再启动建筑行业首客需求，不把建筑草案直接当任务列表。
