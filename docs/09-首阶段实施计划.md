### 建议体验工作的退出条件

1. 自动运行：重复首次请求只准备一次；就绪后执行；活动模型请求不被空闲回收；休眠后状态可恢复；超额排队；撤权/取消与故障处理有回执。
2. 等待和后台执行：输入不丢失、不重复提交，离开和刷新后可读取真实阶段；启动与模型执行分别计时。
3. 任务与通知：确认、审批、失败和完成入口到达具体对象，角色与对象权限在目标页面重新核验。
4. 上下文和回执：返回位置与当前单据保留，结果呈现业务名称、数量、金额、负责人和下一动作。

这些是规划中的目标，不改变 [41](41-六批优化交付与线上验收.md) 的已完成范围。参数与容量经实测确定，新增能力交付前不得标为已开通。

D-013 的业务流程增量与 D-014 的外部工作通道分别验收。平台内审批、待办等业务状态必须以 ERP/平台自身记录为准；飞书、企微、钉钉的实际连接状态按 [20](20-工作通道接入与验收.md)单独标记。受外部授权限制而搁置的通道不得在客户试用中显示为已接通，也不把渠道扫码作为 ERP Assistant 首个 Skill 的前置条件。若首客业务确实依赖某一通道，则该通道的实连验证进入该客户试用门槛。

### ERP AI 体验增量

M4/M6 让企业 AI 入口与 ERP 内入口复用同一 `erp.assistant` 定义、OpenClaw 执行链与平台 Tool Executor；以 [22](22-AI体验与首阶段Agent策略.md) 的“文字需求→采购草稿”为候选，完成固定样本和权限/失败验证。按 D-020/D-022 以平台内置知识和 ERP 业务数据形成至少一个受控闭环；RAGFlow Cloud 暂缓。Skill 或知识闭环通过不替代既定 ERP AI 全范围验收；不新建默认 Enterprise Assistant，也不以 Skill 数量或多轮调用作为完成条件。选型不再等待 PoC，实连和客户验收仍按 [ADR-002](ADR-002-AI运行边界与外部协议.md) 与 [24](24-首阶段新增能力与验收.md) 执行。
