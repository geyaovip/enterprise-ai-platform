# 首阶段实施计划

本计划把“先平台、再 ERP 首客试用”拆成可独立验收的工作包。阶段编号表示依赖，不表示按页面数量或固定日期交付。任何阶段都不能以内部演示代替真实客户试用准入。

## 决策门

先按[总体架构](03-架构与数据安全.md)、[领域边界](12-领域边界与协作契约.md)和[应用接入契约](10-应用接入契约.md)建设平台通用模块。首客数据是否要迁移的 [Q-002](00-文档索引与决策记录.md#待确认的决策) 不阻挡平台设计和开发，但阻挡客户专属映射、迁移脚本及切换窗口。Q-003/Q-004 分别是 CRM/MES 接入门槛，不阻挡 ERP 首期。上线前还须确认客户数据处理、模型供应商和支持联系人。

## 工作包

| 顺序 | 工作包与目标 | 主要产物 | 通过条件 |
| --- | --- | --- | --- |
| M0 | 总体架构与契约定稿 | 上下文图、数据所有者、不变量、跨上下文 API/事件原则、Manifest、权限/AI/审计接入契约及 ERP 旧功能清单 | 采购到入库纵向切片的事务和 AI Tool 边界可复核；未知主数据问题单独记录；旧系统保留策略明确 |
| M1 | 仓库和部署基础 | 新项目工作区、平台 API/Worker 与应用模板、独立数据库配置、lint/typecheck/test/CI、健康接口 | 一条命令启动干净开发环境；平台和应用各自可构建/迁移；无密钥入库 |
| M2 | 平台核心通用模块 | User/Tenant/Membership/App、会话、RBAC、RequestContext、签名内部上下文、平台 SDK、审计底座 | `AC-01`～`AC-05`，双租户/双角色与应用禁用测试；权限变更立即生效 |
| M3 | 统一 Web 与企业管理 | 企业/应用选择、成员与应用管理、账号安全、UI token 与组件 | 刷新/深链接/手机导航/403/404/空状态验收；操作全部对应真实 API |
| M4 | AI 与后台任务基础 | ModelGateway、模型设置、AI 聊天框、读/写 Tool 编排、动作确认与回执、用量、任务状态和审计 | `AC-06`、`AC-07` 的平台契约测试通过，确认与失败状态可复现；不影响人工 ERP 流程 |
| M5 | ERP 应用接入 | ERP 独立业务 API/数据库、旧角色/数据映射、Manifest、前台/后台模块、采购/库存/销售/财务应用命令；先贯通采购确认→分批入库→库存/应付纵向切片，同时设计模块 AI | `ERP-01`～`ERP-07`，`AC-10`～`AC-13`、`AC-15`；关键不变量和事务回归通过，平台未复制 ERP 规则 |
| M6 | ERP AI 真实验收 | 聊天接入 ERP 读/写 Tool，至少完成一次真实的采购草稿创建；采购、销售、库存等模块的履约分析、文字提取、缺料解释与候选用例落地 | `AC-14`、`AC-16`、`AC-17`；真实模型、业务回执、来源、误报、节省人工步骤及失败处理有记录 |
| M7 | 客户试用上线 | 试迁移或空库开通、备份恢复、监控告警、切换与回退演练 | [08 迁移与上线验收](08-迁移与上线验收.md) 各项有实际证据；客户可用 |

M2 完成后平台可以继续建设，但只有 M7 通过才称 ERP 可供首客试用。M3/M4 可在 M2 稳定后交错开发；M5 的客户历史数据迁移设计取决于 Q-002，ERP 应用边界和接入契约不依赖该答案。任何客户可见变更进入上线前先有数据回滚和权限回归证据。

## 每个工作包的实施记录格式

在后续实施记录中写：`目标/功能 ID → 受影响模块与迁移 → 风险/回退 → 构建与测试命令 → 真实浏览器/部署证据 → 已完成、部分完成、未验证`。不要只用“完成百分比”掩盖未通过的租户隔离、真实模型或恢复演练。

## 后续阶段入口

ERP 首客试用稳定后，以同一方法为 CRM、MES 分别建立迁入清单和验收集。CRM 接入前解决 Q-003 的客户/商机字段归属；MES 接入前解决 Q-004 的产品—物料映射。三应用全部稳定后，再启动建筑行业首客需求，不把原始建筑草案直接当新版本任务列表。
