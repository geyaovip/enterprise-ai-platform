## 已确认的决策

| ID | 决策 | 影响 |
| --- | --- | --- |
| D-001 | 建设共享企业 AI 平台；业务应用用普通代码开发，不做通用低代码 APaaS。 | 平台/应用边界与技术选型 |
| D-002 | 先建平台，再从零开发统一架构下的 ERP、CRM、MES，之后开发建筑行业应用。旧应用仅供功能与规则参考。 | 路线图与新建方式替代旧应用迁入和建筑先行顺序 |
| D-003 | ERP 是首个真实客户试用应用；没有“内部演示版”交付目标。 | 验收、模型质量、运维和安全均按客户试用要求设计 |
| D-004 | 首批采用共享云服务，架构考虑客户专属部署。 | 租户隔离、配置与基础设施抽象 |
| D-005 | 三套新应用完成并验收后，才考虑移除旧项目。 | 新应用开发和客户切换期间旧系统必须保留 |
| D-006 | 先设计、开发统一的整体架构和公共模块；ERP 开发时判断哪些能力属于公共模块、哪些属于 ERP 领域。旧三套代码与数据库仅供参考，不作为新项目组成部分。 | 公共模块、领域边界与统一技术架构先于业务开发 |
| D-007 | 平台提供可通过受控 Tool 执行业务操作的 AI 聊天框，而不只是问答；适合的业务模块也尽量嵌入上下文 AI 能力。 | 对话操作与模块 AI 共用权限、业务 Service 和审计；逐场景定义可执行动作与验收 |
| D-008 | 2026-09-29 确认：新 ERP 按旧 ERP 当前已实现的功能范围重新开发，并遵守统一架构；旧系统未实现的能力不自动纳入。旧 AI 已有代码但真实模型质量未验收，须在新系统重新验证后才能对客户开放。 | 首客 ERP 范围同时包含采购、销售、库存、账款、主数据和现有 AI 场景；新平台可执行聊天另按 D-007 实现。详见 [13 盘点](13-三应用业务能力清单与领域归属.md)。 |
| D-009 | 2026-09-29 确认采纳审慎共享原则：平台技术能力统一建设，业务能力默认由应用拥有；跨应用或行业共享须有真实复用、明确所有者和评审证据。 | Shared Business 与 Industry Shared 不在首期预建；ERP 自有模型可先开发，跨应用关联或提升共享按 [14 准入规则](14-共享能力准入与模块公开契约.md) 决定。 |
| D-010 | 开发前固定平台稳定 OrgUnit/成员组织关系及可信 AppContext；原定知识先定检索与引用接口，具体 Provider 按真实用例建设。 | 组织和 appId 从首期进入权限、AI 与审计；知识实施范围后由 D-016 扩展为完整产品。 |
| D-011 | 技术栈与验证门槛按 [ADR-001](ADR-001-技术栈决策.md) 执行。 | M1 固定确切版本并验证 NestJS/Prisma、迁移与同库事务；未经验证不宣称代码可运行。 |
| D-012 | 2026-09-30 确认：后续新应用围绕真实业务事件设计“发现、核对、行动、跟踪、关闭”的可验收闭环；应用拥有由此形成的业务状态，可按具体场景使用内置、平台内其他应用或客户已有系统的数据。跨系统连接和行业 AI 共享能力按真实消费者逐项建设。 | [10 后续应用闭环准则](10-应用接入契约.md#后续新应用的-ai-业务闭环)；不改变 Platform → ERP → CRM → MES → 架构复盘 → 建筑应用的顺序，不将建筑场景或通用连接平台加入 ERP 首客范围。 |

## 当前开发收尾口径（D-022）

- 当前生产使用内置 PostgreSQL + pgvector 知识库，包含混合检索、结构分块、本地规则重排序及中英文 OCR。RAGFlow Cloud 是暂缓的可选接入，不作为当前知识产品完成条件。
- 当前工程证据：一名成员已开通生产 Runtime 并通过真实模型/Tool/内置知识联合验证，ERP 完整性及增量流程已有正式多账号写入回归。其他成员配置、容量、外部值守通知和实际线上入口回退仍需各自验收；当前结果见 [41](41-六批优化交付与线上验收.md)。
- 生产定时备份暂缓；已有手动数据库＋知识原件联合备份和独立恢复证据继续保留。真实客户数据、业务规则、打印模板及资料质量测试由用户后续安排，不与本轮工程完成状态混写。
- “成员 AI 执行环境绑定”指平台运营将有效成员关联到其独立 OpenClaw Gateway 地址、加密访问凭据及助手标识。平台按当前成员选择执行环境；每次 Tool 调用仍由平台重新鉴权并经过业务 Service。知识引擎按企业配置，两者分别开通。

历史 V3.1 规划及后续 GPT 建议的 AI 体验范围见 [22](22-AI体验与首阶段Agent策略.md)；V3.6.1 两份规划的初次评审及用户后续修订见 [23](23-V3.6.1规划采纳评审.md)。规划文字本身不是决策；**D-016 是用户本轮直接确认的新增范围和技术选择**，不再按 D-015 的候选选型门槛处理。
