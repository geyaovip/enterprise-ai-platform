# BOM原生映射与来源复核优化

2026-10-29，D-118。依据用户对D116报告的授权，修复已经复现的原生表头、字段归位、表格角色和人工核对问题；同时完成[D117 Skill对照](117-BOM识别Skill与四模型对照.md)。**本地实现，未部署、无业务结构迁移，未改线上聊天模型/额度，未向业务知识库导入测试资料。**

## 已实现的改动

1. **原生表头与字段归位**：增加料号、线束名称、Product name、Manufacturer Part等精确别名；有明确产品名称时Description进入规格，电子导出的PartNumber按列上下文归为来源MPN，普通机械件号仍保留原身份。Comment、Value、封装、规格、长度、连接器和端子独立保存；冲突不串列、不从标称值猜MPN。
2. **多机型数量**：保留原列名和每个值，包括0/空白。未选机型时没有单一用量；界面显式选择数量列，0行默认排除，空白留待核对；切换机型撤销行/装配审核和历史选择。服务端校验列存在、来源值一致、核对快照绑定机型。缺量或更改该列用量须填写核对依据。
3. **表格角色与区域**：单零件图的热处理/表面处理/图纸代号标题栏不再当明细。支持带明确序号的底部表头，保留原行号/坐标并停止把表后的标题栏读成物料；裁图仅缺底边时有界读取一个边缘表头区域，不臆造表格。底部表头先前未识别列类型的数量也执行数字复核门槛。
4. **数量与单位**：低置信数量不默认1。弱数字识别遇到`8PCS`、`260MM`或`A/R`时，以两种实际不同缩放重读完整原文，避免数字白名单擦掉单位。数字与单位须一致识别；`A/R`仍没有定量。显式零数量默认排除；若人工改变零数量，前后端均要求重新核对和说明。明确`NC / 不装`等排除状态不能进入装配用量。
5. **不完整读取可见**：整个文件0表显示“未确认”，不推成“没有零件”。工作簿只认出部分工作表也给出具体工作表名。公式缓存不采用，公式提示限定在相关行，避免汇总公式让其他行/工作表全部误报。
6. **人工处理与历史证据**：原始位号直接显示，`!PCB1`等异常格式保留原文并要求核对；规格/长度/连接器/端子分开展示，列映射可查。0表或部分未识别可按原件建立人工核对组、填页/工作表/行号及补录说明，再补漏行；不重复自动建组。上述字段、机型和列映射随来源存入BOM行的既有JSON字段。历史参考进一步检查规格、长度、Comment/Value、连接器/端子和适用机型，不复制历史数量。

所有OCR候选和工程字段有疑点的原生行都进入核对；来源文字层置信100不能跳过字段/角色检查。人工采用只填入草稿，发布仍走原有BOM审批与业务校验。
