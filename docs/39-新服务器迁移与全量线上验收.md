- 冻结旧服务后联合备份并恢复；69 张表、1,533 条迁移记录的逐表数量与完整 JSON 行摘要全部一致。
- 新服务器上线后完成 419 次公开 HTTPS 回归请求，包含预期权限拒绝、输入校验和并发冲突；无非预期 5xx。
- 真实浏览器跨账号完成采购提交、待办/通知接收、审核、两批入库、应付形成、完成通知及待办移除。

- 新增 11 个独立假数据企业、50 个测试账号；原企业 33 张业务/管理表和原账号密码摘要保持一致。
- 停写后手动备份并重启数据库及服务，69 张表、6,108 条当时记录的完整指纹一致。该备份另外恢复到隔离数据库，69 张表指纹再次全部一致；隔离库已移除。

本轮没有将 AI 配置问题、外部办公渠道真实送达、真实客户接受度或长时间容量压测记为通过。

## 持久化、备份与恢复

1. 旧服务器停写，冻结状态联合导出 DB 和知识原件，校验后在新空库恢复；69 张表完全一致后启动应用。
2. 测试完成后再次停写，手动导出 DB、知识原件、Runtime 状态及受限环境恢复材料，生成 SHA-256 清单；归档列表可读，文件完整校验通过。
3. 重启 PostgreSQL，在 API/Worker 仍停止时重新计算 69 张表指纹，与重启前 6,108 条记录完全一致；再启动 API/Worker/Gateway。
4. Gateway 冷启动超过最初测试脚本的 60 秒等待；随后 `/readyz` 返回 200、Docker 状态变为 healthy，OOM 为 false。维护脚本等待上限已改为 180 秒。没有再次重启数据库或重复迁移。
5. 公开健康接口恢复 200/database ready；原企业 33 张表及账号密码摘要不变；浏览器完成采购单经公开接口再次核实。
6. 将最新手动 DB 备份恢复到独立 `qa_restore_migration_20261011_0825` 数据库，69 张表、6,108 条记录摘要与备份时状态一致；只删除该隔离库。
7. 手动联合备份已转移本机，5 个清单条目的 SHA-256 均一致；专属 Tunnel 的配置、凭据及 systemd 单元另外以受限归档保存。

没有设置生产定时备份。备份时刻之后继续发生的新写入必须在未来恢复或回退前重新冻结、导出并转移。

## 当前 AI 边界

原成员预备 Gateway（OpenClaw 2026.9.7）已迁移，位于独立 Docker 网络、没有宿主机端口，内存上限 1 GiB。带受控 `erp__customer__create` 客户端工具声明、明确不调用工具的真实模型请求返回 HTTP 200 / completed / “模型连接成功。”，记录见 [Runtime 回执](../output/migration-20261011/runtime-inference-receipt.json)。

**生产平台 AI 仍未开通：当前没有生产成员 Runtime 绑定，`AiExecution` 仍为 0。** 单 Gateway 的真实模型连接不等于平台聊天、Tool 执行、权限、知识引用联合闭环验收。未提供任何 ERP 工具声明的 Gateway 请求会被现有 `erp__*` 工具白名单拒绝；没有放宽工具策略。

RAGFlow Cloud、真实客户场景和生产定时备份继续按原决定暂缓；本轮按用户指示忽略 AI 配置导致的不可用功能。飞书/钉钉/企微外部送达与多成员 AI 并发容量没有被本轮非 AI 回归替代。
