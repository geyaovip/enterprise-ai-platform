# 复杂扫描、照片与完整装配图：GLM扩测及OCR价值评估

2026-10-30，D-127。本轮按用户要求以GLM为主扩大测试，评估错料、错量、漏行及OCR的实际收益，并完成本地优化。**新增29次真实调用：GLM 27次、Kimi 2次；98,591 Token，公开价估算¥0.4731，0重试、0未知用量。未部署本轮业务代码或改变线上模型配置。**

## 结论

- **GLM适合主力提取，不能免人工核对。** 24个主测输入中，351条明细的指定字段严格匹配339条（96.6%）。12条失分中，5条是身份原文字符丢失/改写，7条是同一原单元格被拆入名称和MPN、可无损重组。后者不应被说成7条物料全错。
- 本轮GLM主测没有漏行或非空错量：单数量252/252、机型数量单元格198/198，两个无BOM对照均未造行。这个结果只覆盖已标注字段，不包含全部描述、单位、隐藏零件、采购完整性和多层装配关系。
- **Kimi对定向难例仍有价值，但本轮不支持把它作为普遍默认。** 两个GLM失分输入的31行由25/31升至31/31，其中修复3处字符原文问题和3处字段拆分。它们是按失败选择的难例，不是独立随机模型排名。
- **OCR对这批实际模型错误的检出收益很低，不宜成为复杂图纸的强制步骤。** 95份历史回执与29份新增回执共124个结果、2,287条输出行中，有30条已标注身份原文错误和1条非空错量，当前生产OCR及本地优化版都没有具体检出。旧业务裁剪照片中的`7→1`仍未被补救。没有自然漏行错误，不能计算实际漏行检出率。
- 本地优化消除了原OCR的两次数量误报（同一张图的两份模型结果），增加对齐覆盖；它没有提高本批模型的原始正确率。建议GLM优先，Kimi保留为有原因的复核选项，OCR作为可关闭的辅助。若取消Kimi，需要接受更多人工核对；不能把节省费用说成质量不变。

### 实际错误与提示词对照

典型字符问题：`10-32 X 1 1-8IN - 91772A832`丢了一个`1`；`10-32 X 2-25IN`被写成`10-32 X 2.25IN`。即使供应商编号仍对，也不能宣布原文正确或未经核对就采用尺寸。这是潜在错料风险，不是已经发生了真实客户物料选错的证据。

另有7行把一个源单元格拆为名称和MPN。严格保留单元格的评分仍扣分，但单独标为可无损重组，避免和字符错读混算。缺件号的单独横线按“无身份编码”评分，机型数量里的横线、空白和0仍严格区分。评分说明保存在`scoring-notes.json`，原冻结标签没有改写。

针对三个不同失分输入，仅追加一次短规则复核，要求机械Part Number整格保留、不把连字符改为小数点；与Kimi对照图片不重叠。GLM为37/41→39/41，只解决Vent的两行拆分，两个Handle字符错误仍在。因此保留实验结果，**没有把长Skill或此短规则全量注入业务提示，也没有回写主测339/351的原成绩**。

## OCR到底帮了多少

同样的63张不同图像，分别运行发布版OCR和本地候选；复用相同模型回执，不额外请求模型。124个结果包含不同模型、历史提示配置及同源复核，不能当作124个独立盲测。历史D113的字段诊断保留其旧格式限制，不冒充当前生产schema验收；此前未知用量记录未删除或重试。

| 指标 | 发布版OCR基线 | 本地优化后 |
| --- | ---: | ---: |
| 本地OCR图像 | 63 | 63 |
| 有观察 / 部分观察 / 不可用 | 19 / 2 / 42 | 19 / 2 / 42 |
| 模型输出行（含重复对照） | 2,287 | 2,287 |
| 唯一对齐行 | 491 | 533 |
| 序号/数量两列一致行 | 360 | 338 |
| 具体检出的已知身份原文错误 | 0/30 | 0/30 |
| 具体检出的已知非空错量 | 0/1 | 0/1 |
| 本批自然漏行 / 漏行提示 | 0 / 0 | 0 / 0 |
| 数量冲突误报 | 2次，同一输入 | 0 |
| 单图中位耗时 | 2.41秒 | 3.75秒 |
| 单图最大耗时 | 15.34秒 | 12.68秒 |

对齐更多、一致更少，是收紧置信要求后的覆盖变化，不能称为准确率提高。OCR“序号/数量一致”也不能证明身份正确：优化后仍有1条已知身份错误同时得到两列一致提示。低清、复杂透视、无可靠网格、多机型列或身份置信不足时，大量结果保持未核验。

第一版身份提示实验曾因连字符顺序、字段拆分及`0/O`产生错误提示，已保留失败结果。优化后按图像几何排列短标点、核对页面/局部两次OCR读值，易混淆字符降为未判定，不选择恰好与模型一致的读值。两次OCR仍是同一引擎对同一原件的不同读取，可能同错。

另外用实际Vent图的OCR观察，**人为改变一份已保存答案**：错数量、错身份、删行、错序号均能在满足对齐/置信条件时标疑；乱序不会误配，低置信读值会放弃判定。它只证明检查器在适用条件下可工作，不是本轮真实模型又犯了这些错误，不能加进实际检出率。

建议保留OCR的数量/序号辅助能力及原文证据，但允许关闭。复杂扫描/照片不建议强制等它完成；也不建议为OCR疑点自动追加大模型。后续只有在独立真实错误集上证明检出收益和误报可接受，才扩大默认覆盖。

## 已做的本地优化与后续优先级

已实现：

1. OCR短标点按几何行正确排序，数量两尺度置信度采用更保守口径；最多两次源表格局部读取，身份提示要求同字段、两次高置信读值和至少两个其他同表锚点。字段无损拆分不当作错料，`0/O`等差异不据此直接判定冲突。不自动改料、改量或补行。
2. 补充来源身份对照显示，未核验与已关闭OCR明确提示，保留全部原件复核门槛及旧快照兼容。
3. 增加`BOM_VISION_GLM_FIRST=true`：新页优先GLM，密集、印刷跳号/重复和普通字段缺失作为人工提示，不单独触发付费复核；结构无效或明确无法辨认时才允许一次Kimi。人工复核仍受次数/用量防重约束。
4. 增加`BOM_VISION_KIMI_ENABLED=false`：可完全停止新Kimi调用；结构失败直接转人工处置，不换模型循环。增加`BOM_VISION_OCR_ENABLED=false`：可跳过新的本地OCR计算，显示未核验。已有缓存证据保留。**默认值保留原策略，本轮未在生产启用这些开关。**

接下来更值得做的是：扩大不同来源真实手机纸图、低清扫描和中文小字盲样；优先取得原PDF/高清表格区域，而非把低分辨率图片放大后当新证据；保留原单元格与结构字段的独立通道，针对尺寸/版本字符做复核；为跨文件多层装配补明确图号、版本及父子倍数的人工映射标准。

人工流程继续使用现有的原图定位、逐行核对、补行、暂存与任务历史。历史库可以沉淀经审核的别名、列映射和纠错经验，并限定企业/产品/版本；不能用相似件历史数量补本图未知量，也不能把未审核模型答案入库后再当证明。本轮未新增自动历史学习或知识入库。
