# 迁移与上线验收

旧 CRM、MES、ERP 已在独立环境运行。新平台接入是受控迁移：先实现通用平台，再把每套应用的业务 Service 和数据带入自己的新应用运行单元；不把旧后端和数据库互相合并。旧系统持续可用，直到对应应用在新平台完成真实客户试用、数据核对和回退验证。不得因为新代码能启动就删除旧项目。

## 每套应用的迁移步骤

1. **盘点**：列出现有业务对象、角色、API、页面、迁移版本、数据量、文件与 AI 配置；记录新旧差异和不能自动转换的数据。
2. **映射**：确定新租户/成员/角色与旧记录 ID 的对应表，明确本应用领域数据的所有者、唯一键、状态、金额精度和历史审计如何处理；跨应用同名客户/产品分别保留 ID，未确认字段级归属前不自动合并。
3. **试迁移**：在独立环境用脱敏数据或经客户授权的数据执行，比较记录数、金额、库存余额、关联关系和样本操作；重复运行不产生重复对象。
4. **并行验证**：新旧环境按同一验收集核对；双写只有在冲突处理与补偿设计完成后才能采用，默认以明确切换窗口和只读/增量策略处理。
5. **切换**：确认备份、迁移日志、负责人与回退窗口；向客户说明访问入口变化；切换后验证真实账号、角色和关键读写。
6. **观察与退役**：保持旧环境和备份到观察期结束。由客户/项目负责人确认新平台验收及数据可恢复后，另行决定旧环境退役；本计划不授权自动删除。

具体数据迁移脚本与切换窗口依赖 [Q-002](00-文档索引与决策记录.md#待确认的决策)。如果首客是新租户空库，也必须验证初始化、导入客户主数据和备份恢复；不能用演示数据当客户数据。

## ERP 首客试用准入

| 类别 | 必须具备的证据 |
| --- | --- |
| 产品 | `ERP-01`～`ERP-07` 的保留范围或经客户明确接受的差异清单；无假入口、假数据、未接通连接。 |
| 身份与隔离 | `AC-01`～`AC-05`、`AC-15` 在共享云真实入口通过；双租户、跨角色、跨对象和 AI 越权用例通过，应用服务拒绝伪造上下文。 |
| 业务 | `AC-10`～`AC-13` 在独立验收租户中通过；库存、账款和单据可重启后重核对。 |
| AI | 聊天读/写 Tool 与已启用的模块 AI 通过 `AC-06`、`AC-07`、`AC-14`、`AC-16`、`AC-17`；真实模型、样本来源、操作回执、错误/超时、权限及业务持久化结果均有记录。未启用能力明确显示，不用模拟建议。 |
| 数据 | 空库开通或迁移核对完成；客户数据处理、密钥、备份保留、导出/删除方式已约定。 |
| 运维 | 公网入口、HTTPS、就绪检查、告警、受限备份、恢复演练、发布回退与支持联系人均已验证。 |

这些是**试用准入**，不是正式长期交付或合规认证的自动结论。验收记录要写环境、日期、操作者、数据类型、证据链接、失败项和后续负责人。

## 后续 CRM/MES 与建筑应用

CRM 接入需保持线索到客户/商机、跟进和客户服务的权限与数据流；与 ERP 客户/商机的字段级归属和同步方案按 [Q-003](00-文档索引与决策记录.md#待确认的决策) 确认。MES 接入前按 Q-004 确定与 ERP 的产品—物料映射、单位及主数据归属，不能让 AI 推断不存在的跨库关系。建筑应用另立行业需求与首客试用计划，不直接采用原始草案的建筑 V0.1 Definition of Done。
