用私有环境设置 `OPERATOR_EMAIL`、`OPERATOR_PASSWORD`（至少 12 位）及可选 `OPERATOR_NAME`，执行 `pnpm --filter @suite/api bootstrap:operator`。命令拒绝给已有账户自动提权；运营账号默认没有企业成员身份。运营端创建企业及首位企业管理员，再配置/交付 ERP、AI、企业知识；企业管理员可停用已获能力，不能交付平台未授予的能力。

## OpenClaw 成员实例

开发脚本不会改全局 OpenClaw 配置。官方包安装在忽略目录；每个实例写入 `var/openclaw-members/<membershipId>`，私有配置和导入凭据文件为 0600。

```bash
npm install --prefix var/openclaw-runtime --no-save --registry=https://registry.npmjs.org openclaw@2026.9.7
# 在私有环境文件设置模型地址、模型 ID、API Key 和不冲突的成员端口。
node --env-file=.env.ai-components infrastructure/openclaw-member.mjs init MEMBERSHIP_UUID
node infrastructure/openclaw-member.mjs validate MEMBERSHIP_UUID
node infrastructure/openclaw-member.mjs start MEMBERSHIP_UUID
```

从该成员的私有 `binding.json` 将地址、Token 与 `erp-assistant` 导入平台运营配置，不能将该文件提交 Git 或复制到对话。开发绑定 loopback；容器里的 API 无法用自身的 `127.0.0.1` 访问宿主成员实例，生产需改为允许名单中的私有网络地址并独立隔离成员容器/主机。

当前配置关闭内置终端、CLI Agent、Cron、Hooks、Skills、提升权限、URL 文件读取、ToolSearch 和 CodeMode，只允许平台显式提供的 `erp__*` Client Tools。每次执行使用新 Gateway Session Key，并仅发送平台重新授权的历史；权限已撤销的内容不能从 Gateway 旧记忆重新进入回答。平台保持稳定会话、动作、业务回执、审计与用量。

程序生成的专用 smoke profile 为 `00000000-0000-4000-8000-000000000001`，端口 18790；下游模型仅为 4899 的测试 HTTP 服务。`test:openclaw` 启动该官方 Gateway 并验证就绪、回答、Client Tool 返回和内置工具隔离，结束停止自身进程。它没有实际调用真实模型，也不将 Tool 请求直接写 ERP。

生产实例创建/停用/升级、网络隔离和私有状态备份恢复还需目标环境演练。升级先在隔离成员验证相同工具契约；停用先撤销平台能力或配置、排空任务，再停止该成员实例；其他成员和人工 ERP 应可继续运行。不得把本机独立目录等同于生产容器/主机隔离验收。

回退再次保存原适配器、地址、凭据与选项（配置版本继续递增），重新索引并核对权限和引用。当前可替换性测试已实际执行测试适配器切入、原件重建、会话/引用核对和切回；目标环境切流、完整联合数据恢复及运行中故障演练仍待完成。

## 2026-10-08 D-020 内置轻量知识库

新增 `native` 适配器，复用 API/Worker/PostgreSQL，不启动 AnythingLLM、RAGFlow 本地栈、Elasticsearch 或独立向量服务。API/Worker 镜像安装 Python3 与 Poppler；构建时将受限 Office 解析脚本复制到 dist。可用 `KNOWLEDGE_PYTHON_PATH` / `KNOWLEDGE_PDFTOTEXT_PATH` 指定本机可执行文件，容器默认直接使用系统命令。

### 新的独立部署

在项目 infrastructure 目录，先设置私有 POSTGRES_PASSWORD，使用独立 Compose 项目名运行：

```sh
docker compose -p suite-native -f compose.yaml -f compose.native-knowledge.yaml up -d
```

覆盖文件固定 pgvector 0.8.1 / PostgreSQL 17 的镜像摘要，并使用新的 `suite_native_postgres_data` 卷；初始化执行 `enable-native-knowledge.sql`。关系迁移不依赖扩展，旧纯 PostgreSQL + RAGFlow 环境仍可迁移。更换现有生产数据库时不能直接套这个命令：先停写、联合备份 DB/原件/加密配置，恢复至独立 pgvector 实例，核对业务/知识数据后按发布窗口切流并保留旧实例。上述为本地隔离演练；生产已于 2026-10-08 通过独立备份恢复完成发布，当前固定 PostgreSQL 17.11 / pgvector 0.8.7 镜像，详见下面的生产命令及 [21](21-云端发布记录.md)。

### 配置步骤

1. 运营端首次选择“知识引擎 → 内置轻量知识库”，填写嵌入 API 地址、私有密钥、模型与协议。方舟地址为 `https://ark.cn-beijing.volces.com/api/v3`，模型为本轮实连的 `doubao-embedding-vision-251215`，选择火山方舟多模态嵌入；服务端允许名单加入 `ark.cn-beijing.volces.com`。
2. 检查连接后上传公开样本并确认处理/检索/引用。内置索引和原件在平台，但文字与问题发送到云端嵌入服务；完全离线部署需配置经过验证的本地 OpenAI 兼容嵌入模型，本轮未验证本地模型。
3. 添加其他方案或更新模型时，运营端“保存可选方案”，企业管理员在知识库页“准备并切换”。当前引擎继续服务，候选全部就绪后启用；取消/失败清理候选索引，完成后清理旧引擎索引。回退从平台原件重建旧配置。
4. RAGFlow Cloud Key 私有保留；因用户暂不升级套餐，本轮仍待实连，不把测试替身当作 Cloud 成功。

隔离测试：`pnpm --filter @suite/api test:native-knowledge` 仅允许 `127.0.0.1:54339/suite_native_qa`，不会访问生产。真实方舟公开样本脚本 `apps/api/tests/native-knowledge-ark-smoke.cjs` 要求私有 `NATIVE_EMBEDDING_KEY` 与同一隔离库。具体证据见 [31](31-轻量知识库与多引擎.md)。
