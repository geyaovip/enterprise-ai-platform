# UI 与交互规范

本规范是新平台的**设计目标**，尚未经过页面视觉和设备验收。优先保证企业用户能找到业务对象、理解状态、核对 AI 依据并安全完成操作。应用可以有自己的业务密度，统一身份、导航、表单、反馈和 AI 交互。

## 信息架构

- 登录后先确定当前企业；只属于一个企业时可直接进入应用。企业与应用切换在统一 Shell 中完成，当前企业和应用始终可见。
- 左侧为平台/应用导航，主区为业务内容；企业管理仅对有权成员显示。ERP 保持经营概览、客户、商机、销售合同、产品、供应商、采购、库存、应收应付的清晰入口。
- ERP 库存页的预警页签让采购、仓库和管理员看到相同的实时数量、在途采购单和最近入库回执；仅采购及管理员能从预警带入采购草稿，仅仓库及管理员能执行盘点。带入的建议数量需要核对，不自动保存、确认或入库。
- ERP 客户页将“我的客户”和“客户公海”明确分开；公海领用失败提示已被领用并刷新列表。商机页显示不可覆写的跟进时间线，可记录下一次跟进时间，但自动提醒必须等站内待办功能实现后再展示为“提醒已设置”。采购详情打印件标明草稿/确认状态，不显示页面导航和 AI 面板。
- 采购/销售详情按角色显示“提交审核”或“审核通过/退回草稿”，必须展示待审核状态、当前版本和退回原因输入。未审核状态不提供出入库按钮；管理员直接确认自己的草稿需明确标示这是特权操作并留审计。退回后编辑和站内审核待办尚未实现，页面不得暗示可以修改或已通知审核人。
- 平台有可直接进入的 AI 聊天框，既能提问，也能通过受控业务 Tool 执行用户要求的操作；业务列表、详情和表单中也提供与当前对象相关的 AI 操作。业务页面保持完整可用；AI 不替代确定性数量/金额计算。
- 页面与聊天回执使用所属应用的业务术语。跨模块引用时标明对象所有者、来源和链接；只有经确认属于同一业务主体并建立关系后才展示合并视图，不把不同主体仅因同名合并。
- 项目内页面使用稳定的面包屑或返回路径；详情刷新和复制 URL 后仍可定位同一对象。

## 视觉基础（第一版建议值）

| Token | 值 | 用途 |
| --- | --- | --- |
| `color.brand.600` | `#1D4ED8` | 主操作、当前导航 |
| `color.brand.50` | `#EFF6FF` | 主操作浅背景 |
| `color.text.primary` | `#111827` | 标题与正文 |
| `color.text.secondary` | `#4B5563` | 说明、辅助信息 |
| `color.border` | `#D1D5DB` | 表格、表单、分隔 |
| `color.surface` | `#FFFFFF` | 卡片、表单 |
| `color.canvas` | `#F8FAFC` | 页面背景 |
| `color.success / warning / danger` | `#166534 / #92400E / #B91C1C` | 状态文字，必须同时配文字或图标 |
| `space` | `4, 8, 12, 16, 24, 32px` | 间距基线 |
| `radius` | `6px / 10px` | 控件 / 卡片 |
| `type` | `12, 14, 16, 20, 24px` | 注释、正文、标题层级 |

颜色不单独承载状态；金额、数量和状态标签必须有文字。正文常规最小 14px，密集表格可用 12px 辅助文字但关键数据不得依赖小字。将颜色、间距、字级实现为设计 token，不在每个应用中复制魔法值；品牌视觉正式确定时集中调整。

`packages/ui` 先放设计 token 与无业务语义的 Button、Input、Table、Modal 等基础组件。活动时间线、审批面板、AI 洞察卡等业务组件先由应用拥有；第二个真实场景出现后比较交互和权限语义，再按 [14 共享准入规则](14-共享能力准入与模块公开契约.md) 决定是否抽取。统一 Shell 不意味着通用页面生成器。

## 布局与响应式

- 大屏使用 240px 左侧导航，内容区最大阅读宽度约 1440px；高密度表格可以在内容区横向扩展，不将金额挤成不可读的多行。
- 768px 以下导航改为抽屉；手机不保留悬空桌面侧栏，遮罩可点击关闭，`Escape` 可关闭，焦点回到触发按钮。
- 手机业务列表优先信息卡片或可横向滚动的表格，并清楚标示滚动区域；主要动作保持可触达。AI 辅助面板在手机全屏展开。
- 在 320px、768px、1280px 宽度检查关键页面；不是只检验 CSS 断点，还要实际核对表单、表格、弹窗和关键按钮。

## 核心组件契约

| 组件 | 必须表现 |
| --- | --- |
| 页面标题 | 名称、当前企业/应用上下文、主要动作、必要时显示状态。 |
| 列表 | 搜索/筛选、总数与分页、明确的空状态；权限不足不伪装成“暂无数据”。 |
| 详情 | 来源单据、版本/状态、相关业务对象、审计入口；重要写操作后重新从服务端读取。 |
| 表单 | 必填、单位、金额精度、范围和错误位置明确；离开未保存内容时给出提示。 |
| 确认对话框 | 高影响动作说明对象、后果和不可撤销部分；默认焦点不落在危险按钮。 |
| 状态/通知 | 加载、成功、失败、权限不足、过期冲突、服务不可用可区分；失败保留用户输入和重试路径。 |
| AI 聊天与操作 | 显示当前企业/应用/业务对象上下文及 AI 准备调用的动作；高影响操作展示确认卡。执行后显示处理中、成功或失败的真实状态、回执及对象链接；清楚区分模型建议、未保存草稿与已完成的业务写入。 |

## 交互规则

- 点击保存后按钮进入忙碌状态，禁止同一请求重复提交；服务端仍必须处理重试/幂等。
- 采购确认、分批出入库、付款、角色变更等动作完成后以服务端新状态为准，不在前端自行推断成功。
- 对金额使用统一货币格式，后端以十进制精度校验，前端不以浮点运算结果作为权威金额。库存数量显示单位“件”。
- AI 失败应给出可重试或继续人工处理的具体入口；“未启用”和“运行失败”分开提示。未验证的外部连接不得出现“已连接”状态。
- 空状态说明为什么为空，并提供当前角色有权执行的下一步；禁止用假零值或演示数据填充真实看板。

## 可访问性与验证

交互控件有可读名称、键盘焦点和可见焦点样式；弹窗有标题并限制焦点在弹窗内；错误信息与对应字段关联。文本与背景对比的项目目标为普通文本至少 4.5:1。完成页面时以真实浏览器核对加载、空、成功、失败和权限状态，再用真实设备或等效浏览器视口核对移动端；文档本身不构成视觉验收。
