## 用户流程

入口仍为四个业务应用共用的“消息与通知”。管理员选择通道，扫码并在官方页面确认，平台自动加密保存连接凭据，不要求客户填写 App ID、Secret、回调地址或安装 OpenClaw。授权由各平台决定；扫码不代表绕过企业的应用审批、发布或可用范围限制。

微信官方接口返回扫码者身份，自动绑定当前操作的平台管理员。飞书、企业微信、钉钉当前采用一次性绑定：成员点击“绑定我的账号”，复制指令私聊机器人，页面自动更新绑定结果。不能根据昵称猜测身份，也不能把任意扫描者直接认作当前平台成员。

已绑定成员选择默认助手，支持 ERP 管家、CRM 运营官、MES 生产官、品牌内容创作官，实际选项按企业开通、成员权限和现有 AI 运行策略过滤。私聊发送“助手”查看可用项，发送“切换 CRM”等指令切换。每个助手分别保留会话，切换不混用业务上下文。

普通提问默认查询，只有“执行：”前缀允许发起现有工具动作。高影响操作仍返回平台确认链接，回到平台后重新鉴权。成员和通道可以分别解绑、断开；确认弹窗说明影响范围。

## 官方来源与复用

| 通道 | 已核对的官方能力 | 本项目实现 |
| --- | --- | --- |
| 飞书 | [官方 Node SDK](https://github.com/larksuite/node-sdk) 的 registerApp、createLarkChannel | 扫码创建机器人、WebSocket 收发；申请单聊读取、机器人发送权限和接收消息事件 |
| 微信 | 腾讯微信团队的 [openclaw-weixin](https://github.com/Tencent/openclaw-weixin)，含公开协议、扫码和长轮询实现 | 直接适配官方 iLink HTTP 协议，保存游标、上下文令牌并发送文字回复；无需每个企业运行完整插件 |
| 企业微信 | [WeCom CLI](https://github.com/WecomTeam/wecom-cli) 的扫码授权；[官方 AI Bot SDK](https://github.com/WecomTeam/aibot-node-sdk) | 官方二维码授权取得机器人凭据，SDK 长连接接收并回复，独立发送主动通知 |
| 钉钉 | [官方 OpenClaw Connector](https://github.com/DingTalk-Real-AI/dingtalk-openclaw-connector) 的设备授权；dingtalk-stream | 官方设备二维码取得应用凭据，Stream 接收消息，官方会话 Webhook / OpenAPI 回复 |

对应源码修订号、适配位置及 MIT 许可保留在 `apps/api/src/modules/platform/third-party/`。SDK 版本固定在依赖和锁文件中，钉钉 registry 的 latest 当前为 `2.1.6-beta.1`，不是未固定的浮动版本。

## 数据与运行

- 两条新增迁移：扩展扫码持久化状态、通道游标、默认助手、按助手隔离的会话、加密消息上下文和模型提交标记；另修正新组合唯一索引的 PostgreSQL 名称。仅隔离 QA 库已应用，生产尚未应用。
- `CHANNEL_ENCRYPTION_KEY` 沿用独立的 32 字节 Base64 AES-GCM 密钥，API 和 Worker 必须相同。接口不返回凭据、上下文令牌或授权轮询令牌。不得将测试密钥带入生产。
- Worker 增加授权轮询任务，四个通道分别处理消息。长连接由单个 Worker 持有；多 Worker 副本上线前须增加分布式连接所有权，不能直接水平复制长连接任务。
- 授权等待、扫码确认、验证挑战、过期、取消、重试和断连均有状态。浏览器仅记住接入流程 ID；刷新后恢复，凭据始终留在服务端。
- 绑定码 16 位、有效期 10 分钟、只能使用一次。外部用户必须绑定当前企业成员；每条查询、执行和缓存回复投递前重新检查成员与应用权限。
- 消息先持久化，再确认接收或推进游标。模型提交有持久化标记；发送重试复用已保存回复，不重新调用模型。不承诺跨平台严格一次送达，极端“已发送但未保存回执”仍可能重复通知。
- 采购与现有 ERP 流转通知扩展到已接入的四种通道，未绑定目标人保留等待状态。页面将上游回执表述为“通道已接收”，不将其等同于手机已读。

## 真实账号验收与发布边界

四个账号都尚待管理员在手机上完成官方授权，然后逐个验收：长连接在线、成员绑定、真实私聊查询、助手切换、一次测试通知、撤权/解绑后拒绝访问。扫码取码成功不能代替这些真实测试。

当前覆盖私聊文字和现有业务通知；群聊、外部对话中的图片/语音/文件理解、媒体原文件投递、朋友圈或公众号运营不是本次实现。品牌内容助手沿用现有工具授权，不因通道接通自动获得额外生成权限。

发布时必须备份数据库、保留旧镜像、应用两条迁移并同步发布 API、Worker、工作区前端；确认加密密钥已配置，通道 Worker 单实例。D-146 的本地界面改动仍保留，不能在未核对的情况下把整个脏工作区标为本次正式发布。
