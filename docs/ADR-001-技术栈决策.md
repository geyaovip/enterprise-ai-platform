# ADR-001 技术栈决策

状态：**已采纳的开发基线**（2026-09-29）。适用于新项目，不要求旧三套应用升级。M1 建仓时必须用实际依赖锁文件和可运行样例验证版本组合；若验证失败，先记录 ADR 修订及原因，再改选型。

## 决策

| 层 | 选型 | M1 目标主版本 |
| --- | --- | --- |
| 运行时与语言 | Node.js、TypeScript 严格模式 | Node.js 24 LTS（工具链至少 24.15）；TypeScript 5.9 |
| 前端 | 一个 React + Vite Web，包含业务 Shell 与 Admin | React 19、Vite 7 |
| 后端 | 一个 NestJS 模块化单体 API；独立 Worker 进程复用同一代码版本 | NestJS 11 |
| 数据 | 一个 PostgreSQL，Prisma schema/Client/Migrate，业务原子操作使用同库事务 | Prisma ORM 7；PostgreSQL 具体服务端版本在 M1 部署记录固定 |
| 工作区 | pnpm Monorepo、唯一锁文件、统一脚本与 CI | pnpm 11 |

不在首期引入 Next.js、另一套 ORM、每应用独立后端/数据库或运行时动态 APaaS 引擎。React + Vite 负责客户端业务界面；服务端数据访问和授权只在统一 API 内。Worker 只处理确有异步需求的任务，不替业务命令完成必须同事务提交的库存与账款写入。

## 依据与版本门槛

旧三应用已有 React/Vite、NestJS、Prisma、PostgreSQL 与 pnpm 的团队经验，但旧代码、数据库及依赖锁文件不迁入新项目。选择当前稳定且能覆盖首客流程的组合。官方资料显示 Node.js 24 为 LTS；NestJS 工具生成器要求 24.15+；Prisma ORM 7 支持 Node.js 24，而 Prisma ORM 8 在本决策日期仍是候选发布，且尚缺少本项目需要的部分查询/事务能力。因此固定 Prisma 7 主版本，CLI 和 Client 不使用无主版本约束的 `latest`。

参考：[Node.js 发布状态](https://nodejs.org/en/about/previous-releases)、[NestJS 运行要求](https://docs.nestjs.com/first-steps)、[Vite 7](https://vite.dev/blog/announcing-vite7)、[Prisma ORM 7 系统要求](https://www.prisma.io/docs/orm/v7/reference/system-requirements)、[Prisma ORM 8 发布状态](https://www.prisma.io/docs/orm/release-status)、[pnpm 安装与兼容性](https://pnpm.io/installation/)。这些是 2026-09-29 的选型依据，M1 仍需核实当时下载的确切版本。

M1 退出前记录 Node、pnpm、React、Vite、NestJS、Prisma、TypeScript、PostgreSQL 的**确切版本**与镜像摘要，提交新项目自己的 `packageManager` 声明、锁文件和运行时版本文件；`prisma` 与 `@prisma/client` 主版本一致。NestJS 11 + Prisma 7 的 ESM 模块设置、PostgreSQL 驱动适配、生成 Client、迁移和同库事务，必须通过干净安装、构建与一条写入/回滚烟测。官方 [NestJS Prisma 配方](https://docs.nestjs.com/recipes/prisma) 是兼容性参考，不能代替本仓库实测。

此 ADR 锁定技术路线。依赖补丁升级走常规验证；更换主框架、数据库/ORM 或不兼容的主版本升级，须有明确阻塞与替代方案，修订 ADR 后实施。
