# 功能与验收契约

> 文档属性：功能契约。规则与验收要求不等于全部能力已实现或已发布，日期证据保留其环境。状态入口：[47](47-项目现状与文档维护.md)；公共UI：[ui/00](ui/00-公共UI规范.md)。

本文件描述新平台的目标能力和验收方法。功能编号在需求、实现、测试和发布记录中保持一致；未完成的功能不得仅因有入口、接口或模拟数据而标为已交付。

当前开发收尾执行 D-022：采用内置知识库，RAGFlow Cloud 和生产定时备份暂缓；使用授权工程样本验证真实生产模型、Tool 和知识链，真实客户场景由用户后续单独测试。下方涉及客户业务样本的准入要求继续留作后续测试，不标为本轮已通过。

## 平台能力

| ID | 功能 | 必须满足的行为 | 主要验收 |
| --- | --- | --- | --- |
| PL-01 | 企业与租户 | 开通企业时创建租户、首位管理员和成员关系；同一用户可拥有多个租户成员关系；停用租户拒绝业务访问。 | `AC-01`、`AC-02` |
| PL-02 | 登录与会话 | 登录、退出、会话过期、密码/凭据管理；租户切换前后重新核验成员状态。共享云中不同租户不能因同邮箱或 URL 猜测而串数据。 | `AC-01`、`AC-02` |
| PL-03 | 组织与成员 | 平台提供同租户 `OrgUnit` 树和 `MembershipOrg` 成员归属；管理员创建/邀请、启停成员、调整组织/角色；至少保留一位有效管理员。跨租户父子/成员关系和组织环被拒；停用、调组织或降权后旧会话的后续请求立即按新权限执行。 | `AC-03` |
| PL-04 | 权限 | 平台权限与 ERP 应用权限分开；服务端对每个查询和写入执行租户、动作及对象范围校验；UI 只负责显示可用动作。 | `AC-02`、`AC-04` |
| PL-05 | 应用入口 | 企业仅看到已启用且自己有权访问的应用；应用菜单/后台模块从应用注册信息展示，不生成任意业务对象。 | `AC-05` |
| PL-06 | 模型与 AI 网关 | 管理员配置/测试模型；密钥只在服务端保存；模型故障有明确状态；记录请求 ID、目标 `appId`、模型、用量和结果状态。专门聊天与模块 AI 共用网关；Tool 使用当前 App/成员上下文、权限和业务 Service。 | `AC-06`、`AC-07` |
| PL-07 | 文件/知识 | 首阶段交付 `KnowledgeProvider`/`RetrievalContext`/`Citation` 与知识空间、文档版本、上传/处理/搜索/引用 UI，按 D-020/D-022 以内置引擎实施文档解析和检索。文件按租户鉴权，内容在发送模型前过滤租户、App 和对象权限并返回可核验来源。 | `AC-08`、`AC-19` |
| PL-08 | 审计 | 登录与权限变更、关键业务写入、AI Tool 操作可追溯到租户、用户、请求和对象；普通用户不能修改审计记录。 | `AC-09` |
| PL-09 | 企业管理 | 管理成员、应用启用、模型状态、审计查询等最小可用后台；不为无真实差异的配置预建空页面。 | `AC-03`、`AC-05` |
| PL-10 | 应用模块注册 | 代码模块以 Manifest 声明路由、动作、后台与 AI 能力；统一 API 注册模块，未启用应用的所有入口拒绝访问。 | `AC-05`、`AC-15` |
| PL-11 | 对话式业务操作 | 从平台导航可进入 AI 聊天；用户可提问，也可用自然语言要求 AI 调用有权应用的受控 Tool 执行操作。执行前显示待确认的高影响动作；执行后返回真实状态、对象链接和回执。切换企业或撤权后不能沿用旧权限。 | `AC-02`、`AC-07`、`AC-16` |
| PL-12 | ERP 首阶段 AI 体验与专业能力 | 单 ERP 租户的企业 AI 入口与 ERP 内入口复用同一个代码定义的 ERP Assistant 能力；至少一个真实 ERP Skill 具有明确输入输出、业务证据与固定评测样本，通过授权 Native Tool 调用 ERP 业务 Service。Agent/Skill/Tool 不建三级类型体系；执行基础按 D-016 接入 OpenClaw。 | `AC-18` |
| PL-13 | OpenClaw 执行基础 | OpenClaw 承载首阶段 Agent/会话/模型运行；平台 API 仍拥有租户、成员、App、Tool 授权、确认、业务回执和审计。共享云的互不信任租户使用隔离 Gateway；现有直接模型链迁移后不与新链并行对客户开放。 | `AC-18`、`AC-19` |
| PL-14 | 企业知识产品与内置引擎 | 平台管理知识空间、文档/版本、Owner、权限、处理状态与引用；内置引擎承担解析、索引和检索，RAGFlow Cloud 保留可选且暂缓接入。Workspace 提供上传、状态、搜索、文档查看和引用跳转；AI 检索前授权且不把业务实时数据当文档索引。 | `AC-08`、`AC-19` |
| PL-15 | Platform Admin | 独立前端交付租户、应用/AI 能力、知识/模型配置及运营审计；平台角色由 API 校验，不能直接越权读取租户业务正文。 | `AC-20` |
| PL-16 | Tenant Admin 与 Enterprise Workspace | 独立租户后台在平台已交付范围内分配组织、成员、应用、AI 和知识访问；员工 Workspace 使用 ERP、企业 AI、知识和真实待办。三端共享同一身份/API 契约和业务 Service。 | `AC-05`、`AC-20` |
| PL-17 | AI Runtime 与知识引擎可替换 | 当前默认采用 OpenClaw 与内置知识引擎，保留 RAGFlow 适配器，通过平台拥有的稳定契约与独立适配器接入。平台保存可迁移的会话/动作/审计、原始文档/版本/权限/引用 ID；外部组件 ID 只保存在映射中。发布配置可选择适配器，并具备数据重建、受控切换与回退步骤。 | `AC-21` |

第一阶段交付 PL-01～PL-17；D-016 已将 PL-07 的完整文档知识实现及 PL-13～PL-16 纳入必做，D-017 增加 PL-17 的可替换边界。任何未实现部分必须在 UI 和对外说明中如实标明。Webhook、SSO、通用集成与复杂角色编辑器只在有客户需求和完整验收方案时追加。

## 新 ERP 功能

| ID | 业务流程 | 保留的关键规则 | 主要验收 |
| --- | --- | --- | --- |
| ERP-01 | 客户、商机、产品 SKU、供应商 | 编号/SKU 租户内唯一；停用后历史可读但不能用于新单；销售只能访问有权的客户和合同。 | `AC-04`、`AC-10` |
| ERP-02 | 采购与分批入库 | 确认后才可按行入库；超收拒绝；单据、库存流水、应付在同一业务事务中一致更新。 | `AC-10` |
| ERP-03 | 销售与分批出库 | 确认后才可按行出库；库存不足整批回滚，超发拒绝；形成应收。 | `AC-11` |
| ERP-04 | 库存与盘点 | 每次变动有单据及流水；并发库存变化时盘点不能覆盖新值；低库存按确定性规则计算。 | `AC-12` |
| ERP-05 | 应收应付与收付款 | 金额大于零且不超过未结清余额；同一账款参考号不能重复；金额与历史可追溯。 | `AC-13` |
| ERP-06 | 模块内 AI | 在采购、销售、库存等业务页嵌入上下文问答、履约分析、文字单据提取和缺料解释；逐模块评估资料整理、草稿与异常分析等用例。按权限取数，AI 结果与确定性计算分开；出入库和记账等关键写入须展示后果、经操作者确认，并经有权业务 Service 执行，不允许模型直接写表或未经确认自动执行。 | `AC-06`、`AC-14`、`AC-17` |
| ERP-07 | 统一成员与角色 | 管理员、销售、采购、仓库、财务角色在统一权限模块中定义；对象范围由 ERP 业务模块执行。旧 ERP 权限仅供需求对照。 | `AC-03`、`AC-04` |

## 验收场景

| ID | 场景和通过条件 |
| --- | --- |
| AC-01 | 从空环境开通企业，首位管理员登录、退出、再次登录；会话过期后受保护页面和 API 均拒绝访问。 |
| AC-02 | 创建 Tenant A/B，同一账号分别拥有不同成员身份；切换租户、直接改 URL/API 参数、AI 会话及文件检索均不能读写另一租户数据。 |
| AC-03 | 管理员创建、停用、调整成员/组织归属后立即验证服务端权限；不能移除最后一位有效管理员。组织父子及成员关联不得跨租户或成环，移动/停用组织不留下越权范围。 |
| AC-04 | ERP 销售 A 无法读取销售 B 私有客户/合同；采购、仓库、财务只能执行各自授权动作；AI 与人工 API 结论一致。 |
| AC-05 | 未启用 ERP 的租户看不到可用入口且直接请求被拒；已启用租户的有权成员可从统一入口进入 ERP 与相应后台。 |
| AC-06 | 未配置、配置错误、超时或返回无效结构时显示真实错误，业务人工流程照常可用；密钥不进入浏览器、日志、审计明文或仓库。 |
| AC-07 | AI 读/写 Tool 为目标 App 重建当前 RequestContext、AIExecutionContext 并调用同一业务 Service；切换应用、撤权或组织变更后旧会话不能沿用旧权限，越权 Tool 被拒并留审计。普通授权操作按业务规则执行；采购确认、出入库、收付款等高影响动作在执行前获得明确确认，并始终通过新 ERP 的业务校验。 |
| AC-08 | 文件与知识功能若启用：跨租户/跨 App/无权对象无法下载或检索；Provider 在内容送往模型前鉴权，每条 AI 引用能追溯到有权来源、版本与定位，点击时再次鉴权。未启用则不展示假入口。 |
| AC-09 | 以请求 ID 从审计记录追溯到操作者、租户、对象、前后状态或安全摘要；普通用户无法篡改。 |
| AC-10 | 创建产品/供应商/采购单并确认，分两批入库；逐批核对实收量、库存、流水和应付，超收与重复单号被拒。 |
| AC-11 | 创建客户/商机/销售合同并确认，分两批出库；核对库存与应收，库存不足整批回滚，超发被拒。 |
| AC-12 | 盘点生成差异流水；并发变更时拒绝过期盘点；低库存状态更新正确。 |
| AC-13 | 分次收付款，余额正确；超额支付和重复参考号被拒；重启后记录仍在。 |
| AC-14 | 在真实模型和经客户允许的业务样本上验证 ERP AI 输出：来源对象真实、确定性数量准确、建议与事实分开、不能编造 SKU/交期；人工可拒绝建议。 |
| AC-15 | 从未注册/未启用 ERP 的租户请求前台、API、后台及 AI Tool 都被拒；伪造请求体中的租户、用户或角色无法绕过服务端授权。三个前端/API/数据库迁移按兼容版本部署，ERP 同库事务、表的唯一写入所有者及模块公开契约有测试约束。 |
| AC-16 | 从平台导航进入 AI 聊天，让 AI 查询有权 ERP 对象，并通过受控 Tool 创建一张采购单草稿；核对草稿确已落库、归属正确、回执与对象链接可用。对需要确认的高影响动作，拒绝确认时不得写入。切换企业、停用应用或撤权后，旧会话和 Tool 不再能读写原对象；模型或 Tool 失败时显示真实失败状态。 |
| AC-17 | 在采购、销售和库存的真实业务页面直接发起对应 AI 用例，系统带入当前对象与版本；结果能回到原业务流程处理。使用真实模型和授权样本验证相较纯人工减少的操作、事实正确性、越权拒绝及失败后的人工继续处理。 |
| AC-18 | 在仅启用 ERP 的租户，从企业 AI 和 ERP 内两个入口以同一用户/对象完成一个真实业务任务；两处使用同一 `erp.assistant` 定义、执行服务、Tool 治理与审计语义。显式指定无权 Agent、停用 App、换租户或撤权后均不能沿用旧上下文。首个候选是文字采购需求提取、主数据核对、人工复核后创建采购草稿。Skill 在正常、资料不足、事实过期、越权和模型/Tool 失败样本上记录输入、工具选择、业务依据、输出及结果；受控写入可确认、拒绝、撤权和幂等重试，业务 Service 回执与持久化数据一致。业务写入后回执故障需显示结果待核实并能对账，不能直接报失败后重复执行。验收不依赖外部 Agent Runtime PoC，也不替代 ERP 全范围验收。 |
| AC-19 | OpenClaw 与内置知识引擎在目标环境实连：互不信任租户的 Gateway、会话和凭据隔离，成员不可跨权限读取会话或调用 Tool；平台撤权在下一次操作生效。授权文档经内置引擎处理和检索，跨租户/无权内容在送模型前被阻断，引用可回到版本与定位；删除、撤权、重新索引、超时及组件故障均有可重复测试。一个 ERP 工程样本任务同时使用 Native Tool 业务事实和企业文档证据，真实模型结果及审计可对账。RAGFlow Cloud 暂缓；真实客户场景按 D-022 后续单独测试。 |
| AC-20 | Enterprise Workspace、Tenant Admin、Platform Admin 三个独立前端部署并以不同角色验收。平台运营方交付或撤销租户能力；租户管理员只能分配已交付能力，不能管理其他租户或平台 Catalog；员工只见有权应用/知识。三端刷新、深链接、手机导航、403/404、退出、租户切换、审计及原 ERP 业务流程回归通过。 |
| AC-21 | OpenClaw、内置知识引擎及保留的 RAGFlow 适配器均经平台契约接入，ERP/前端不引用其私有 ID 或 SDK。使用隔离环境的替身适配器执行同一组会话、Tool、摄取、检索、引用、越权与故障契约测试；保留平台原始文档并能重建知识索引。演练一次配置切换和回退，核对会话/动作/审计及文档/引用的稳定 ID、未完成任务的排空或中断处理、授权与业务回执；记录不可迁移的组件私有状态。此项不要求当前接通 RAGFlow Cloud、第二个真实供应商或运行中无感热切换。 |

以上是功能验收，不替代部署和客户数据开通验收。客户试用还必须满足 [08 数据导入与上线验收](08-迁移与上线验收.md) 的备份、恢复、监控和回退要求。

## D-019 ERP 客户完整性增补（2026-10-08）

稳定验收包 EC-01～EC-09 的领域规则、实现和证据集中维护于 [30 ERP 客户完整性优化](30-ERP客户完整性优化.md)。涵盖原批次退货/退款/冲正、取消关闭/销售变更、期初和预收预付、量价税/账期/信用、多仓与成本、报价/打印、筛选报表、邀请恢复和审批、备份/真实组件联调。EC-01～EC-08 已有隔离与正式业务回归；EC-09 的手动联合恢复、真实单成员模型/Tool/知识与六批工程证据见 [41](41-六批优化交付与线上验收.md)。客户场景、容量、外部值守通知和实际入口回退仍按各自门槛验收，不据此宣称全部企业 AI 场景可用。
