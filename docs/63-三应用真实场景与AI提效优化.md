## 二、本批用户流程

### ERP：资料变成采购/销售草稿

入口：采购单或销售合同的新建/编辑面板，`从资料生成草稿`。

1. 粘贴文字、选择 UTF-8 TXT/CSV，或上传 PNG/JPEG 明细图片。
2. 单次模型请求整理往来编号/名称、商品编号/名称、明确数量、原始单位及资料依据；含税人民币单价明确时一并提取。
3. 服务端在当前企业、有权客户及有效商品内匹配。存在编号时优先精确编号；编号不存在不回退同名商品，重名不自动选择。模型不接收整张物料/客户主数据表。
4. 核对预览，显式采用回填表单。用户继续补充单号、交期、账期、缺失商品和数量，通过原有 Service 保存草稿。

不将总价当单价、不将最小起订量或型号数字当数量，不换算外币，不自动套用不明折扣/税价。数量缺失、单位缺失或与主数据冲突时留空；没有单价时原有商品价格规则仍生效，预览直接提示核对默认价。客户归属、停用、重复明细和金额校验保留。

### CRM：导入匹配与自然语言人群

导入文件上传后，已知且唯一的中英文表头自动写入批次映射，映射版本递增并使旧预览失效；原有手动映射仍存在来源列时保留，更换文件后清除指向不存在列的旧映射。不能将“订单总金额”映射成“实付金额”。同一目标存在多个候选列时留待人工选择。

特殊列可点击 `AI补充字段匹配`：模型只看到**该有权批次的表头及目标字段说明**，不读取电话、邮箱、客户名称或订单行值；结果只能采用空缺字段，保存映射、校验、确认导入仍走原批次链。模型生成期间文件/版本变化则拒绝交付，不能将旧结果用在新文件上。

分群弹窗增加 `描述要找的客户`：文字 → 类型化规则 → 服务端实际预览 → 显式采用 → 原分群保存/运营任务流程。默认窗口及币种来自企业设置，明确“最近N天”的统计窗口由系统按计算时点生成日期，距最近购买N天与统计窗口分开；窗口购买与历史购买分别处理。“高价值”等缺阈值表达不能随意填默认金额。无法用当前字段表达时说明缺项，不以更宽条件代替。真实人数来自 Service，不来自模型。生产 CRM AI 仍须完整题集通过后再开通，本批不改变原闸门。

### MES：图纸明细变成 BOM 草稿

入口：新建/编辑 BOM 的 `从图纸明细或资料整理BOM`。

- 默认使用已有本地中英文 Tesseract OCR 读取 PNG/JPEG 的明细文字，再由当前文字模型整理；不调用云 OCR，不建立知识文档或检索索引。
- AI 返回产品、组件、单件用量、原始单位、明确损耗、父件及原文/明细行依据；无明确信息填空。
- 有效物料按编号或唯一同名匹配。单位冲突不自动换算；缺单件用量不默认填1；未提供损耗留空让用户核对。
- 多层装配不自动拍平成单层；检测到非当前父件的行时禁止整批回填，需分层建立子 BOM。编辑已有 BOM 时，识别产品与当前产品不一致也禁止替换。
- 核对并采用后回到原 BOM 表单；保存仍执行产品/组件/重复/数量/损耗/循环校验，发布仍独立进行。AI 提取不自动创建物料、保存、发布、派工或审批。预览提供原图和行级依据；本批不建立正式图纸附件/版本台账，表单备注只保留2000字符容量内的摘要，不能替代原件留存。

**支持边界**：当前是可见零件明细的辅助录入。图片原图与各行依据可对照，但 OCR/模型可能漏字错列，行号依据也是待核对的识别结果；没有几何解析、隐藏件推断或完整装配识别保证。PDF、DWG/DXF、超过50行的完整拆分、多份图纸合并及真实工厂识别质量尚未验收；不对外称为“任意图纸自动完整拆 BOM”。

## 三、公共交互、权限与用量

三应用共用 `AiIntakePanel`、公共字段/按钮/提示、紫色主题和移动布局。页面直接展示待核对内容，不增加“允许 AI”或能力启用勾选。服务未启用、无权或未配置时可继续手填。

- 生成不创建正式单据/BOM/分群/运营任务；CRM沿用已有持久预览快照机制。用户显式采用才修改当前表单，再通过原保存动作提交。不会生成后直接覆盖人工输入。
- 表单、来源、企业或应用变化时旧结果失效；生成失败保留输入。重复点击由前端 ref 和服务端同成员/应用的进程内互斥防护；后者不是跨 API 副本的分布式限流。
- 先核验应用 AI 权限和目标业务权限，模型返回后由 Runtime 再核验身份、应用、AI能力和权限；领域匹配/预览再次鉴权。无权的模型结果不交付，但已经发生的模型用量仍保留。
- TXT/CSV 与粘贴文本最多12000字符；CRM 分群文字最多2000字符。PNG/JPEG 每次1张、最多2MiB、400万像素且边长不超过4096；拒绝 URL、SVG、伪造 MIME、超限及非标准 Base64。OCR 文字超限拒绝，不静默截断。
- 每次整理一次 Runtime 调用，不加载聊天历史/长期记忆，不循环找工具，不自动重试。复用现有24k输入估算准入和4000输出上限、成员额度及独立账本，记为 `document_extract`。这些是准入/协议上限，不是供应商计费硬保证。
- 图片 OCR 在本机运行，不产生模型 Token；常见表头用规则不产生模型请求。AI 只在用户明确点击整理或补充映射时调用，打开页面不后台调用。

## 四、接口及配置

公共入口：

- `GET /api/v1/tenants/:tenantKey/apps/:appId/ai/intake/options`：图片模式、大小与字数限制。
- `POST /api/v1/tenants/:tenantKey/apps/:appId/ai/intake`：只返回待核对结果；appId 为 erp、crm、mes。

请求：

```json
{"kind":"purchase","source":{"text":"实际采购需求文字"}}
```

ERP kind 为 `purchase` / `contract`；MES 为 `bom`；其 source 支持 `image:{mime,data}`，data 为纯 Base64。CRM kind 为 `segment`，仅接收文字；或 `import_mapping`，传 batchId、version、role，不接收外部传来的文件行值。旧 ERP `/extract` 及任务接口保留兼容。

默认图片路径为本地 OCR，使用已有 `KNOWLEDGE_TESSERACT_PATH` / `KNOWLEDGE_PYTHON_PATH`；生产镜像已包含 chi_sim+eng。仅在真实图片样本验证后，才可设置 API `AI_IMAGE_INTAKE_ENABLED=true` 选择视觉直传；受管 Runtime 还须将**实际验证的模型 ID**配置到 `OPENCLAW_IMAGE_MODEL_IDS`，由策略5声明 model input 并返回应用范围。手工 Binding 必须显式声明 imageInputApps。缺少匹配能力在发模型请求前拒绝，不偷偷降级成纯文字空读。该路径按固定 [OpenClaw 2026.9.7 OpenResponses 协议](https://raw.githubusercontent.com/openclaw/openclaw/v2026.9.7/docs/gateway/openresponses-http-api.md)实现，本批不宣称视觉模型验收通过。

## 六、效果怎样判断

用真实人员同一份脱敏资料，分别记录手填和辅助录入：总耗时、人工修改字段数、漏行/重复行、误匹配物料、未知项正确提示、业务保存成功率及模型请求/Token。CRM 还核对规则与人群是否符合口径；BOM 还核对单件用量、单位、父子层级和损耗。只有样本验证后报告节省比例，不以“代码存在”或合成样本替身结果写提升百分比。
