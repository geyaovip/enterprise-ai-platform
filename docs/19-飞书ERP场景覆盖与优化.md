# 飞书 ERP 案例场景对照与优化

> 文档属性：功能契约。规则与验收要求不等于全部能力已实现或已发布，日期证据保留其环境。状态入口：[47](47-项目现状与文档维护.md)；公共UI：[ui/00](ui/00-公共UI规范.md)。

状态：2026-10-02 按本轮实现更新。来源是用户给出的[飞书案例页](https://ae.feishu.cn/hc/zh-CN/articles/701815393342)及其可读取的[飞书官方案例正文](https://www.feishu.cn/content/7326874920045723652)。案例是场景参考，不是本项目已交付证明；本文的“本机验证”也不等于真实客户试用验收。

## 执行决定

- 首版先完成平台内业务流程，再通过独立的渠道适配器对接飞书、钉钉、企业微信、Telegram 等。业务审批、任务状态、消息投递结果必须保存在本平台；渠道回调不直接写 ERP 表，统一走拥有者命令与授权、幂等和审计。
- 四种渠道的身份、权限和数据能力不同，按客户实际使用范围逐一实现、逐一验收；“预留适配边界”不代表任一渠道已接通。平台内通知不能以浏览器提示或一次 HTTP 成功冒充可靠送达。
- 案例中提到的“开票”先区分开票申请/登记与法定电子发票开具；未接税控或电子发票服务前只能实现内部申请、审核、登记与状态追踪，不能标记真实发票已开具。
- 案例中“采购确认即生成应付”与现有“按真实入库形成应付”的会计时点不同。当前应付保持实收批次口径；采购审批后形成采购承诺额，不能伪装成已发生应付。变更此规则需真实客户财务口径确认。
- 客户公海、商机跟进仍由 ERP 拥有。未来 CRM 同一性按 Q-003 评审；不因案例先建共享 Party。

## 17 个场景对照

“覆盖”只表示存在业务等价能力且已按现有测试验证；“部分”表示缺少案例中的关键动作或渠道。“待做”不能算覆盖。编号沿用案例顺序，第 10 项的采购变更单独列出。

| 场景 | 当前情况 | 依据和下一步 |
| --- | --- | --- |
| 1 工作台入口、公告通知 | 部分 | 统一入口、经营概览和从实时业务状态生成的“我的待办”已有；公告发布/撤下、阅读回执与持久站内通知已实现和本机验证；外部可靠投递仍待验收。 |
| 2 客户公海与领用 | 本机新增，部分 | 管理员可新建未分配客户，销售可见公海并原子领用；同一客户并发只一人成功。管理员可将无关联业务客户退回公海，或把客户及关联商机/合同转派给在职销售；有待审事项时阻止转派。自动分配和逾期回收待做。 |
| 3 客户管理与关联商机 | 覆盖 | 客户 CRUD、负责人范围及客户关联商机已有；客户联系人目前只有单个基础字段。 |
| 4 商机阶段与跟进 | 本机新增，部分 | 阶段、带时间戳的跟进记录与下次跟进时间已有；到期记录会出现在负责人“我的待办”，记录新跟进后旧项消失。到期站内通知由 Worker 自动生成并去重，2026-10-07 隔离 QA 通过；外部渠道推送仍待真实授权验收。 |
| 5 商机转销售单/合同及审核 | 本机新增，部分 | 商机可选关联合同，金额由服务端逐行汇总；销售提交、管理员审核/退回及原发起人编辑退回草稿已实现。采购/销售提交和审核的持久站内通知已补；商机页创建合同会按当前授权重新读取来源并带入客户/商机；销售创建、编辑保存和 canonical 关联/金额回读已经浏览器验证。 |
| 6 审核后合同、开票与应收 | 部分 | 合同和实发应收已有；不自动以审批代替出库。已确认合同可发起内部开票申请，但登记不自动形成应收。 |
| 7 财务开票、申请人同步、合同开票状态 | 本机新增，部分 | 销售申请、财务登记/退回、申请人撤回、内部作废记录和状态追踪已本机验证；持久处理通知和合同详情申请/登记/作废金额汇总已补并本机验证；真实税票服务未接。页面不会声称法定发票已开具。 |
| 8 销售发起收款、财务认款/分摊 | 本机新增，部分 | 财务人工登记已核实到账，销售认领本客户并可分摊至多笔应收，财务待办确认后原子冲抵与留收款回执；API 和双角色浏览器闭环已验证。尚缺销售预报收款、银行自动导入、已确认分摊冲销与真实客户对账。 |
| 9 供应商管理 | 覆盖 | 供应商建档、修改、停用与采购引用已实现。 |
| 10 采购提交、经理审核、任务/日程、上级关注 | 本机新增，部分 | 采购提交、管理员审核/退回、发起人与审核人分离及未审禁入库已实现；当前审核会出现在管理员实时待办。持久任务指派/完成/取消/重开与截止时间、采购审核通知已补；经理专职角色、完整日程和关注人待做。外部渠道留后续。 |
| 10b 审核后一次变更及再次审核 | 本机新增，部分 | 原发起人可对已确认且未收完的采购单申请修改现有行数量/备注，管理员再次审核；待审暂停入库，已收数量与应付不倒退，批准最多一次。API 和采购/管理员浏览器闭环已验证；增删行、换供应商、改单价不在当前范围，真实客户变更口径待核。 |
| 11 审核采购单自动生成应付 | 口径不同 | 当前按实际入库金额在同一事务形成应付；采购确认仅表示承诺，见上方执行决定。 |
| 12 收货员验收入库 | 覆盖 | 仓库分批入库、超收拒绝、库存与应付原子更新；质量验收/拒收单未做。 |
| 13 管理员上架增加库存 | 部分 | 收货确认直接增加库存并留单据、流水；没有独立“待上架→上架”状态，需真实仓储场景验证是否必要。 |
| 14 销售订单出库、库存不足拦截 | 覆盖 | 仓库分批出库；不足、超发与并发冲突阻断，库存与应收同事务。 |
| 15 采购单打印 | 本机新增 | 详情页打印 A4 采购单，含供应商、明细和总额；未做电子签章/正式合同模板。 |
| 16 管理员权限调整、离职撤权 | 部分 | 成员角色切换/停用、服务端即时鉴权和审计已有；细粒度自定义权限尚无管理 UI。 |
| 17 老板经营驾驶舱与责任人下钻 | 部分 | 经营概览有实际业务数量、余额及按商机/合同负责人、采购创建人的分组和记录链接，每组展开最近十条；销售仅自身范围。库存通过预警下钻，未建立库存责任人或异常归因模型。 |

## 开发顺序与验收线

1. **客户经营**：公海领用、商机跟进、到期跟进待办和管理员受控转派已增加；继续补自动逾期回收及真实离职交接规则。双销售领用竞争、跨租户、转派后旧负责人撤权和审计已本机验证。
2. **交易审核**：销售合同与采购单的提交、批准、驳回、审核人隔离和版本冲突已完成本机验证；管理员对自己草稿的直接确认是有专门审计字段的例外。退回草稿可由发起人修改，采购变更数量/备注最多批准一次，已收数量、应付和历史快照不倒退。采购变更页面与实时待办浏览器已验证；销售草稿编辑与商机带入合同已通过浏览器复查，站内通知与任务指派已补，继续核对专职负责人角色，再做审批消息适配。
3. **财务闭环**：内部开票申请/登记及人工到账→销售多应收认领→财务确认已本机验证；继续补销售预报收款、已确认分摊冲销与真实银行对账。重复流水、余额和撤回已做本机测试；税票真实开具仍是外部连接范围。
4. **协同与经营**：平台内待办、公告、消息与日程、责任人下钻。先保证站内可查看和关闭，再做各渠道的单独授权、发送回执、失败重试、去重和撤权。
5. **渠道适配**：飞书已有扫码创建机器人、成员绑定、采购审核通知与私聊 AI 的本地实现，真实飞书企业授权和收发仍待验收；企微、钉钉待接入。外部通道不可成为业务状态唯一来源，未取得官方真实投递回执前不标“已覆盖”。实施和验收边界见 [20 工作通道](20-工作通道接入与验收.md)。

各项仍遵循 [17 ERP 追踪矩阵](17-ERP功能追踪矩阵.md) 的实现与验收状态，以及 [08 上线验收](08-迁移与上线验收.md) 的真实客户门槛。新增范围来自本轮用户提出的飞书场景对照，优先补业务等价能力，不复制飞书低代码产品形态。
