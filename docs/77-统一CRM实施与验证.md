# 统一 CRM 实施与验证

2026-10-26，D-077。用户要求统一优化新CRM，并计划后续弃用旧CRM。D-077在新项目完成代码、增量迁移和本地隔离验证；后续D-078已获单独授权发布生产并退役旧云服务，见[78](78-统一CRM上线与旧三应用退役.md)。**旧CRM真实数据未导入新系统**。本页覆盖原“仅电商CRM”的产品范围，不把本地结果写成线上或客户验收。

## 本批结果

- 一个“客户CRM”承接销售管理、客户运营与客户服务，共用现有平台身份、组织、岗位、审计和公共UI。
- 新增线索查重、编辑、销售池轮转、接受/退回/无效、主管转化审核和事务性转客户/商机；重复请求返回同一真实结果。
- 客户支持企业资料、销售与服务归属、交接、独立联系人、脱敏/显式明文读取、逐客跟进、更正与下次跟进待办。
- 新增商机负责人/参与人、分币种预计金额、概率/日期/下一步行动、阶段推进和实际赢单/输单结果；客服可将续约商机交给有权销售。
- 新增服务计划、任务指派/提交/退回/重提/另一主管审核，以及风险登记/解决。取消计划会结束尚未完成的任务，不删除已发生记录。
- 保留导入、净消费指标、分群、运营任务/确认/执行和效果观察。客户列表分为档案/经营指标，详情分为档案/购买与运营，避免业务资料和空消费指标堆在一起。
- ERP继续拥有其交易客户、商机及合同/履约/账款；本批不自动创建或合并ERP对象，Q-003的真实跨应用身份映射仍待业务输入。
- 原生AI维持D-076提示模式，未接通新模型；WorkBuddy不重复提审，本批只验证已提交连接器的兼容性，不宣称新销售/服务接口已经成为连接器工具。

业务状态/权限/接口、旧数据快照格式、预检命令及回退约束见[CRM16](crm/16-统一CRM销售与服务.md)。主要实现：`apps/api/src/modules/crm/engagement.*`、`crm-core.service.ts`、`crm-permissions.ts`、`metrics.service.ts`及`apps/web/src/crm/Engagement.tsx`。

## 关键修正

- 全范围权限转换SQL时保留有效租户条件，避免空OR分支让管理员漏掉重复候选。
- 归属约束附着于每条岗位配对范围，同时覆盖ORM详情和消费指标/客户列表的SQL查询；在A团队任主管不会扩大B团队销售的可见记录。
- 客户交接、商机/联系人等更新按版本提交；服务计划结束与任务状态变更共享锁，避免并发写入覆盖。
- 新表单成功保存后先放行未保存保护，再进入回执详情；失败保留输入，相同未完成命令重试沿用requestKey。
- 联系方式只进入加密专用字段；跟进/方案/交接原因拒绝明文联系方式、密码和密钥。归属或权限变化后，详情与联系方式按当前授权读取。
