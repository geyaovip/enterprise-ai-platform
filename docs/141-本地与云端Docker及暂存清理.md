# D-141 本地与云端 Docker、暂存清理

2026-11-02，用户授权清理本地和云服务器垃圾，重点减少Docker及临时环境的磁盘/内存占用。本轮已完成；没有发布D-139/D-140，生产源码继续D-138。

## 实测结果

| 项目 | 清理前 | 清理后 |
| --- | --- | --- |
| Mac数据盘可用 | 约10.2 GiB | 约19.4 GiB |
| Docker.raw实际分配 | 约13 GiB | 约4.6 GiB |
| 云端根分区已用 | 25.04 GiB | 21.96 GiB |

云端文件系统已用减少3,307,294,720字节，约3.08 GiB；Mac可用空间同时受swap等活动影响，不将全部变化精确归因为镜像标称大小之和。Docker.raw的60GB是虚拟容量上限，不能当作实际占用。本轮没有删除/重建/缩小Docker.raw或直接操作存储层。

## 本地

- 停止4个本轮预览进程：工作区4601、企业管理4603、平台管理4602、隔离API4635；逐个核对PID、工作目录及命令后停止。停止`suite-content-qa-20261030`数据库容器，保留容器及其写层数据。没有停止四个常驻平台容器或用户浏览器/桌面应用。
- 移除10个已退出的内容QA、BOM工具及Loomic参考容器。移除对应闲置API/参考项目/BOM镜像与已确认无容器使用的官方数据库镜像；后者保存不可变registry digest用于重拉。23个数据卷全部保留，包含旧ERP/CRM/MES和其他项目的数据。
- Loomic的数据库/素材卷在保留原卷之外，另以只读挂载导出压缩备份；归档完整读取校验，私有配置、镜像信息和容器重建参数受限保存。
- 按实际盘点的62个缓存ID清理本项目API/BOM构建缓存，没有全局system/volume prune。`uv cache prune`仅移除35个闲置文件、167.8KiB；工具运行时、项目依赖和实际使用的缓存保留。
- 12份历史`release-source/`在逐文件核对原压缩包后折叠；未收入原包的测试代码、生成文件等另压缩校验并保存软链接恢复元数据。7个上传外包的每个成员与保留文件逐字节一致后移除。主工作区、当前D-138基线、画布API验收基线、D-139/D-140待发布目录和压缩包保留。
- 实际恢复一份历史源码快照，1,068个清单文件逐一散列一致，再移除恢复演练的临时解压副本；这不是数据库或整个旧版本的业务恢复验收。

## 云端

仅清理`ubuntu@<服务器地址>`中已明确归属本项目的资源。

- 选择本项目API/Prisma/frontend构建记录及依赖祖先中的可回收、非共享缓存，按301个精确ID删除；记录数346→45。没有删除任何线上镜像、容器或数据卷。
- 9份有完整逐文件校验源包的旧发布解压目录折叠；原包保留，环境文件和其他原包外内容另存私有补充包并校验。当前D-138、直接前端回退D-137-ui-r3、实际API/Worker的content-canvas-r1、上一API回退content-employee-r1保留；PostgreSQL仍挂载SQL的20261011-vietnam保留。未通过包/源码匹配或无对应归档的目录保留。
- 21个临时传输文件逐文件或逐成员匹配已有持久归档后删除，合计480,227,957字节。未确认重复的临时文件、业务原件、NASA资料、Runtime成员目录及审计日志保留。

方法沿[Docker构建缓存精确筛选](https://docs.docker.com/reference/cli/docker/buildx/prune/)及[Mac实际磁盘占用说明](https://docs.docker.com/desktop/troubleshoot-and-support/faqs/macfaqs/)。清理没有改变Docker配额、重启Docker服务或添加后台定时任务。

- 本地证据及恢复脚本：`var/operations/20261102-cleanup-r1/`。历史源码可运行`python3 var/operations/20261102-cleanup-r1/restore-local-snapshot.py <版本目录名>`，会从原源包、私有补充包及软链接元数据还原，拒绝覆盖已有解压目录。

后续临时预览按需启动，验收完成后关闭自建进程和闲置QA数据库；已归档的旧源码不长期保留重复解压副本，不把整个`var/output/node_modules`递归复制进新的验收暂存。缓存清理继续先核对归属和在用状态，不凭“未挂载”判断数据库卷可删。
