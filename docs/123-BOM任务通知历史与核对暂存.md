## 现在的流程

1. 图纸提交后仍由原Worker处理。完成、失败或停止时，在现有站内通知中心生成通知，只通知任务所属企业的本人。
2. BOM列表及整理区提供“整理任务”入口，按状态筛选、分页查看本人任务。通知/历史链接直接打开具体任务；读取历史、刷新进度和继续核对均不创建模型请求。
3. 用户修改选料、数量、排除项、机型、备注、人工补行或核对状态后，约900毫秒自动暂存到服务端，也可手动暂存。显示正在暂存、已暂存或失败，暂存未确认前由编辑页离开保护提示。
4. 另一设备登录同账号、同企业后，从历史打开任务，恢复已暂存的修改与核对状态。原始单元格、视觉/OCR结果、来源定位和模型回执始终从原任务恢复，不由暂存数据覆盖。
5. 物料失效、物料/父产品单位变化时，相关数量和核对状态失效，要求重新核对。新模型复核会清除旧暂存；复核按钮沿原有“并重置核对”语义，未暂存时不允许开始复核。

“完成”指识别结束、待用户核对，不表示BOM已经保存、发布或可采购。站内通知复用现有按焦点/可见状态及约60秒刷新机制；不新增邮件、短信、系统推送或服务承诺。

## 来源、并发与用量

- 任务、历史和暂存均按企业＋用户＋成员隔离，每次读写重新鉴权。MES权限撤销后，该任务通知从当前通知流隐藏，直接读取也拒绝。
- 暂存只接受可编辑字段白名单，服务端校验原分组/来源行及人工补行的原件摘要，重新读取当前企业有效物料。不能删除/重排原始识别行，不能写入伪造OCR“通过”、模型回执或原始单元格。
- 原结果版本和暂存版本分别校验；同一任务加行锁，两个设备竞争时只有一个版本提交成功，另一个409且不覆盖。前端保留冲突设备的本地修改，可明确重新载入服务端版本。
- 同一暂存请求标识与原参数重复提交返回同一版本，处理“服务器已保存但响应丢失”的情况。暂存PUT有20秒超时/取消保护；失败后停止自动写入，明确重试，复用请求标识，不进行无界自动重发。
- 通知与任务终态同事务保存并去重，重复Worker检查不会重复发通知。完成与停止竞争时返回真实最终状态，避免把已完成任务误标成停止。
- 沿用原件7天保留期，核对暂存随任务结果清理；已保存到BOM的来源证据不因此删除。过期任务保留历史状态，不能继续暂存或重新恢复原图。

暂存针对后台任务的结果。尚未提交的附件、资料文字及单独“本地整理”产生的同步预览仍属于当前页面，不属于跨设备任务暂存；BOM正式草稿保存仍走原业务流程。

## 接口与实现

| 接口/对象 | 语义 |
| --- | --- |
| `GET .../mes/boms/intake/history` | 本人历史，`status`为all/active/completed/failed/cancelled/expired，默认20/页、最多50 |
| 原`GET .../intake/jobs` | 保留仅查询运行中任务的数组契约，兼容自动恢复 |
| `GET .../intake/jobs/:id` | 增加结果版本、暂存版本/时间与失效提示；返回依据当前物料恢复的核对结果 |
| `PUT .../intake/jobs/:id/review` | 提交预期版本、结果版本、requestKey和可编辑核对文档 |
| `PersonalNotification.kind=mes-bom` | 跳转`/t/:tenant/mes/boms/new?bomTask=:id`，目标页重新鉴权 |
| `AiTask.result.review` | 保存有版本的核对文档，不新增数据库表或迁移 |
