## 用户流程

三端共用邮箱登录：输入邮箱→获取六位验证码→登录。首次验证成功才创建User，不自动加入其他企业、不授予平台角色；无企业时仍可自行创建企业或接受管理员邀请。`/register`在前端收敛至`/login`，官网移除注册入口。企业邀请必须在邮箱登录后确认加入，邀请链接不再直接创建免验证账号。

已有邮箱账号按同一邮箱找到原User，不复制成员身份。没有邮箱的历史账号，可以在已登录的「账号安全」页通过验证码关联邮箱；已退出的用户可在登录页的「关联已有账号」中同时证明原账号密码与新邮箱，仍使用同一User ID、成员和业务数据。邮箱占用或已关联其他邮箱时拒绝覆盖，不按昵称或相似账号自动合并。关联入口的密码仅用于旧身份迁移，不是日常登录方式。

账号安全页显示登录邮箱，提供「退出所有设备」并保留一次明确确认。历史密码恢复接口不恢复公开密码登录；不重置用户现有密码，不批量迁移或删除原用户。

## 会话约定

- 新会话有效期180天；正常鉴权时，剩余期限需要增加超过30天时自动续期，单次登录最长365天。
- 会话及令牌摘要持久保存在PostgreSQL，cookie保持原名称和路径（HttpOnly、SameSite=Lax，生产Secure）。不依赖进程内登录缓存，不在普通发布时删除Session。
- 旧七天会话仍可使用并自然续期，令牌不更换。已经过期、主动退出、停用用户、密码恢复撤销或最长365天到期时仍需重新验证。
- SSE等已经发送响应头的请求不执行cookie续期，避免对AI流式响应再次写响应头；后续普通请求续期。
- 不保证清除浏览器cookie、更换浏览器/域名、手动撤销或灾难恢复后仍然登录。

## 服务端边界

| 接口 | 规则 |
| --- | --- |
| POST `/api/v1/auth/email/request` | 只接受合法邮箱，调用固定Resend HTTPS邮件接口；返回挑战ID、600秒有效期和60秒重发间隔，不返回验证码 |
| POST `/api/v1/auth/email/verify` | 校验邮箱/挑战/验证码并一次性消费；同事务找到或创建User、创建180天Session；禁止注入角色字段 |
| POST `/api/v1/auth/email/bind` | 先验证当前会话，再消费验证码，将邮箱关联到当前User，拒绝改绑其他已有邮箱/用户 |
| POST `/api/v1/auth/logout-all` | 仅撤销本人所有会话并清理当前cookie |
| POST `/api/v1/auth/login`、`/auth/register` | 均返回403，不保留密码登录或自由注册的后门 |

新增可空`User.emailVerifiedAt`、`AuthEmailChallenge`和`AuthEmailRate`两表；增量迁移不改业务表，不清空用户/Session。验证码用服务端稳定秘密HMAC保存，数据库没有明文验证码；每挑战最多尝试5次，单次消费与并发重放由数据库事务/锁保护。原账号关联同时使用条件更新避免两个邮箱抢占同一账号。

发信/验证限流保存在数据库，API重启不重置。发信每IP每小时20次、每邮箱每小时5次/每天10次、同邮箱60秒间隔；验证每IP每15分钟40次。平台默认每日80次发送尝试（`AUTH_EMAIL_DAILY_LIMIT`可调整）。限额不是Resend账单对账，失败请求/冷却请求也可能消耗尝试额度。更大业务量需按真实出口IP与邮件服务额度调整，不能关闭邮箱/验证码限流。

`RESEND_API_KEY`、`AUTH_EMAIL_FROM`和稳定的`AUTH_EMAIL_SECRET`只在服务器私有环境中配置；配置缺失或邮件失败时失败关闭，不提供调试验证码或自由注册降级。服务端12秒邮件超时、前端20秒请求超时，不自动重试发送；Resend以挑战ID作为幂等键。过期挑战与限流记录在后续发信成功时清理超过一天的记录。禁止公开邮件验证码、密钥或会话令牌。
