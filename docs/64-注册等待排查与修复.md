# 注册等待排查与修复

日期：2026-10-24；D-064。用户反馈注册页长时间显示“注册中”。

## 线上排查事实

- 截图中的账号已存在于正式User表，active=true；没有读取或重置用户密码。注册成功不代表浏览器收到了成功响应。
- 正式域名健康检查200，约1.00秒；注册页200约2.29秒；无效注册POST正确返回400约0.95秒，旧Workers来源同样可用。这是排查当时的小样本，不代表注册性能P95。
- 当时数据库没有阻塞锁或长注册查询；主机磁盘23%使用、可用内存约1.15GB、API健康。没有证据证明数据库慢或AI调用引发此次等待。
- 注册服务只校验/哈希密码并创建User，不启动AI、不创建企业、不接第三方。
- 确定的缺陷：浏览器fetch没有截止时间，网络或正文迟迟不完成时，finally无法运行，按钮始终busy。没有当次完整请求追踪，不能断言具体阻塞发生在浏览器、边缘还是回源。

## 修复

1. 公共请求工具支持按次设置超时；仅注册/登录启用20秒，覆盖响应头及正文。超时终止等待、释放按钮，不自动重试POST。
2. 8秒后显示慢响应提示；注册超时/断网提示“结果待确认，先登录”，不误称账号没创建。
3. 同步提交锁防止同一事件周期连续提交；等待期间锁定账号、密码输入，避免请求身份与界面不一致。
4. 修复账号HTML pattern在现代浏览器Unicode v模式下的连字符语法，合法短横线/下划线通过，非法@被原生校验阻止。
5. 三端共用同一实现；AI、企业创建及其他业务请求没有新增20秒限制。

## 本地验证

- 请求测试覆盖响应头挂起、正文挂起、超时abort、不自动重试、成功清除计时器、409错误、其他请求不受限。
- Playwright浏览器模拟：8秒提示、20秒恢复、连续submit只发一次、能前往登录、正常注册转登录；网络中断恢复、合法/非法账号、390px无横向溢出。
