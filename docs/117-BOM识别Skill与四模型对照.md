## 本次实际做了什么

- 建立 `skills/bom-evidence-extraction/`，包含共享规则及机械、电子、线束清单、工程图四类条件规则；编译器只加载共享规则和当前一类，不读测试答案。另有只报风险、不改原值的结构核对脚本。
- 现有MesIntakeSkill是业务录入编排；此前D116已有较强通用提取提示，但没有这种分类规则加载。本次测试的是从真实Skill编译规则并注入API提示，**不代表方舟原生执行Skill，也没有把整个工具工作流作为模型能力验收**。
- 先冻结Skill，再选两份未送过模型、未用于编写Skill的资料：RP1“小电池保护板长线”PDF的3行表，及MCAP原生电子表7行的受控渲染。仍属同一RP1工程资料，非独立客户盲样。
- 旧样本取D116的9张正例及单零件图负例，复用40份A响应；新增两图分别跑A/B，并对旧10图跑B。每模型12张、11正例/166条来源行及1负例；四模型共96份评分响应，**仅56次新请求**。同一输入图、schema及模型参数，B只追加分类规则；新图两臂顺序交错。
- A旧图来自历史已结算响应，非全部同期随机试验；Kimi温度1、豆包滚动版本及单次输出均有波动。本轮不将1行差异解释为稳定显著提升。

- **线束列归位**：豆包从0/15升到15/15，核心名称/数量两臂均15/15；主要是停止把连接器和端子并入线材规格，不是恢复15个漏件。最适合把这条规则做成明确列映射。
- **长料号/位号**：规则没能消除读错字符。GLM将`!PCB1`从A的`IPCB1`变成B的`PCB1`，仍错；Kimi维持全匹配。DeepSeek补回一个PCB标识，但在原先通过的替代料和39行表上出现新错料，密集表也回退，不能上线为默认增强。
- **缺量、单位、多机型**：原提示已有效，两臂基本持平。应依靠结构字段、选机型和服务端拦截固定行为，避免每次付费重复解释。
- **豆包仍有错料/错量**：整字段改善后仍未优于GLM；不因一个类型改进切换默认模型。原始差异清单保留新增错误与被修复错误。
- 辅助诊断按明确序号或相同输出条数下的来源顺序对齐，不替代主评分：DeepSeek非空错值15→18、遗漏2→1；GLM1→1，豆包21→5，Kimi0→0。空值被错误填入均0。归位错误也计非空错值，不能称为同数量的“错料”。
