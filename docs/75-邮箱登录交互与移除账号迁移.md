# 邮箱登录交互与移除账号迁移（D-075）

2026-10-24。用户要求优化真人验证和验证码交互，并明确「不需要迁移功能」。覆盖D-072的原账号密码迁移决定。三端使用同一AuthScreen，不新增独立认证体系。

## 交互与身份契约

1. 登录页只输入邮箱，主按钮为「获取验证码」。不显示原账号、原密码、注册或账号关联入口。
2. 发码成功后进入「输入验证码」，显示收件邮箱和「修改邮箱」，自动聚焦六位验证码输入框。输入不足六位时登录不可提交；一个真实文本输入支持数字键盘、自动填充、前导零、整段粘贴及带空格/短横线的六位码粘贴，不拆成六个输入框。
3. 重发按钮与登录按钮分开，按服务端retryAfter计算剩余时间。重发冷却不影响登录；登录限流有独立倒计时。修改邮箱返回第一步并聚焦邮箱，不重发邮件；保留相同邮箱当前冷却，变更后的邮箱仍由后端限流。
4. Turnstile保留Managed、interaction-only和服务端必验。成功回调立即隐藏校验组件及留白；必要的新挑战会重新显示，失败可重试。隐藏成功展示不代表跳过服务端验证，不自动重复发信。
5. `POST /auth/email/verify`严格只接受email、challengeId、code。legacyAccount、legacyPassword等额外字段一律400，移除通过旧账号密码领取身份的服务逻辑。禁止合并两个User或转移成员、企业数据。
6. 已有持久会话继续有效；已登录用户在账号安全中验证自己的登录邮箱仍属于本人设置，不接受原账号密码或改绑其他用户。无邮箱的历史账号在退出后不再提供密码迁移入口。新邮箱首次验证按原规则创建独立普通用户，无企业权限。

## 验证与证据

- 在独立临时PostgreSQL运行74项邮箱认证/会话检查、97项防刷检查：迁移参数拒绝、原用户未改变、未消费验证码或创建Session、本人邮箱设置、旧会话续期、重放、滚动额度、并发及5/15/60分钟冷却均通过。替身发信，不调用真实模型。
- 浏览器9类场景通过：两步登录、错误码修正、重发、修改邮箱、校验失败、发送失败、429、配置重试、本人邮箱设置/格式化粘贴；Cloudflare官方测试siteKey通过后成功隐藏。320/390/768px验证码页无横向溢出，输入框26px/56px。
- 三端TypeScript/Vite构建通过；已发布。149项线上资源/策略核验、3组迁移参数400拒绝、三端浏览器默认登录页均通过。所有旧哈希资源完整保留。真实邮件投递沿D-073既有证据，本轮不重复发送真实邮件，不宣称完成客户验收。

研究参考：[Carbon分步登录](https://carbondesignsystem.com/patterns/login-pattern/)、[GOV.UK邮箱模式](https://design-system.service.gov.uk/patterns/email-addresses/)、[Cloudflare组件配置](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/widget-configurations/)。沿用已有品牌与公共UI，不更换认证供应商。

## 发布与恢复

以D-073已发布源码为基线，仅叠加公共AuthScreen、Turnstile、登录样式及两份认证服务/Controller；不发布并行开发的D-063/D-074业务或WorkBuddy增量。API/Worker已发布为`20261024-login-experience-r1`，无数据库迁移；保留Resend/Turnstile/会话秘密、当前CRM AI设置、Runtime和知识服务。

发布前数据库dump通过pg_restore目录校验，配置、会话快照和数据库备份复制本地并逐项SHA256核对。回退按该次发布记录恢复API/Worker和三个前端版本，保留数据库，不覆盖发布后的业务写入；紧急恢复到D-073会恢复其旧迁移入口，须同步处理，不能将该回退作为日常更新。

证据：`var/operations/20261024-login-experience/`。私有备份不进Git或公开前端。
