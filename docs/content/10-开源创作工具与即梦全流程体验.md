## 本轮范围

按用户要求暂停现有内容应用优化。参考工具依次运行，不同时启动多套服务。所有生成使用虚构咖啡案例，不上传企业真实资料。只做少量必要生成，不批量跑图、不自动重交付费任务、不购买套餐。

本轮证据目录：`output/reference-workflows-20261030/`。源码和数据保留在工作区相邻的 `reference-apps/`，测试适配器没有迁入本平台业务代码。界面体验、模型请求成功、文件下载与服务重启恢复分别验收。

本地接入改动：注册 Ark 图片/视频模型、参考图转内联字节、修复直接生图接口剥离参考图的问题、让默认 Agent 模型读取现有环境配置、关闭自动重试。本轮没有修改 Loomic 的界面布局。

实际体验发现：

- 选中图 → 描述修改 → 新变体，是可用的修改方式；没有必要为这个场景先做文字、图形、图层海报编辑器。
- Agent 将新图放在原图右侧，但打开聊天面板时新图被遮住；生成视频又叠在原图上，定位和布局需要人工处理。
- 品牌套件是提示上下文，不是品牌规则的强制校验。
- 画布中的图是完整位图，不能据此声称有语义化的海报文字/元素编辑。
- 第一次 Agent 修改因默认模型配置错误而失败，修正配置后人工重发；这次失败没有发起生图请求。

纠正两项早期判断：旧开发缓存随源码移动导致的白屏，不计为上游缺陷；视频实际已放入画布，收起面板后可见并能播放，后端也确实等待任务完成后返回地址，不存在“异步任务 ID 被当成视频 URL”的接口不匹配问题。

企业接入仍须重做公开素材桶、租户授权、画布存储路径与 RLS、任务/文件恢复和宿主代码执行边界。此前发现的画布文件上传失败后退回整体 Base64 保存的行为未在本轮修复。

## Toonflow

固定提交：`af6e884c3d8cda353acaf8ef13aea8ea754a4afd`。本地 Bun 1.4.3，正式 Web 构建通过；构建时需使用 Node 24 处理工作区 TypeScript 配置。服务只监听 `127.0.0.1:4662`，设备互联保持关闭。

这个版本实际呈现“工作目录＋对话＋节点画布”，不能只按 README 的小说转短剧描述来判断它。

实际步骤：新建工作目录 `coffeeBrandReview` → 添加图片生成节点 → Seedream 单张生图 → 界面下载 → 存入全局素材库 → 对话生成两条短文案 → 在图片提示词中引用素材 → 改米色背景 → 预览两个历史版本 → 下载变体 → 新增视频生成节点 → 引用图片输出作为首帧 → 三秒 Seedance 视频 → 播放和下载 → 重启服务、刷新 → 退出并重新打开项目 → 界面打包下载 ZIP。

截图：`toonflow/03-image-result.jpg`、`toonflow/04-copy-result.jpg`、`toonflow/06-reference-result.jpg`、`toonflow/07-history.jpg`、`toonflow/10-video-result.jpg`、`toonflow/12-project-restored.jpg`。实际交付文件为 `coffeeOriginal.jpg`、`coffeeVariant.jpg`、`coffeeVideo.mp4`、`coffeeBrandReview.zip`。

接入改动只包括本地监听地址及 `volcanoArk.ts` 媒体供应商插件。上游默认媒体供应商主要是中转平台；现有火山 Key 未发给这些平台。图片和视频均直接调用北京 Ark API。

一次视频配置尝试被本地适配器拒绝，未请求火山：Toonflow 的 `startFrameOptional` 表示首帧可选、单图作为尾帧；本轮需要的是 `endFrameOptional`，即尾帧可选、单图作为首帧。能力声明纠正后才提交真实视频请求。这是测试适配器理解错误，不能记为上游故障。

实际体验发现：

- 从素材库引用图片后，自动建立素材节点和输入连线；从图片节点继续引用到视频节点，修改过程容易追溯。
- 节点历史和实际文件保存可取，能支撑“选版本、再修改、拿到结果”的闭环。
- 聊天浮窗会遮挡生成按钮；刷新后又默认展开。多节点、长工具栏、画布缩放也增加操作负担。
- 首屏及节点工具栏包含全景、局部重绘、打光、多角度、宫格、音视频拆分等能力；本轮没有逐项付费验证，不能把按钮存在当成验收通过。
- 媒体任务放在进程内 Map 中，已完成产物可以恢复，不代表执行中的任务具备跨重启恢复能力。
- 文本调用记录里的 cost 为 0 是模型单价未配置，不能解释为免费。
- 源码类型检查未通过：缺少 `.hutch/devkit/api/config/ElectrobunConfig` 开发类型文件。没有添加假类型文件；正式构建和本轮浏览器流程单独记录为通过。

可参考的源码位置：`packages/providers/types.d.ts` 的能力声明；`packages/nodes/imageGenerationNode/src/index.vue` 和共享的历史预览逻辑；`packages/nodes/videoGenerationNode/src/index.vue` 的引用输入；`apps/server/src/utils/media/generation.ts` 的媒体落盘。Vue/VueFlow 宿主组件需要适配现有 React 平台，不能原样复制整套工作台。

## InvokeAI

官方说明：[外部模型](https://invoke.ai/features/external-models/)、[Seedream 接入](https://invoke.ai/features/external-models/seedream/)。文档说明不能代替本地流程验收。

截图：`invokeai/03-image-result.jpg`、`invokeai/05-reference-result.jpg`、`invokeai/06-canvas.jpg`、`invokeai/07-restored.jpg`。实际文件为 `coffeeOriginal.png`、`coffeeVariant.png`、`coffeeBrandReview.invoke`。项目包已检查不含 API Key。

首张实际交付图片出现左上角白色方块；第二次原计划内的参考修改同时去掉白块、改为米色。保留原结果，不能只展示修正图，也不能用单样本将此问题归因为工具或给模型做质量排名。

本地适配和兼容边界：

- 原生 Seedream 适配器支持区域地址，但 BytePlus 的模型 ID 需要映射到北京 Ark 的 `doubao-` 模型 ID；没有重写它的 UI 或生成流程。
- 每次限制一张图片、会话最多两次真实图片请求，关闭外部请求自动重试。
- 首次启动的 VACUUM 因仍有活动 SQL 语句而失败，参考环境只对这个特定的非必要清理错误延后处理，保留原数据库。
- PyPI 安装解析到 Starlette 1.10.0、Uvicorn 0.54.0，而上游 lock 为 0.48.0、0.49.0；出现流式响应压缩兼容错误。本地通过官方 `http_compression_level: 0` 配置关闭 HTTP 压缩后继续体验，不据此宣称原样安装无问题。

可参考的是 Generate 独立于 Canvas 的产品分层、作品集、结果元数据和带图片的项目导入导出。源码入口：`invokeai/app/services/external_generation/providers/seedream.py`、`invokeai/frontend/web/src/features/controlLayers/hooks/useCanvasProjectSave.ts`、`useCanvasProjectLoad.ts` 及 `util/canvasProjectFile.ts`。Python/FastAPI、PyTorch、专业画布和本地模型管理整套引入会增加本平台部署与维护成本。

原生外部模型文档说明不支持 inpainting；界面进入 Canvas 后也会按模型能力限制部分参数。本轮没有为了点亮这些按钮而另写局部重绘或视频适配器。专业图层、文字、蒙版确实存在，但不等于本平台首版需要实现同等编辑器。

实际交互发现：

- 主入口集中为输入、参考上传、模型/尺寸/数量和生成按钮；结果跟在同一对话里，复杂编辑通过结果工具或独立画布进入。
- 完成生成后自动给出“你可以试试这样改”的具体建议，比把一长排高级参数全部放在主入口更便于继续创作。

## 对本平台的取舍

本轮不据单个咖啡样本给生成质量排名。就已实际走过的流程，当前更适合采用的是：

| 参考来源 | 采用方向 | 暂不引入 |
| --- | --- | --- |
| 即梦 | 单一输入区、结果卡片、明确的参考改图入口、历史对话；待连接恢复后补齐其修改与下载实测 | 直接照搬首页运营内容、全部工具入口及复杂画布 |
| Loomic | 选中结果作为修改对象、项目绑定品牌上下文；React 组件按依赖与权限边界筛选 | Supabase 身份/积分/公开桶、整套 Agent 宿主、宿主 Shell 执行 |
| Toonflow | 素材引用、结果版本历史、图片输出接视频输入、带素材的项目导出思路 | VueFlow 节点工作台、进程内媒体任务、短剧/3D/打光全套功能 |
| InvokeAI | 独立 Generate 与专业 Canvas 分层、作品集、结果参数和可移交项目文件 | Python/PyTorch/本地模型管理整套部署；专业蒙版和图层编辑器 |

首版仍围绕“选品牌 → 输入需求/参考图 → 生成候选 → 描述修改 → 下载”，补一个轻量历史即可。继续接入本平台已有身份、租户、任务和存储；开源部件能降低总成本才提取，不为保留参考项目架构而重建一套应用。不把本轮发现的高级能力自动加入开发范围。

真正提取代码时按固定提交记录来源和修改，保留许可证与版权声明：Loomic、Toonflow 为 MIT，InvokeAI 为 Apache-2.0。第三方依赖和素材的许可另行核对；本轮只是本地研究适配，没有把这些代码迁入平台。
