# Loomic 本地验证与首版收敛

日期：2026-10-30。依据用户最新纠偏：接入现有平台，先做好企业品牌图文创作核心闭环，避免将产品扩展成海报编辑器和复杂管理系统。本文覆盖旧首版范围及阶段B—D的自动推进安排；历史验收记录保留，不代表新的产品验收。

## 决策

首个场景仍为产品营销图文。主路径收敛为：输入需求、可选品牌/产品上下文及参考图 → 生成候选 → 继续描述修改 → 下载。作品自动保存，失败可理解、可恢复。

第一屏只承担开始创作和继续最近作品。品牌资料作为可复用上下文，不要求先建立并发布完整品牌规范；产品原图与本次卖点可直接上传/填写，不要求先建产品档案。企业账号、权限和文件隔离继续由平台处理。

默认生成完整设计图或基于参考图修改。生成图中的文字不能承诺无损、逐字独立编辑；用户需要精准文字时，后续按样本验证最小补字方案。现有背景生成加固定图层合成保留为历史实现，不能继续充当唯一创作路径。

| 现有复杂度 | 收敛要求 |
| --- | --- |
| 品牌发布、产品建档、需求清单成为首次生成前置步骤 | 改为就地输入与可选上下文；只对真实缺失且影响本次结果的信息提示 |
| 图层、坐标、字号、层级、裁剪等主导作品界面 | 首版退出主流程；不再扩建自研海报编辑器，不再为它追加模板变量和复杂排版 |
| 文案候选、工作单、对比、采用、保存正式版之间反复跳转 | 文案在作品旁直接改；AI候选与继续修改在当前创作上下文中完成 |
| 8个内容管理入口 | 日常入口聚焦创作和作品；品牌资料保持轻量；模板中心、单独审核中心等后置 |
| 多尺寸批次、复杂审核、预算治理、视频、技能市场 | 不列为首版完成前置；有真实使用需求后逐项评估，不按旧B—D清单自动开发 |
| 租户鉴权、私有素材、任务持久化、未知付费请求不盲目重试 | 保留，作为底层可靠性；不转成用户每次都要确认的步骤 |

这不是仅把控件折叠：实施时必须梳理并移除主链上无用状态和跨页跳转。旧作品、素材、历史版本先保持可读，数据清理/迁移独立处理；不得删数据来制造简洁。当前回合是部署、源码核查和收敛决策，未把这些改动冒称已实现。

### 两个关键源码事实

1. `features/canvas/canvas-element-writer.ts`把生成结果写为`type: "image"`。画布可另外创建文字/形状，但没有把一张生成图自动拆为标题、价格、产品等独立语义图层的依据。不能承诺“AI生成后的每个文字都能直接改”。
2. 它的品牌工具从资料读取后传给Agent，属于生成上下文。公开界面和源码均不能证明每次Logo、产品外观、字体和宣传用语一定正确；应通过真实结果核对，而不是增加大量前置表单制造一致性保证。

### 保存问题的代码依据

`canvas-service.ts`使用`canvas-files/<canvasId>/<fileId>`作为存储路径；`20260323000002_loomic_supabase_foundation_hardening.sql`的存储写入策略要求第一层路径是有权工作区UUID。两者不一致，上传被拒绝，服务又静默保留Base64。本轮独立请求已复现该拒绝；不是只凭注释推测。

适配平台时直接使用平台素材ID/受控读取，不迁入这段保存协议。若未来采用Excalidraw，只提取画布适配层，并补真实保存/并发/失败可见性验证。

依赖已按原锁文件安装；共享包编译通过。针对现有相关测试：Web API 9项通过；OpenAI图片与Metaso视频适配器22项替身测试通过；`test/chat-workbench.test.tsx`因引用不存在的`src/components/chat-workbench`而无法收集。这些是有限源码验证，不是完整仓库通过或模型能力证明。


## 本轮交互审查与采用顺序

实际画面能确认的优点是创作输入突出、品牌可选、资料直接保存、项目自动建立。首页也有重复Agent按钮、模型/技能选择、积分和灵感案例等额外负担；企业首版不照搬这些入口。新建项目主动开新标签页、sessionStorage传初始附件，会增加平台导航与异常恢复成本，应改为当前应用内衔接。

当前现有内容模块的复杂度核查覆盖`ContentPage.tsx`品牌/产品/需求门槛、文案候选与正式版本之间的跳转、`ArtifactEditor.tsx`的图层控件，以及内容Service/Artwork/Delivery的调用边界。现有本地预览在本轮新的浏览器环境显示登录安全验证不可用，故这部分结论以源码和已知流程为依据，不冒充本轮已重新走完所有现有页面。原304项等工程测试不能证明该产品范围合理。

第一批优先选取附件状态与附件条、轻量品牌资料分区、图像预览；适配平台API与现有UI。已直接执行的`createExcalidrawImageElement`证明部分辅助函数不必依赖Next宿主，但首版不因此引入画布。输入框可提取布局与附件能力，去掉开源项目的多模型/技能耦合。接下来先在现有模块中收敛创作主链，再根据实际必要性提取组件；不同时移植两套框架，也不先造通用抽象。

Toonflow本轮再次核对`imageInpaint.ts`：原图+标记图引导生成，再用蒙版本地合成保留选区外像素，有局部修改需求时可提取处理函数；VueFlow节点宿主与界面不搬入当前React应用。该能力不是当前首版完成前置，未在本轮部署Toonflow或验证其模型质量。

结论是采用Loomic中边界清楚的组件和函数，并参考其低门槛创作入口；现有平台继续承担身份、素材、任务与模型接入。不会因为框架不同就把所有前端重写，也不会把Loomic整站接成第二套独立系统。未通过的画布界面和真实生成不作为可直接投产的依据。
