## 实现与资源

| 功能 | 默认方案 | 可替换能力 |
| --- | --- | --- |
| 混合检索 | 授权范围内 pgvector 余弦距离 + 中文双字词/英文词及编号匹配，各取 32 个候选，以 RRF 合并 | 仍经 KnowledgeEngine 契约替换；不依赖新增搜索服务 |
| 结构分块 | Markdown 标题层级、代码围栏、管道表格；DOCX 标题/段落/表格；PDF 页；XLSX 工作表/行；分块带章节及表格首行上下文 | 新文档自动生效；旧文档需重新索引 |
| 重排序 | 本地规则按词覆盖、完整短语及融合顺序排序，明确不是神经模型 | Jina/Cohere 格式 `/rerank` 接口，可由客户本地或云端服务实现 |
| OCR | Tesseract fast 中英文模型；PNG/JPEG 和无文字 PDF 页自动识别；混合 PDF 的文字页直接抽取 | OpenAI 兼容视觉模型 `/chat/completions`，支持客户本地或云端服务 |

没有新增常驻服务、向量表、重复全文索引或大型模型。OCR 仅任务执行时启动进程，语言包随 API/Worker 镜像安装。默认重排序无需下载模型。API/Worker 共用镜像层，不重复保存两份模型。

原件、向量和已有引用仍保存在平台。结构分块变更可能产生新引用 ID，历史引用仍按原版本和当前权限访问。OCR 文本只用于检索，不替代原件，不保证表格版式、手写文字或复杂版面的准确复原。

## 上限与失败处理

- 保留原文件 8 MiB、Office 解压 32 MiB、文本 180000 字、256 个分块。
- PDF 最多 120 页，其中无文字/扫描页最多 20 页；不能将超过限制的文档截断后标为成功。
- 输入图像最多 1200 万像素，单边 10000 像素；PDF 渲染最大边 2400 像素；识别图像最多 8 MiB。
- 每个解析子进程最多 30 秒、输出 2 MiB；整份文档解析 90 秒，整个解析/嵌入任务沿用 210 秒限制。Linux 子进程限制地址空间 256 MiB、CPU 25 秒、生成文件 8 MiB；Tesseract 单线程。
- 每次 OCR 使用权限为 0700 的临时目录，逐页处理并删除渲染图像，在成功、异常和超时路径清理目录；Worker 启动时清理超过 10 分钟且带本模块所有权标记的残留目录。
- 模型重排序 20 秒超时、响应最多 2 MiB；索引缺失/重复/越界/无效分数拒绝。失败退回本地规则，返回 `retrieval.degraded=true`，界面提示降级。
- 云端 OCR 无效或截断输出不提交索引；暂时不可用可重试。所有分块完成后才能提交，不能暴露半成品。
- 嵌入维度变化继续失败关闭，不混用索引；关键词召回可以补充被向量距离阈值排除的编号匹配，嵌入服务不可用仍明确报错。

## 配置契约

复用企业 `InfrastructureBinding` 的独立 kind，密钥沿用 AES-256-GCM 加密，不放入 options：

- `kind=knowledge-rerank`、`scopeKey=tenant`、`provider=api-rerank`、`options={model}`。`baseUrl` 为兼容服务 API 根地址，例如包含 `/v1`；调用追加 `/rerank`。
- `kind=knowledge-ocr`、`scopeKey=tenant`、`provider=openai-vision`、`options={model}`；调用追加 `/chat/completions`。
- 首次配置需要 secret，更新留空保留；enabled=false 恢复内置本地能力。OCR 修改后已有文档需重新索引；重排序修改即时用于新搜索，不改变嵌入模型或引擎代次。
- 仅平台运营可配置或检查连接。企业成员看到能力和数据发送提示，不获得端点凭据。地址必须在 `INFRASTRUCTURE_ALLOWED_HOSTS` 中；禁止重定向。
- 向外部重排序发送片段前再次检查成员、企业能力、空间访问、当前文档版本及引擎；返回引用前再次检查。供应商返回的文本不会替换平台候选，只有合法候选序号参与排序。

外部 API 可由客户自行部署或选择供应商；平台不会自动采购订阅或下载模型。视觉模型健康检查只证明基础请求可访问，实际图像能力需用授权图片验证。
