## 运行管理边界

- 控制器在新服务器单独运行；API/Worker 挂载只读 Socket 目录，不挂载 Docker Socket。控制器只处理规范 UUID、已批准企业模型及自己记录的成员容器；不提供任意命令、任意路径或状态删除接口。
- 每个成员独立容器、Gateway 令牌、工作目录与会话状态。不同企业不共享批准的模型配置；未配置模型、未交付/启用 AI、无应用权限或成员停用时不自动开通。
- 现有成员 Gateway 可显式纳入管理，保留原状态与绑定。已有手工地址不被静默替换；手工停用绑定优先于自动开通。
- 当前 2 核 4 GiB 测试主机最多保留 2 个就绪成员 Gateway，每成员最多 2 个并发执行；每实例内存上限 1536 MiB、CPU 上限 2 核。上限不等于实际占用或物理资源预留。已提前准备的成员保持就绪，其余成员空闲 15 分钟暂停；排队及资源升级须等待活动租约结束。暂停保留数据，不删除容器或成员状态。此前 1 实例/1 GiB/1 CPU 为 D-031 初版设置。
- 租约持久保存，执行时每 10 秒续租；过期宽限 180 秒。准备/排队与模型调用分别计时，模型执行预算 60 秒，整个资源等待预算 240 秒。等待人工审批/收货的确定性业务任务不占用 Gateway。
- 容器使用固定 OpenClaw 2026.9.7 镜像及摘要、只读根文件系统、独立状态挂载、去除 Linux capabilities、禁止提权，无对外 Gateway 端口。使用轻量 `/readyz` 就绪检查。
- 主机/控制器重启后核对容器并恢复请求租约。用户停止执行、权限或绑定变化后不交付回答或发起新业务写入；已提交业务通过回执恢复，不再次调用模型或重复提交。
- 自动调度不代表模型已开通、无限并发或容量承诺。真实多客户并发容量、模型质量和业务收益需另验收。

## 接口与领域契约

- `POST /tenants/:tenantKey/ai/conversations/:id/turns`：`content/version/requestKey/allowAction/useKnowledge`；原子保存用户消息和 `AiTask(kind=message)`，返回任务标识和已提交版本。同一请求重复返回原任务，参数冲突返回 409。
- `GET /.../ai/conversations/:id`：返回 `activeTask`，恢复后台状态；存续的排队/执行不能被当作中断请求。
- `GET /.../ai/tasks`、`GET /.../ai/tasks/:id`、`POST /.../ai/tasks/:id/cancel`：仅本人、当前应用、当前授权；分析对象与识别权限重新核对。旧同步消息接口保留给已接入工作通道。
- `GET /tenants/:tenantKey/notifications`、`POST /.../notifications/:id/read`：平台个人通知加应用公开贡献，按时间稳定分页，读操作核对收件成员。ERP 保留自己的通知与业务流转数据。
- `AppAiProvider.actionPresentation`：由应用解释业务输入及回执；平台不直接解析另一业务应用的内部表。
- 前端 `/tasks?task=...`、`/tasks?aiTask=...`、`/erp/ai?conversation=...`：刷新后直达同一记录。`returnTo` 仅允许同源、同企业内部路由；目的页仍从服务器重新鉴权。
- `AiProviderSettings` 为企业管理员配置的默认模型；平台批准的专属企业 Profile 是可选来源。已有独立手工 Gateway 继续遵守其原配置。

## 2026-10-12 D-032 速度体验复查

**本轮生命周期功能已上线，但交互响应速度尚未达标。** 76–83 秒就绪样本属于需要修正的产品缺陷。后台保存、准备状态和完成通知已验证，不代表用户等待体验已经合格。

当前源码与主机核对：Runtime 空闲 15 分钟后停止整个 Gateway，下次需重新加载；最多 1 个活跃成员实例，跨成员请求可能触发实例切换与重新启动。Gateway 限 1 CPU / 1 GiB；历史运行日志中的进程 RSS 约 664–933 MiB，不能直接当作整个容器的稳定内存。聊天适配器 `capabilities.streaming=false` 且请求 `stream:false`，前端等待完整结果。这些是当前观测事实；尚未通过分段剖析确定所有初始化耗时的占比。

下一步速度优化顺序：

1. 为普通交互保留已就绪服务和有界热资源，提前准备授权成员环境；重型资源的空闲回收与普通对话的快速入口分别制定策略。登录/页面预热需鉴权、去重、容量上限，不挤掉正在工作的成员。
2. 接通真实增量输出，从 Runtime、持久任务、授权读取到前端全链路验证；首段可读文字单独计时。受控工具参数不在未生成完整时执行，部分输出和最终业务回执分别展示。
3. 评测初始化缓存、精简加载、提示/历史长度、知识检索和模型速度；模型选择需同时通过业务质量和权限评测。若保留每成员重进程仍无法满足交互目标，再按可替换适配契约设计轻量交互与隔离执行的不同路径。
4. 重新验证当前主机容量和多成员热请求，确定热实例数量与扩容依据。单成员常驻仅缩短该成员热请求，不能据此宣称多人等待解决。

公开参考：[AWS 预置并发](https://docs.aws.amazon.com/lambda/latest/dg/provisioned-concurrency.html)解释预先初始化环境以降低交互冷启动；[Anthropic 延迟指南](https://platform.claude.com/docs/zh-CN/test-and-evaluate/strengthen-guardrails/reduce-latency)区分 TTFT 与完整生成，并建议流式输出、模型和输入输出优化。这些公开机制可用于本项目设计，不能据此推断各商业产品未公开的后端实现。

[OpenClaw 安全边界](https://docs.openclaw.ai/gateway/security)规定每个 Gateway 对应一个信任边界；多个 Agent/会话不自动提供互不信任成员或租户隔离。因此不通过把所有成员塞进同一 Gateway 来消除等待。共享或轻量运行设计须保留当前授权、上下文、受控 Tool、审计、确认、取消与业务回执契约。

目标及测量定义见 [04](04-UI与交互规范.md#响应速度与实际操作效率d-032)、[06](06-开发与测试规范.md#d-032-性能与体验验收)。以上是当时的阶段记录；后续已发布的版本和实测见文末 D-033 记录。

缓存对照样本：在同一新服务器的独立 QA 容器启用持久 `NODE_COMPILE_CACHE`，保留原固定镜像、1 CPU / 1 GiB 和隔离成员配置，首次就绪 80.04 秒，停止后再次启动 72.83 秒。仅两次工程观察，不作稳定性能或因果承诺；仍明显超出交互目标，不能只靠缓存关闭缺陷。QA 容器测试后已停止，生产策略及业务数据未改动；证据为忽略目录 `output/latency-20261012/cache-benchmark.log` 和新服务器私有 `shared/latency-20261012/cache-result.json`。

容量复查：再次短时启动同一隔离 QA 容器，Docker 在健康就绪后显示约 643 MiB，cgroup `memory.current` 为 682,000,384 字节（约 650 MiB）。启动期间 `memory.peak` 达到 1 GiB 限额，`memory.events` 的 `max` 计数为 532，`oom` 与 `oom_kill` 均为 0；日志中的进程 RSS 一度约 998.8 MiB。容器最终健康就绪，取样后已停止。此为单容器、无模型请求的短时样本，不代表业务负载峰值或客户交付所需的每实例内存；容量规划须测多成员、并发请求和启动峰值并保留余量。

## 主流部署机制与客户交付建议（2026-10-12）

用户明确测试机资源不作为客户交付架构上限。本次查询官方公开文档，不推断商业产品未公开的内部实现；以下均为方案研究，尚未部署。

| 机制 | 已公开的实例 | 对本项目的含义 |
| --- | --- | --- |
| 长期运行的 Gateway | [OpenClaw 网络模型](https://docs.openclaw.ai/network)将 Gateway 描述为长期运行进程 | 交互入口与已批准的 Runtime 先准备好，健康后再接流量，不让普通请求反复承担完整初始化 |
| 预先准备并自动补充执行环境 | [Daytona Warm Pools](https://www.daytona.io/docs/en/warm-pools/)提供基于快照的预建运行沙箱，领取后自动补充；匹配条件不支持自定义环境变量、卷或 Secret | 无身份的公共模板与分配后的租户私有环境区分；带成员配置的 Gateway 不能未经兼容验证直接套用公共池 |
| OpenClaw 自身的执行资源准备 | [Cloud worker warm images / Ready workers](https://docs.openclaw.ai/gateway/cloud-workers/warm-images)公开了准备镜像、就绪 Worker、分配后补充和按需清理 | 可以在保留 OpenClaw 的情况下研究独立执行资源的准备与调度；当前固定镜像、插件、供应商与使用场景须先验证，当前成员 Gateway 管理器不等同于该能力 |
| 保存状态后恢复 | [E2B 状态说明](https://changelog.e2b.dev/security)公开了文件系统与内存状态的暂停/恢复 | 对低频、长期任务可研究真实快照恢复；当前 Docker stop/start 与 Docker pause 不具备同等的内存快照释放/恢复语义 |
| 持久状态和可扩缩的计算分离 | [LangSmith data plane](https://docs.langchain.com/langsmith/data-plane)把 threads/runs/checkpoints 放入 PostgreSQL，运行任务用 Worker 池，读接口和任务队列按不同负载扩缩 | 会话或任务数量不直接等于常驻执行进程数；平台持久任务和对象授权继续作为权威记录，计算侧替换或回收需验证断点和权限 |

对当前 ERP 的建议分两步：

1. 先保留现有 OpenClaw 执行契约，把普通交互所需 Gateway 设置为就绪后长期服务，接通真实流式输出。实例在客户开通、成员获 AI 授权和模型配置批准后提前准备；发布先检查就绪再切流量，故障单独恢复，不能把实例启动作为每条普通消息的常规前置操作。
2. 将来需要浏览器、脚本或独立文件工作目录时，再把执行沙箱与 Gateway 分开管理，接入预热池或快照。当前 ERP Tool 经平台业务 Service 执行，不为了套用云沙箱模式新增无业务用途的执行环境。

按 [OpenClaw 安全模型](https://docs.openclaw.ai/gateway/security)确定信任边界；当前成员 Gateway 的状态、令牌、模型配置和工作目录隔离保持到专项验证通过。资源足够不代表可以把所有企业/成员的身份和状态混用。公共预热模板中不能包含用户状态或凭据，已分配环境不直接返回其他租户的公共池。

客户交付按最低就绪容量、实际活跃负载、排队时间和资源水位扩缩；缩容须排空活动执行并保留可恢复状态，交互服务和沙箱用不同回收策略。数值目标仍按 D-032 的端到端测量，不把供应商的环境领取或恢复速度等同于完整模型回答时间。

## D-032/D-033 实施与实测（2026-10-12）

用户明确要求普通问题自动快速处理、复杂问题允许更长时间。当前消息增加 `thinkingMode=auto|fast|deep`；默认自动选择，界面可手动选“快速回答”或“深入分析”。短问答走精简提示与限长输出；长文本、分析/比较/规划等请求走深度模式。只要检索企业知识、关联业务对象或授权业务操作，就强制深度模式，即使界面选择快速也不能绕过对象权限、引用核验、Tool 授权、人工确认、审计与业务回执。幂等消息参数含模式，重试不能换模式复用同一请求标识。

受管成员 Gateway 仍按成员隔离。每个有企业模型配置的 Gateway 有标准 Agent 与快速 Agent；快速 Agent 在固定 OpenClaw 2026.9.7 版本中用模型请求参数关闭方舟深度思考，仅允许只读 `session_status`，请求不提供业务 Tool。标准 Agent 保留原业务工具和模型默认推理。Gateway 会话键带 Agent 标识，避免多 Agent 所有权不明。旧成员配置在无执行租约时升级，升级会重启对应 Gateway；手动绑定或没有企业模型配置时不冒用快速 Agent。运行管理器每轮核对容器健康，重启后未就绪的容器不得接新执行租约。

同时上线授权成员提前准备、有界并发、持久消息的流式展示和后台继续处理。当前测试主机最多保留 2 个成员 Gateway，每位成员最多 2 个并发会话；其余成员按公平队列等待。前端离开后任务继续，可从通知返回。浏览器对本页点击发送的请求记录 `suite.ai.firstVisibleCharacter`：从提交事件到回答区域绘出首个非空白字符，且只在页面可见时记录；它是用户等待的主指标。平台记录 `runtimeWaitMs`、首个非空白 `firstDeltaMs`、`totalMs` 和实际选择模式作为诊断信息；任务片段持久化与 SSE 还有独立延迟。预览文字不构成最终业务回执。

## D-034 工具调用与思考过程体验复查（2026-10-12）

用户要求统一检查工具调用、大模型思考链路和相关使用体验。本轮在现有快慢分流与流式回答上增加可核验的处理阶段：核对业务上下文、按需检索知识、等待 Runtime、模型处理、生成回答、核对结果与权限、按需核对或执行操作、保存回复。阶段由平台实际处理点写入持久任务及最终消息；会话刷新后可展开“处理记录”。这里展示的是平台处理过程，不是模型内部逐字思维链，也不将等待或预览文字伪装为已经完成的业务回执。

深度分析只有用户明确勾选“允许本条消息发起业务操作”时才向 Runtime 提供 ERP 业务工具。未勾选时仅允许分析和回答；有操作请求时仍经过平台 Tool 参数校验、成员权限、业务 Service、必要的人为确认、审计及业务回执。普通快速回答不提供业务工具。线上回归还发现模型可能只用文字模拟“待确认采购草稿”，却没有调用 Tool 或创建操作记录；现要求 Runtime 不这样回复，并在终态由平台拦截此类假预览，明确显示“未生成可确认的业务操作”，只有真实操作详情里的记录可确认。前端在执行期间显示实际选择的快慢模式和阶段，并在操作请求中提示生成内容只是预览。聊天区和历史会话区分别滚动，长历史不再把输入框挤出桌面视口；切换会话、收到增量及最终回答时，若用户未主动上翻，保持最新内容可见。

## D-036：首字延迟定位与优化（2026-10-13）

当前正式 API/Worker 为 `20261013-runtime-latency-r3`，27 项运行管理器测试、固定 OpenClaw 2026.9.7 的真实 Gateway＋模拟下游模型测试，以及平台 69 项断言 / 74 次 HTTP 隔离回归通过。本轮没有生产数据库迁移，20 条迁移保持；Cloudflare 入口、企业管理端、运营端沿用 D-035；员工端本轮状态文案和分段测量版本为 `77ed8342-34b7-45ea-9cc3-0b33df42b9a3`。生产已就绪的两个成员实例均实测为 1536 MiB / 2 CPU 上限，地址、令牌、成员身份和平台会话保持原关系。

### 定位结果

同一短问题的组件对照：模型接口直接调用首个非空白回答片段 2.561 秒，Gateway 的原持久会话为 28.599 秒；在内存临时会话中为 12.759 秒，解除 1 CPU 限额后为 5.460 秒。以上是单次诊断样本，提示内容和执行上下文并非完全相同，不是浏览器首字或 P95。原 Gateway 日志实测出现 8.492 秒 SQLite maintenance-plan 和约 768 MiB 临界内存压力下的工作线程回收。原持久会话的浏览器样本中，任务创建到 Runtime 执行记录约 0.546 秒，运行资源分配约 0.157 秒，Runtime 首增量约 21.997 秒；主要等待发生在 Gateway 执行阶段。

另发现运营原先配置的生产方舟 Profile 没有快速 Agent；没有企业模型设置行时，旧代码未提供关闭思考的快速入口。现为平台受管且由运营批准的已有方舟 Profile 补齐快速和只读 Agent，保留其原模型、地址与密钥。未把这种情况扩写为所有第三方模型都支持同一思考参数。

### 已发布改动

- 平台继续保存消息、授权历史、业务回执、用量和审计；Gateway 只处理每轮生成的内存 Incognito 会话，停止重复写入本轮完整聊天记录。每次执行仍提供当前已授权历史，不复用 Gateway 的旧记忆。该方式仍经 OpenClaw，不新增第二套执行引擎。
- 临时会话键由当前成员的执行租约派生；后台私有 loopback RPC 清理失败时保留重试，重启后继续处理；超过 100 项积压暂停新准入。只清理由平台生成的临时键，普通持久会话不进入此接口；Gateway 停止也会清除其进程内临时状态。
- 快速问答使用已验证的关闭思考参数；纯深入分析使用独立只读 Agent，直接流出自然语言正文。显式授权的操作继续进入原业务 Agent、Tool 参数校验、权限、确认和审计链。旧外部手动绑定保留原接入行为。
- 默认 Gateway 上限改为 1536 MiB / 2 CPU，支持控制器配置；内存上限在实例重启后才更新 OpenClaw 启动时采样的压力阈值，活动执行结束前不升级。已相同的 Profile 内容只记录版本，不再无故重启。
- 执行用量内增加 `transportTiming.gatewayHeadersMs` / `gatewayFirstDeltaMs` / `gatewayTotalMs`，继续保留资源等待、Runtime 首增量与实际浏览器首字。Gateway 首增量不作为模型请求本身的首字数据。

机制依据：[OpenClaw Incognito](https://docs.openclaw.ai/concepts/session)、[工作区上下文注入](https://docs.openclaw.ai/gateway/config-agents/workspace-and-bootstrap)、[OpenResponses HTTP 会话](https://docs.openclaw.ai/gateway/openresponses-http-api)；具体行为以本轮固定版本实测为准。
