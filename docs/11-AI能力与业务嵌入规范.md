# AI 能力与业务嵌入规范

> 文档属性：功能契约。规则与验收要求不等于全部能力已实现或已发布，日期证据保留其环境。状态入口：[47](47-项目现状与文档维护.md)；公共UI：[ui/00](ui/00-公共UI规范.md)。

已有自动运行、任务通知和业务回执的日期发布记录见 [43](43-自动运行与工作体验优化.md)；最新本地实现、历史发布及未覆盖边界统一见 [47](47-项目现状与文档维护.md)。

本规范落实 [D-007](00-文档索引与决策记录.md#已确认的决策)：平台必须有能通过受控 Tool **实际执行业务操作**的 AI 聊天框；设计业务模块时逐一寻找能切实减少人工整理、查询、录入或分析的 AI 用例。以下是目标设计，不表示这些能力已经开发或验证。

## 两类入口

| 入口 | 用户做什么 | 系统必须做到什么 |
| --- | --- | --- |
| AI 聊天框 | 从平台导航进入，用自然语言查询、分析，也可要求 AI 创建或修改有权业务对象；可选择当前应用与业务上下文。 | 保留会话历史，明确当前企业/应用；读取带来源，写入调用受控应用 Tool，并展示真实操作结果。 |
| 模块内 AI | 在列表、详情、表单中针对当前业务对象发起提取、分析、生成或检查。 | 自动带入当前对象及版本，减少重复描述；结果可回到原页面处理，不能跨越对象权限。 |

聊天和模块入口复用平台模型配置、任务、用量、权限及审计能力；业务提示词、Tool 和事实来源由所属应用管理。Enterprise AI 是企业级体验入口，不自动对应一个独立 Agent。单 ERP 租户的首阶段目标是企业入口和 ERP 内入口复用同一 `erp.assistant` 能力；ERP 页面内 AI 带入对象上下文，但不额外授予权限。切换企业或应用时重新验证权限，不能沿用前一个上下文的可见数据。聊天可以发起业务写入，但只通过所属应用的业务 Service，不能另存一套影子业务数据或让模型直接写数据库。Agent/Skill 的最小契约与当前差距见 [22](22-AI体验与首阶段Agent策略.md)。

聊天会话保存用户选择的当前应用和资源，仅作为下一次请求的输入线索。每次模型读取、Tool 调用或异步任务执行都由服务端重新构造 [AppContext、RequestContext 和 AIExecutionContext](03-架构与数据安全.md#4-请求权限与-ai)，验证目标 `appId` 已启用、当前成员有权且资源仍可见；跨应用 Tool 不能沿用另一个应用的权限快照。AI 行为的审计和用量均记录目标 `appId`。

平台 AI 运行时只依赖 Tool 注册与执行契约，不导入 ERP/CRM/MES 的内部服务或表。应用注册 Tool 实现，再调用本应用命令。通用摘要、结构化提取或检索机制只有在有实际复用时进入平台；采购履约、生产异常、建筑合同判断的提示词、事实来源、评测和执行 Tool 留在所属应用或经评审的行业模块。共享边界见 [14 共享能力准入](14-共享能力准入与模块公开契约.md)。

这里的“AI Gateway”是平台内部的控制边界，和 OpenClaw Gateway 职责不同。当前 ERP 已通过 Runtime 适配器调用 OpenClaw，可信 Context、按 App 选择 Provider/Agent 和受控 Tool 执行已实现；生产一名成员的真实调用证据见 [41](41-六批优化交付与线上验收.md)。两处会话入口必须共用执行链；写操作以业务单据和幂等回执为准，结果不明时先核实。D-016 已指定 OpenClaw，不再做候选选型 PoC；第二模型 Provider 和外部 MCP 仍按 [ADR-002](ADR-002-AI运行边界与外部协议.md) 的触发条件建设。任何 Runtime 的自动调用仍须经过平台授权、确认与应用命令。

## 用量与有预算的执行

模型执行计量独立于业务会话/测试租户生命周期，失败、取消与权限复核失败不能丢掉已收到的用量；缺失明细标未知，不记作0。独立账本不与同一请求的旧执行/额度表重复相加，缓存/推理分别属于输入/输出的分项。按任务选择有权工具与Skill，同轮只读结果复用须重新校验权限和数据版本，写操作与过期人群不能复用。付费验证必须显式启用、设批次预算并持久化逐次回执；错误或计量缺失时停止继续调用。D-054/D-055本地与真实模型证据见[57](57-AI用量治理与Evolving复测.md)，D-056正式发布及边界见[58](58-AI用量治理与ERP专项修复线上发布.md)。

D-055补充ERP入口：聊天、业务分析、风险检查、单据提取及摘要共用Runtime输入准入检查；平台组装的单次消息和工具定义估算超过24k Token时拒绝发送，不静默删减事实。估算不包含供应商/网关内部附加开销，不等于供应商计费硬上限。ERP按本轮问题和实际可用工具提供主数据，库存上下文不再重复加入补货清单；部分结果必须明确范围，不能推断为全量或无库存。合同中库存事实需要独立库存查看权限，新生成回答携带授权范围凭据，权限变化后隐藏相关派生回答；通用分析返回前复核业务事实。用量用途分别记`reply`、`analysis`、`risk_review`、`document_extract`和`context_summary`，可按应用/用途查询，历史缺失用途不反推。该批状态与证据见57的ERP专项记录。

## 知识检索的最小契约

首阶段按 D-016 建设企业知识产品，并让 `KnowledgeProvider` 通过受控 RAGFlow 接入实际执行；业务模块负责文档与业务对象的含义和可见范围。知识空间、文档版本、上传/处理/检索/引用及权限验收见 [24](24-首阶段新增能力与验收.md)。

会话/Agent 记忆、企业文档知识与 ERP 等应用的实时结构化业务数据分别处理：会话内容不能变成授权来源，业务数量/金额/状态须经有权 Native Tool 从应用 Service 获取，文档内容才经知识检索接口返回。文档须有 Owner、版本、生命周期和可见范围；RAGFlow 只处理派生索引，不持有平台权限或业务数据的权威状态。检索前按租户、成员、App 与对象范围限定来源，返回带版本/定位的引用；点击引用时再次鉴权。RAGFlow 已由 D-016 指定，使用前以授权文档样本验证解析、权限和部署，而非再做选型比较。

```ts
type RetrievalContext = {
  request: RequestContext; // 服务端当前租户、成员和目标 App
  currentResource?: { appId: string; type: string; id: string; version?: number };
};
type Citation = {
  sourceAppId: string;
  sourceType: string;
  sourceId: string;
  sourceVersion?: string;
  locator?: string; // 页码、章节或业务记录定位；展示前再次鉴权
};
interface KnowledgeProvider {
  retrieve(ctx: RetrievalContext, query: string): Promise<Array<{
    excerpt: string;
    citation: Citation;
  }>>;
}
```

`RetrievalContext` 由服务端构造，Provider 在取得内容并送入模型前按租户、App、对象权限过滤；引用只指向当前用户可访问的来源，点击时再次鉴权。Provider 未实现或无权时返回明确状态，不能用模型编造出处。ERP 的业务数据库上下文查询可直接由 ERP 的授权查询服务提供，不必伪装成已建好的知识检索系统。

## 对话中执行操作

用户可说“根据这段需求创建采购单草稿”“把这条有权客户记录的联系人电话改为……”。AI 需要先识别目标对象和缺失字段，再调用应用声明的 Tool；成功后返回单据/记录 ID、实际状态和可打开的链接，而非只回复“已经完成”。

1. **准备**：从当前租户、应用、会话及业务对象读取最少必要资料；解析用户目标，缺字段时在聊天中追问。模型输出的对象 ID、金额和数量要重新核对。
2. **授权与预检**：平台校验成员与应用权限；应用 Tool 再校验记录归属、业务动作、状态、版本及输入。聊天与页面调用同一应用命令和领域规则，不能为 AI 复制一套业务流程；参见[12 领域边界与协作契约](12-领域边界与协作契约.md)。
3. **执行**：普通已授权操作（如创建草稿）可在用户指令后直接执行；采购确认、出入库、收付款等高影响动作先展示待执行对象、关键字段及后果，取得明确确认后再执行。确认不能绕过再次校验。
4. **回执**：以 Tool/业务 Service 返回的持久化结果为准，记录会话、请求 ID、操作者、租户、对象、动作和结果；给出可进入业务页面的链接。处理中、失败、取消和成功必须有不同状态。

D-048的三端公共对话将业务提案与写入分开：ERP默认允许提出有权操作，同时携带`requireConfirmation:true`，所有操作（包括原工具声明无需确认的创建客户/商机）都先保存为pending。用户在自动展示的工作单核对参数后一次确认，才调用同一业务Service；不再要求前置“允许本条操作”勾选或重复确认弹窗。`requireConfirmation`只增加确认要求，不能覆盖工具原有的强制确认；管理域仍拒绝`allowAction`/知识检索。旧客户端未传该字段时按false兼容既有单次授权，幂等比较将缺省false与显式false等同，改变该要求不能复用同一requestKey。字段不新增数据库迁移。
5. **恢复**：重试采用幂等键，避免重复建单或重复记账；Tool 超时不能宣称成功，应查询实际结果或展示待核实状态。

## ERP 首批场景清单

以下为逐模块设计与验收的候选场景，最终实现以具体业务样本和权限验证为准。不能因为场景列在表中就对外宣称已交付。

| 模块 | 优先评估的 AI 用例 | 业务事实与执行边界 |
| --- | --- | --- |
| 客户与商机 | 整理客户资料、总结沟通与商机进展、起草下一步跟进；在聊天中创建有权客户或商机草稿。 | 客户归属和可见范围由 ERP 校验；写入返回真实对象 ID。 |
| 产品与供应商 | 从资料提取 SKU/供应商字段，提示重复或缺失，辅助比较。 | 编号唯一性、停用状态和价格以 ERP 数据及规则为准。 |
| 采购 | 从文字/文档提取采购单草稿，聊天中创建草稿，分析履约、交期与异常，整理待处理事项。 | 采购确认、入库数量、库存与应付由 ERP 规则和事务处理。 |
| 销售合同 | 提取合同条款及单据草稿，分析履约和风险，生成客户沟通草稿。 | 合同状态、库存可用量、出库与应收由 ERP 校验。 |
| 库存 | 解释缺料与异常波动，提出补货方案，帮助定位相关单据。 | 库存余额和缺料数量由确定性计算；AI 不编造现有 SKU。 |
| 财务 | 解释应收应付变化，整理对账线索、提醒和异常。 | 金额、余额与收付款记录以账务数据为准；自动付款不在首批范围。 |

开发 CRM、MES 或建筑应用时也按相同方式逐模块列场景，不机械复制 ERP 提示词或 Tool。

ERP 低库存当前同时提供实时查询和持久经营事件。补货事实合并库存、已确认未收采购量与未发货销售需求；建议先生成持久计划，人工核对后创建草稿并提交，由指定审批人审批，分批入库后核验结果。后台扫描持久经营事件并生成负责人待办/通知，来源风险解除后自动关闭；支持转交、处理及逾期升级。数量依据确定性业务规则，未提供模型自动采购或 AI 自动审批。具体来源口径和线上四类事件证据见 [41](41-六批优化交付与线上验收.md)。

## 单个 AI 用例的设计卡

每个业务模块先列出现有人工步骤及耗时/易错点，再为候选 AI 用例写清：

1. **入口与目标**：从独立聊天、模块页面还是两处进入；用户想省掉哪一步人工工作。
2. **上下文与权限**：租户、应用、对象、数据版本、可见字段及引用来源；哪些数据绝不提供给模型。
3. **输入与输出**：支持的真实资料类型、结构化结果、草稿或分析的状态；缺字段时如何提示补充。
4. **业务动作**：是否只读、生成未保存草稿，还是会调用写入 Tool；明确执行前预览、是否需确认、执行回执及幂等规则。写入必须经所属应用 Service、权限和状态校验。
5. **质量与失败**：真实模型样本、事实正确性、无权/跨租户、模型超时、无模型与人工继续处理路径；不要用固定文案冒充 AI 成果。

只有经真实模型和业务样本验证、能明显减少步骤或改善判断的用例才进入客户可见范围。AI 生成的解释不能覆盖确定性业务计算；聊天和模块 AI 要能区分“建议/草稿”与“业务操作已完成”。

后续新应用若需要主动发现业务事件，应同时使用 [10 后续应用闭环准则](10-应用接入契约.md#后续新应用的-ai-业务闭环)：说明触发来源、证据、应用拥有的候选状态、责任人、人工确认、后续动作及关闭回执。主动运行不扩大模型的授权范围，也不自动把候选判断提升为已确认业务事实；定时扫描、通知渠道和外部连接只在该场景需要且完成验收时建设。

## 可见处理记录（D-037）

- 平台实际阶段产生公开进度说明，经已有任务 SSE 通道推送；记录开始、结束、耗时、完成/失败/取消。无需额外模型调用或定时编造进度。当前展示字段的 `summary` 为阶段说明，不是模型思考摘要。
- Runtime 只转发本轮声明工具的请求标识；原始函数参数先不公开。平台完成参数校验后，使用应用 `actionPresentation` 生成用户可读参数。工具卡片明确区分生成请求、待确认、执行中、完成、取消、失败和结果待核实。
- 消息 JSON 保存阶段和工具记录，Task JSON 保存运行中片段；无需新增业务影子表。读取、流式重连、刷新及历史详情重新核对租户、成员、应用、对象、引用和 Tool 权限。人工确认/取消后的卡片状态从持久 AiAction 和审计回执恢复，不以历史模型文字为准。
- 当前正式模型 `doubao-seed-2-1-pro-260915` 直接接口实测有推理文本，没有独立思考摘要；固定 OpenClaw 2026.9.7 `/v1/responses` 实测只有正文事件。`reasoning.summary=auto` 未产生摘要，与其接口文档“接受但忽略 reasoning”一致。因此本轮不展示思考摘要，不用推理原文或额外生成内容替代。将来模型、协议或 Gateway 更新后需独立验证再接入。
- 原始参数、网关地址/令牌、模型密钥、内部工具、推理文本和 SDK 错误堆栈不进入公开卡片。撤权后清理流式缓存并隐藏参数/回执；任务停止不撤销已提交业务交易。
- 首字测量仅选择正文节点；公开进度、时间线、工具卡片和等待标识不计作模型回答首字。工程验证与正式版本见 [43](43-自动运行与工作体验优化.md)。


### 任务终态的即时交付（D-038）

消息任务的 SSE `progress` 终态可带 `result: { message, version }`，正文与处理记录均来自已通过对象、引用和 Tool 重新鉴权的 `task()` 结果。前端直接合并最终消息及版本，并结束等待；不以历史列表、操作列表或下一次 1.5 秒轮询作为展示门槛。无终态消息的取消任务及旧服务保留立即读取会话的兼容路径；轮询和终态并发返回时只结算一次，旧运行状态不能覆盖已结束状态。权限拒绝时清除未完成内容。

## 公共交互与管理助手边界（D-044/D-045）

所有应用的对话外壳/入口/历史/新对话/工作单/焦点规则由 [公共AI规范](ui/04-AI对话与工作单.md)维护，应用只补事实、工具和业务行为。现有AiConversation为ERP及两个管理域适配，新CRM须完成自身接入，不能直接默认ERP API。

两个管理域保留标识分别为tenant_admin和platform_admin；均只读、无业务Tool，不接知识检索。企业管理仅当前企业管理统计；运营助手需全局运营身份和受控服务企业，模型/计量不会自动使用当前选中的客户企业。请求、任务、SSE和终态重新鉴权，详见46。该能力本地已验证，线上状态见47。


## D-047：分层记忆与上下文

三端共用平台历史、受控OpenClaw摘要和长期记忆；长期原文/权限仍由平台持有，原生memory-core仅做隔离关键词索引。用户明确保存，默认不自动采集聊天，不把历史或记忆作为授权/实时事实。接口、配额、过期/删除、降级与验证边界统一见[50](50-AI分层记忆与上下文.md)。
