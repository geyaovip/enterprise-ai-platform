## 不可省略的接入边界

1. **OpenClaw 的租户与成员隔离**：官方文档将一个 Gateway 定义为一个信任边界；共享云为互不信任的租户使用独立 Gateway、状态、凭据和网络，不把 `sessionId` 当授权。ERP 销售、采购、仓库、财务及不同销售的会话/工具也必须互相隔离：员工不直接访问 Gateway，平台 API 按当前成员、App、Agent/Tool 与资源范围重鉴权；禁用或收紧跨会话/跨 Agent 工具访问，并按成员配置可验证的隔离边界，必要时使用独立 Gateway。不能只靠前端隐藏会话。参见 [OpenClaw 多租户托管](https://docs.openclaw.ai/gateway/multi-tenant-hosting)与[信任模型](https://docs.openclaw.ai/gateway/security/trust-model)。
2. **Tool 与业务提交**：OpenClaw 的 Tool 请求只表示执行意图。平台 Tool Executor 拦截并复核租户、成员、App、对象、风险和确认状态，再经 ERP Application Service 提交；高风险动作拒绝确认不得写入。成功只认业务记录和审计回执，结果不明先按动作 ID/幂等键对账。
3. **RAGFlow 的数据与权限**：用户已选定首阶段使用 RAGFlow Cloud，暂不本地部署，不再设置自托管前置条件。平台原件与权限留在本平台，索引进入所配置的 Cloud 账户。联调使用程序生成的公开样本；真实客户文档上传须按实际授权和数据处理要求验收。平台保有知识 Owner、版本、权限和引用；对允许的空间/文档集合先授权再检索，索引同步失败、撤权和删除必须阻止旧结果进入模型。RAGFlow 的 Agent/Chat/Model 功能不作为本平台主链。参见 [RAGFlow 官方部署与数据集说明](https://github.com/infiniflow/ragflow/blob/main/docs/quickstart.mdx)。
4. **三个前端共享一个后端产品**：分别交付 Workspace、Tenant Admin、Platform Admin，但保持同一 API、身份/租户规则、设计组件和 ERP 领域所有权。拆分前端不意味着将 ERP/CRM/MES 拆成三个服务或数据库。迁移现有 `apps/web` 管理页面时保证现有路径或提供可回退跳转，不中断已验证 ERP 流程。
5. **部署与故障**：记录 OpenClaw 每租户实例的创建、停用、备份、升级和故障隔离，及 RAGFlow 数据/索引的备份、重建、容量、健康与升级步骤。任一组件故障时，人工 ERP 流程继续可用；AI/知识入口显示真实不可用状态，不伪造完成或引用。

## 未来替换的边界（D-017）

- **稳定契约**：Agent 侧按当前业务所需定义执行输入、会话关联、流式/非流式事件、Tool 请求、取消/超时与用量；知识侧定义文档摄取/删除、处理状态、按授权来源检索、引用及健康状态。先覆盖实际用例，用能力标识表示可选特性，不为未来产品预建空接口。
- **平台权威数据**：平台持有会话 ID、消息/动作与审计、Agent/Skill/Tool 的业务定义、知识空间、原始文档/版本、Owner/ACL 和稳定 Citation。OpenClaw Session ID、RAGFlow dataset/document/chunk ID 只在映射表中出现；ERP 业务服务不能直接依赖它们。模型凭据/配额与知识数据处理策略由平台治理，适配器只取得执行所需配置。
- **切换路径**：新方案实现同一契约并通过同一组租户、权限、Tool、引用和失败测试；RAGFlow 索引可由平台原始文件与版本重新构建，引用映射重新核对。OpenClaw 中正在运行的任务先排空或标记中断，历史会话从平台记录读取；私有 Memory、上下文压缩、Hooks/Automation 等不能承诺自动无损迁移，必须逐项导出、重建或明确舍弃。分阶段切流后保留旧适配器和数据恢复窗口，出现越权或结果不一致立即回退。
- **首阶段验收**：在隔离环境用符合契约的测试替身切换执行/检索适配器，再切回指定实现；执行原始文档重新索引与引用对账。此演练验证替换机制，不是重启 OpenClaw/RAGFlow 的多候选选型 PoC，也不要求生产同时运行两个供应商。
