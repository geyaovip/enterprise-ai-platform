# 开发与测试规范

> 文档属性：功能契约。规则与验收要求不等于全部能力已实现或已发布，日期证据保留其环境。状态入口：[47](47-项目现状与文档维护.md)；公共UI：[ui/00](ui/00-公共UI规范.md)。

## 技术选择与仓库边界

技术栈已按 [ADR-001](ADR-001-技术栈决策.md) 决定：Node.js 24 LTS、TypeScript 5.9、React 19 + Vite 7、NestJS 11、PostgreSQL、Prisma 7、pnpm 11；M1 固定确切依赖版本并验证兼容性。按 [A-001～A-003](00-文档索引与决策记录.md#本轮架构设计) 建设统一的模块化后端：平台提供身份/租户/组织/权限、AI 网关、审计和应用入口；ERP、CRM、MES 是同一 API 和数据库中的业务模块，分别拥有业务模型、应用服务、表和测试。跨模块通过公开应用服务接口协作，不直接修改其他模块拥有的表或复制业务规则。

目录应反映产品边界，而不是提前生成空目录。建议逐步形成：

```text
enterprise-ai-platform/
  apps/web/              # Enterprise Workspace 与 ERP
  apps/admin/            # Tenant Admin
  apps/platform-admin/   # Platform Admin
  apps/api/             # 一个 HTTP API，内部按领域模块组织
    src/modules/platform/
    src/modules/erp/
  apps/worker/          # AI、文档和可靠异步任务
  packages/contracts/   # API schema 与模块公开接口
  packages/ui/           # 跨应用设计 token 与组件
  infrastructure/        # 共享云/专属部署配置
  docs/
```

不得为未来建筑行业或 Shared Business 预建空业务模块；不得把业务实体转换成通用动态对象引擎。平台先实现稳定组织关系和 AppContext；D-016 已将知识产品、RAGFlow、OpenClaw 及三个独立前端纳入首阶段，按 [24](24-首阶段新增能力与验收.md) 落实。业务公共代码按[14 共享准入规则](14-共享能力准入与模块公开契约.md)评审后提取，不能仅因代码相似抽取。新应用按[应用模块契约](10-应用接入契约.md)开发，不能复制平台登录或授权规则。领域所有者、术语、关键不变量与跨模块协作先按[12 领域边界与协作契约](12-领域边界与协作契约.md)确认。

DDD 采用“边界先行、战术按需”的方式：复杂模块按业务能力组织代码，区分领域规则、应用命令、数据适配与 HTTP/AI Tool 入口；简单配置和只读查询不强制建立聚合或每表一个 Repository。一个限界上下文可包含多个内部模块，不据此增加进程。金额、数量、状态和版本等约束明确后再引入值对象或聚合规则。

## 代码与接口约定

- TypeScript 开启严格检查；边界输入以 schema 校验，不能信任前端类型。金额用数据库 Decimal/整数最小货币单位等精确表示，库存数量与版本号在服务端校验。
- 控制器负责认证上下文、输入校验和响应转换；应用命令编排事务，领域规则判断状态和数量是否合法，数据适配负责持久化。复杂模块用 Repository 隔离存储；简单查询可直接使用受约束的查询服务。页面、AI Tool、Worker 调用同一应用命令，不能各写一套业务规则。
- 任何按 ID 查询同时限定租户；对象所有权/角色范围在服务端检查。越权返回稳定错误，不泄露对象是否存在于另一租户。
- 每次请求从当前会话、Membership 与 TenantApp 构造可信 AppContext/RequestContext；前端的 appId 只能表示选择，不能授予权限。组织范围和对象范围在使用时重新校验，AI Tool 与 Worker 同样适用。
- 新增写接口先定义权限动作、幂等/版本策略、审计内容和失败状态，再写前端按钮。需要原子性的跨模块写入使用统一数据库事务；通知、索引或第三方投递等可延迟副作用使用可靠 Outbox 和幂等任务。
- 跨模块只导入所有者公开的类型与应用服务接口，不能导入别的模块的内部 Repository、Prisma Model 或私有命令；每张业务表标明唯一写入 Owner。提升共享须附迁移、历史引用、回退和跨应用回归方案。
- API 使用 `/api/v1`，错误返回机器码和请求 ID；列表限制页大小，避免无界查询。命名和路由按[05 路由与接口契约](05-路由与接口契约.md)。
- 密钥只从服务端 Secret/环境配置加载，不提交 `.env`、客户数据、数据库转储或完整敏感提示词。日志不记录完整业务文档、密码、模型密钥、付款凭证或 Cookie。

## AI 能力约定

- 平台 AI 聊天既能问答，也能通过受控 Tool 执行有权业务操作；每个业务模块按 [11 AI 能力与业务嵌入规范](11-AI能力与业务嵌入规范.md) 评估上下文 AI 用例。模型调用集中经过 AI Gateway；应用注册读/写 Tool 的输入、权限、幂等、确认和回执契约，不能让模型自由执行 SQL 或任意网络请求。
- 扩展 ERP AI 前按 [22 最小迁移](22-AI体验与首阶段Agent策略.md#现有实现的最小迁移)校正现有执行链：先认证并构造可信 RequestContext，再解析有权 Agent，建立 AIExecutionContext；企业 AI 与 ERP 内会话复用同一 `erp.assistant`、执行服务和 Tool 治理。显式 `agentId` 与默认 Agent 均须授权；App 不必须配置 Agent。
- AgentDefinition 只保存身份、范围和能力引用；Skill 组织可评测的 AI 输入、输出与事实来源；Tool 声明权限、风险、输入和回执。最小 Runtime 只产出回答或 Tool 请求；平台执行点负责重鉴权、必要确认、幂等、审计及业务回执。Tool 通过 ERP Application Service 调用业务，不直写 Repository/DB；Skill 不复制领域规则。
- 新 AI 场景不得继续把 Prompt、Model Gateway、Tool 调度与业务访问堆进 `ErpAiProvider`。它可作为迁移适配层，但同一动作只能保留一条有权写入路径；代码静态清单足够时不建数据库 Registry、Builder 或空目录。
- 结构化结果必须经 schema、对象 ID、来源版本和当前权限复核；无效结果整体拒绝或明确标识，不生成看似真实的兜底数据。
- 业务事实由确定性服务计算；模型可解释、提取信息、生成草稿并选择已授权 Tool。聊天发起写入时，应用 Service 重新读取当前对象、检查版本与业务规则并持久化；模型文本不能代替真实业务回执。高影响动作在确认后仍须走相同的 Service 校验。
- AI 写入的幂等键须传递到业务命令或由等价原子去重机制保证。若业务提交成功、动作记录却未保存成功，显示“结果待核实”，先按业务单据/幂等键对账；测试须覆盖故障注入、重复请求和确认后撤权。
- 每个模型任务规定超时、重试、并发/预算上限、失败可见状态和可追溯审计。客户启用前使用实际模型与业务评测样本验收。

## 迁移与测试

- 每个数据库变更都配迁移文件、回填/兼容策略、回滚或恢复步骤及所影响的租户范围。禁止在生产库上直接运行测试或无备份的破坏性迁移。
- 单元测试关注领域不变量、权限判断、业务状态机、金额/数量和版本冲突；集成测试关注 Manifest、模块公开接口、统一 API 授权、ERP 同库事务、异步事件幂等、文件/知识授权与 AI Tool → 应用命令；端到端测试覆盖真实用户路径。
- 每个阶段必须有双租户隔离测试：普通 API、列表/详情、AI 上下文、文件/检索、后台任务和审计查询。角色测试覆盖 ERP 销售私有数据及采购、仓库、财务边界。
- AI 测试分两层：固定模型替身验证读/写 Tool 契约、确认、幂等与失败处理；真实模型样本验证聊天操作和模块 AI 的来源、准确性、实际持久化结果、越权拒绝及节省的人工步骤。两类结果分开报告。
- D-016 新增验证：OpenClaw 跨租户 Gateway/成员会话与 Tool 隔离、撤权、断线重试和业务结果对账；RAGFlow 文档版本/权限、检索前过滤、引用定位、删除/重建及故障；三个前端的角色、深链接与原 ERP 流程回归。选型已确定，不以多候选 PoC 代替这些接入测试。
- D-017 可替换验证：真实 OpenClaw/RAGFlow 适配器与隔离替身共用 Runtime/知识引擎契约测试，覆盖稳定 ID、授权、取消/超时、Tool 回执、文档摄取/删除/重建、引用与故障；在隔离环境演练发布配置切换和回退。业务模块及前端不得直接依赖组件私有 SDK、ID 或索引格式；实际替换新的技术方案时再做其专属兼容验收。
- 对实际启用的外部 Runtime、知识引擎或模型适配器，增加场景对应的契约与故障测试：撤权/跨租户被拒、确认不可绕过、业务结果可对账、超时或组件失联时拒绝越权并显示真实状态。未启用的候选不生成空适配器测试；选型结论与回退方案进入 ADR。
- 只为有行为风险的逻辑写测试；不写镜像实现的空洞测试。文档改动核对链接、编号和决策一致性。

## 一次开发任务的完成条件

1. 对照功能 ID、路由、权限和验收 ID 确定范围，列出受影响模块。
2. 实施 migration → Service → API → UI，或说明某一层不需要变化。
3. 同步更新契约、测试、运维说明；运行相关 lint、typecheck、build、测试。
4. 对客户可见流程做浏览器验收，写明环境、数据、模型是否真实、通过项与未验证项。
5. 代码审查重点检查跨租户查询、权限、业务事务、模块公开边界、共享提升证据、异常/重试、敏感日志和回退路径。

“构建通过”“测试通过”“共享云已部署”“客户已验收”应分别记录。不得用前一种状态替代后一种。

## D-029 新应用和持续任务回归

当前平台已有通用应用注册/Provider/命令/Reader、持久任务与协作 Outbox，不再按早期 ERP 唯一 Provider 的过渡结构添加新业务。下一系统按 [10 接入清单](10-应用接入契约.md#新业务应用接入与验收清单d-029) 实施。

- `pnpm --filter @suite/api test:orchestration`：应用上下文、Provider/Agent 隔离、事务事件、幂等/回执恢复、执行中取消、权限撤销、额度与支持授权。必须使用受保护的隔离数据库；不得直接对生产库执行。
- `apps/api/tests/worker-lanes-flow.cjs`：真实 Worker 子进程暂停知识通道时，业务任务仍推进并核对九通道健康。
- 业务命令指定价格、数量或换算时，预览必须与领域实际写入一致；同时测试金额舍入、过期事实和确认哈希。
- 经营事件按真实来源生成并解除，核对去重、合法负责人、转交、升级、任务及通知；角色不适合该事件时不得出现在候选人列表。
- 正式环境场景通过公开 API，在明确授权的独立演示租户造数据；生产脚本必须有显式环境/目标 guard，保留账款、库存、角色及非预期错误回执。
- 浏览器验证桌面/390/320px 页面与弹窗，检查页面溢出、按钮对齐、状态、二次确认及敏感支持范围；构建成功不能替代截图和实际交互。

本轮通过数、上游替身边界、真实生产模型和备份恢复证据统一维护在 [41](41-六批优化交付与线上验收.md)，不由规格表自动扩大完成状态。

## D-032 性能与体验验收

功能回归、视觉与交互检查、响应速度和真实客户验收分别记录。每次修改用户流程，同时评估等待、重复录入、操作步骤和错误恢复成本。时延目标与测量定义见 [04](04-UI与交互规范.md#响应速度与实际操作效率d-032)。

- AI 分开记录发送到界面处理反馈、服务端执行进度可见、Runtime 处理阶段可见、首个回答文字四个时间点。前三项不能代替首字，也不能推断供应商大模型实际收到请求的时间。用户不要求显示“正在提交消息”；已就绪无拥塞时，执行进度目标为 1 秒内。
- AI 主要测量浏览器首字时间：从点击发送到回答区域绘出首个非空白字符，不把状态提示、空白增量或用户原文算作回答。另分段测量消息持久化、Worker 排队、Runtime 就绪、检索、模型首次非空白增量、任务片段持久化、首段、完整生成、工具执行及最终回执；统计以用户动作开始，不从模型开始才计时。浏览器首字必须在真实前端和代表性网络中测量，服务端增量及 SSE 时间只能用于诊断，不能替代它。
- 冷启动、空闲恢复、热请求、成员切换及并发分别测试；缓存命中样本不能代替首次使用，低频成员不能长期承受不可用的冷启动等待。
- 流式部分文本不触发业务写入；完整工具参数通过结构和授权校验后才进入已有确认和业务 Service。测试断流、刷新、重复提交、取消与撤权。
- 优化不能通过复用别的成员状态或降低租户/对象鉴权来换取速度。共享 OpenClaw 进程前必须评审其信任边界；仅用不同 session key 不构成不同租户或不互信成员隔离。
- 80 秒环境准备在本项目交互式 AI 场景判为体验缺陷。能完成请求或显示“正在启动”不足以关闭该缺陷；必须用实际端到端结果关闭。

## 公共UI与文档交付（D-045）

公共规则从 [ui/00](ui/00-公共UI规范.md)读取，组件接口/缺项和新应用准入按ui/05执行。改共享组件需覆盖三端和现有消费者；CRM仍有自己的业务、HTTP、浏览器和真实模型验收，不因ERP通过而跳过。

文档改动检查相对链接/标题锚点、术语/断点一致性、单处规则归属、状态与环境分离，历史记录保留日期。文档任务不要求重跑全部应用测试；新增路由/模型/权限/行为的代码任务才按影响范围选择验证。

D-044专项入口为 `pnpm --filter @suite/api test:account-management-ai`，只允许其脚本指定的独立QA数据库；用例和实际通过范围见46。新测试命令必须实际存在于package.json，未运行不写通过。
